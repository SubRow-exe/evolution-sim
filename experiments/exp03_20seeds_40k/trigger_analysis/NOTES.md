# 転移トリガー解析 (Issue #18)

- 日付: 2026-08-29
- データ: Exp03 の20 run（**再実行なし**。既存の `events.csv` を再解析）
- ツール: `tools/analyze_trigger.py`
- 対応: Issue #18 / `docs/V1.1_転移トリガー解析項目.md`

## 検証した仮説

```
繁殖上の小さな優位 → 1個体あたり出生率上昇 → 系統人口増加
→ 突然変異の試行回数増加 → さらに有利な変異 → 正のフィードバック → sweep
```

## 結論: 仮説は「部分的に支持、ただし要修正」

**繁殖優位（出生率の上昇）は sweep のかなり前から存在したが、それだけでは
人口増加につながっていなかった。** 同じ大きさの死亡率上昇で相殺されていた。

---

## 主要な結果（13転移seed全て）

支配系統の「集団全体に対する比」を2つの窓で比較した。

- **A窓** = 転移6,000〜2,000 tick前（sweepより十分前）
- **B窓** = 転移1,000 tick前〜転移時点（sweep開始時）
- **純増余地** = 出生比 ÷ 死亡比。1.0なら繁殖優位が死亡で完全に相殺されている

| | A窓 中央値 | B窓 中央値 |
|---|---|---|
| 出生比 | 1.25 | 1.83 |
| 死亡比 | 1.02 | 1.21 |
| **純増余地** | **1.02** | **1.40** |

**A窓の純増余地は13 seed中11 seedで 0.98〜1.13 に収まる**（範囲 0.98〜1.39）。

つまり支配系統は sweep のずっと前から**出生率が集団平均より高い（中央値1.25倍）
にもかかわらず、死亡率も同じだけ高く、人口はまったく増えていなかった**。

代表例（seed 20）: 支配系統は転移12,000 tick前から出生率が集団平均の1.7〜1.9倍
だったが、死亡率も1.7〜2.0倍で、人口は約6個体・シェア約1%のまま14,000 tick停滞した。
転移直前に死亡比が0.62へ落ち、そこから6→88→2,481個体へ急拡大した。

---

## 解釈と、その限界 ★重要

### 情報量のある結論（A窓）

**「出生率が高い系統が勝つ」という単純な図式は否定される。**
勝者は最初から速く増えていた系統ではなく、**高回転（多産多死）で頭を抑えられていた
系統**だった。仮説の「繁殖優位 → 人口増加」という最初の矢印が、
実際には長期間つながっていない。

これは非自明な発見である。

### 注意: B窓の結果は一部が定義上ほぼ自明である

B窓は「シェアが1%から50%へ上がる区間」なので、その区間で支配系統の純増が
集団平均を上回るのは**ほぼ定義的**である。したがって
「純増余地がB窓で1.0を超えた（13/13）」こと自体は、
sweepの原因の証拠として弱い。

情報があるのは**その内訳**である。

| seed | B窓 死亡比 | 内訳 |
|---|---|---|
| 20 | 0.62 | 死亡率が集団平均を下回った |
| 18 | 0.78 | 同上 |
| 9 | 0.95 | 同上 |
| 1 | 1.59 | 死亡率も上がったが出生率がさらに上がった |
| 10 | 1.49 | 同上 |

**機構は一様ではない。** 「死亡率低下が引き金」と一言でまとめることはできない。
seedによって「死亡率が下がった」ケースと「出生率がさらに伸びた」ケースがある。

### 未確認のまま残る点

- なぜ A窓の均衡（出生増＝死亡増）が破れるのか。外的要因（局所資源の解放、
  競合系統の衰退）か、内的要因（追加の変異）かは本解析では区別できていない
- 「変異試行回数の増加 → さらに有利な変異」という仮説の後半は未検証

## 形質変化との関係（seed 20）

支配系統の形質はsweepの前から緩やかに動いていた。

| 相対tick | body_size | light_abs | repro_inv |
|---|---|---|---|
| −15,120 | 0.917 | 0.322 | 0.394 |
| −5,120 | 0.760 | 0.432 | 0.387 |
| −1,120 | 0.734 | 0.626 | 0.512 |
| +880 | 0.353 | 0.854 | 0.704 |

小型化と高光利用化は sweep の前から進行しているが、**急変は sweep と同時**である。
形質変化が先行して引き金を引いた、とまでは本データからは言えない。

## 方法上の注記

`lineages.csv` は上位8系統しか記録しないため、13転移seed中4 seedで
支配系統の sweep 5,000 tick前の記録が欠けていた。これは
「早くから大きかった系統しか見えない」という**選択バイアス**であり、
まさに本解析の問いを歪める方向に働く。

そのため本解析は `events.csv`（全個体の出生・死亡を lineage_id 付きで保持）
から全系統の履歴を tick 0 から復元した。**再実行は不要だった。**
