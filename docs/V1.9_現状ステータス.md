# 2. V1.9の目的

V1.9は単なるphototrophy起源実験ではない。

> **より生物学的に妥当なchemical-first iLUCA baselineを再構築し、環境側を生存に合わせて曲げるのではなく、自然な環境圧へ生物側が進化で応答できる土台を作る。**

実装方針:

```text
比較的支持が強いLUCA的特徴        -> baselineへ
普遍的な恒常性・飢餓応答          -> coarse-grained baselineへ
不確実な具体機構                  -> 固定しない / 後続versionへ
後発能力                          -> 初期値0、将来進化可能にする
```

# 3. 現時点で確定しているV1.9方針

## 3.1 chemical-first ancestor

初期iLUCAは光依存・捕食依存で始めない。

```text
INITIAL_GENOME.light_absorption     = 0
INITIAL_GENOME.predation_efficiency = 0
```

初期Energy獲得の中心はchemical metabolismとする。

## 3.2 H2 explicit / CO2 implicit

V1.9では:

```text
H2  = 明示的な環境substrate
CO2 = 十分存在する暗黙の共基質
```

とする。

CO2 field、carbon fixation、炭素保存則、完全なcarbon cycleはV1.9へ同時導入しない。
これは意図的なscope制限であり、将来version候補とする。

## 3.3 chemical stockをEnergyそのものとして扱わない

V1.8までの:

```text
chemical stock -> 直接 usable Energy
```

をやめ、V1.9では:

```text
H2-like substrate
  -> uptake
  -> chemical free energy
  -> conversion efficiency
  -> usable Energy + loss/heat
```

というcoarse-grained chemical metabolismへ変更する。

## 3.4 state-dependent homeostasisを導入する

現行ではEnergy残量が非常に少なくても、移動・非core代謝・修復行動がほぼ変わらない。
V1.9では、未来予測や日没認識ではなく、**現在の内部Energy状態だけ**に依存した飢餓応答を導入する。

原則:

```text
Energy不足
 -> 随意活動 / 非core支出を抑制
 -> core maintenanceは残る
Energy回復
 -> 通常活動へ戻る
```

「夜だから休む」「あと何tickで日没だから貯める」のような未来予測は入れない。

## 3.5 Energyを operational + reserve の2-poolへ分離する

V1.9では個体内部Energyを:

```text
Operational Energy (E)
Reserve Energy     (R)
```

へ分離する方向で進める。

目的:

- 即時利用Energyと備蓄を分離する
- body_sizeだけで夜間/飢餓耐性が決まる構造をやめる
- 「余剰Energyを得たら即繁殖して備蓄できない」構造を解消する
- reserve strategyを自然選択可能にする

## 3.6 生理的レバーを遺伝化する

少なくとも次の3軸を進化可能にする方向で進める。

```text
starvation_sensitivity
reserve_capacity
reproduction_threshold
```

固定世界定数だけで適応度が決まる構造を減らす。

## 3.7 今後の成立確認では進化ON対照を必須とする

固定表現型runだけで「環境が悪い」と結論しない。

今後は原則として:

```text
fixed iLUCA control
+
evolution ON control
```

を対で確認する。

固定iLUCAが崩壊しても、進化ONで安定化するなら、それは失敗ではなく「その環境が適応を要求した」可能性がある。

# 5. 実装前に残っている主要設計課題

以下は**実装開始前に人間判断を通したい項目**。

## P1. Operational Energy + Reserve の詳細仕様【最優先】

未決:

- `E_max` と `R_max` の定義
- reserve capacity geneの数値意味
- Operational EnergyとReserveの初期比率
- Energy取得時にEとRへどう配分するか
- reserve保存効率 / mobilization効率
- reserve維持コストを持たせるか
- reserve不足時の取り崩し順序
- 分裂時のE/R分配
- death/corpseへどこまで内部Energyを引き継ぐか

注意:
単純にcapacityを増やして生存させるのではなく、自然なtrade-offを持つ設計にする。

## P2. starvation responseをどの支出へ適用するか

方向は確定しているが、適用範囲は未確定。

候補:

- movement
- non-core metabolism
- growth
- repair
- reproduction
- BMRの可変部分

原則としてcore maintenanceはゼロにしない。

検討点:

- activity response curve
- activity floor
- `starvation_sensitivity` geneの意味
- reserveがある間は通常活動を維持するか
- growth/reproductionを明示的に止めるか、Energy gateだけに任せるか

## P3. reproduction strategyの詳細

`reproduction_threshold`を遺伝化する方向は確定。

未決:

- thresholdが見るEnergyは `E` のみか `E+R` か
- capacity fractionとして定義するか
- Matter gateとの組み合わせ
- birth overheadの支払元
- parent/childへのOperational/Reserve分配
- 高threshold / 大reserveのtrade-offが十分自然に成立するか

## P4. H2 environmentの詳細

CO2 implicitは確定済み。

未決:

- H2 source数
- source配置
- source flux
- spatial diffusion
- environmental loss
- replenishment
- uptake式
- 個体間競合
- H2濃度の単位・ledger上のEnergy-equivalent
- 初期iLUCAのspawn方式

初期spawnについては以下が候補だが**未確定**:

```text
H2濃度に応じたsource-biased initialization
```

vent座標を個体へ教える方式は避ける。

## P5. 「0の能力が新しく出現する」mutation設計

初期値0にする予定の例:

```text
light_absorption = 0
predation_efficiency = 0
```

しかし現行の乗算中心mutationでは0から立ち上がりにくい。

未決:

- zero -> positive mutationの確率・scale
- 全continuous geneへ一律適用するか
- phototrophyのような能力とpredationのような複雑能力を同じ発生モデルで扱うか
- 「能力の起源」をcontinuous geneだけで扱うか、将来activation/innovation mechanismを導入するか

この項目は将来の進化シミュレーション全体に影響するため、雑に決めない。
