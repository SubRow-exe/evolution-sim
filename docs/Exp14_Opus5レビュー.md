# 0. 結論

**Exp13の絶滅は光量不足ではない。原因は次の1点にほぼ集約できる。**

> **夜の生存は「昼にどれだけ光を浴びたか」ではなく「体にいくら貯められるか」で決まる。
> そして繁殖ルールが、貯蔵を `0.6 × E_max` より上へ絶対に貯めさせない。**

`E_max = energy_capacity × matter = 100 × M` は `light_max` を含まない。
したがって光をいくら強くしても日没時のreserve上限は変わらず、増えるのは
**その夜に死ぬ子の数だけ**である。これが `light_max = 0.8 〜 4.0` の全8水準が
一様に 0/5 COMPLETE / 5/5 EXTINCT になった理由であり、
`4.0` が `3.0` より長生きしなかった理由でもある。

検算（現行実装の式をそのまま使用、body_size=1.0 固定、light specialist）:

```text
満タン (E=E_max)             で夜を  176 tick 生き延びる  -> 夜100 tickは本来越えられる
繁殖閾値 0.6*E_max が実際の上限 ->      106 tick           -> R = 100/106 = 0.94  ぎりぎり
出産直後の親 (M 1.2->0.78)   ->       83 tick           -> 餓死
出産直後の子 (M=0.42, 69%)   ->       77 tick           -> 餓死
```

**繁殖が「圧力弁」として働き、余剰Energyを子へ逃がし続けるため、
個体は夜を越すのに必要な貯金を作れない。** 昼が豊かであるほど繁殖が増え、
日没時には「reserveが浅い個体」と「もっと浅い新生児」で埋め尽くされる。

したがって:

- **H1（平均light不足）は、Exp13の時点ですでに実質的に反証されている**
- **H2（夜が長すぎる）と H3（繁殖がreserveを奪う）は、同じ1つの無次元量の
  分子と分母である**（§2-3）

Exp14の方向（light_maxを闇雲に伸ばさず原因を切り分ける）は**正しい**。
ただし現在の計画には **MUST FIX 3件 / SHOULD FIX 5件 / OPTIONAL 3件** がある。
最大の問題は、§9 の読み方ルールだと **正しいデータから誤った結論（「interaction」）が
出る構造になっている**ことである（§4-1）。

# 1. 何が起こったか

## 1-1. 事実の整理

| 項目 | 実測 |
|---|---|
| light_max | 0.8 / 1.2 / 1.5 / 1.8 / 2.1 / 2.4 / 3.0 / 4.0（8水準 × 5 seed） |
| COMPLETE | **全水準 0/5** |
| EXTINCT | **全水準 5/5** |
| verdict | `LIGHT_CALIBRATION_FAIL / REVIEW`（事前規則どおり） |
| Phase B | 未実施 |

`light_max=4.0`（5 seed）の共通パターン:

```text
tick   0   pop 100
tick   1   pop 200      ← 初期個体が一斉に出産（§2-5）
tick 100   pop 440〜503 ← 日没ちょうどが population peak（全seed一致）
tick 200   pop 8〜16    ← 夜明け。97.6% が夜のあいだに餓死
以降 昼に再増殖 → 夜に再崩壊 → 全seed starvation extinction
```

seed1 の場合、births_cum 515 に対し starvation deaths 515。
**生まれた個体はほぼ全て餓死しており、他の死因は事実上ゼロ**である。

## 1-2. 「population peak が毎回ちょうど tick 100」が決定的な手がかり

tick 100 は `period=200 / day_fraction=0.5` の**日没そのもの**である。
5 seed すべてで peak tick が一致しているということは、
**個体数を決めているのが確率的な要因ではなく、昼夜という決定論的スケジュールそのもの**
であることを意味する。

これは「光量が足りない集団がじりじり減る」パターンではない。
**昼に増えられるだけ増え、夜に構造的に死ぬ**パターンである。

# 2. 原因の定量診断

以下はすべて現行実装の式（`maintenance_and_movement` + `repair` + wander速度）を
そのまま回した検算である。夜は `light=0` なので収入は厳密に0になる。

## 2-1. 夜の生存時間は `E_max` と維持費だけで決まる

夜の1 tickあたり支出は

```text
BMR(0.15 + 0.15*M^0.75)
+ organ_upkeep(0.05*M*3.05)      ← light_absorption=2.0 が効いている
+ sense(0.0032)
+ membrane + resistance
+ move_cost(0.0405)              ← 夜も random walk する（後述）
+ repair                         ← damageは夜も溜まるので修復に支出する
```

で、**light_max はここに1つも現れない**。

body_size別の夜生存tick（夜の長さ = 100 tick）:

| M | `E_max` | 満タンから | satiety 0.85 から | **繁殖閾値 0.6 から** |
|---:|---:|---:|---:|---:|
| 0.35 | 35 | 101 | 86 | **61** |
| 0.50 | 50 | 125 | 106 | **75** |
| 0.65 | 65 | 144 | 122 | **86** |
| 0.80 | 80 | 159 | 135 | **96** |
| **1.00** | **100** | **176** | **150** | **106** |
| 1.20 | 120 | 190 | 162 | 114 |

**満タンなら 176 tick 持つので、100 tick の夜は本来余裕で越えられる。**
問題は満タンに到達できないことである。

## 2-2. 繁殖が「圧力弁」として reserve を 0.6·E_max に固定する

`_try_reproduce` は毎tick・全個体に対して呼ばれ、

```text
E >= repro_energy_frac(0.6) * E_max
AND M >= repro_matter_frac(0.8) * body_size
```

を満たせば必ず出産する。**時刻を見ない。** 絶対原則12（未来予測を入れない）に
照らせば当然の設計だが、その帰結として:

> 個体は `0.6 × E_max` を超えて貯金できない。超えた瞬間に出産で吐き出す。

昼が豊かでも `satiety_energy_frac = 0.85` には決して到達しない
（0.6 で繁殖が発火するため）。したがって**実際に到達可能な夜前reserveの上限は
`0.6 × E_max` であり、M=1.0 なら 106 tick 分**しかない。

出産の瞬間の収支（親 M=1.2 / E=72 で出産した場合、実装どおり）:

```text
親: M 1.20 -> 0.78   E 72.0 -> 41.2   (E_max 120 -> 78)
子: M = 0.420        E = 28.8         (E_max 42.0 の 69%)

親の夜生存 83 tick  -> 餓死
子の夜生存 77 tick  -> 餓死
```

**出産した親も、生まれた子も、その夜を越せない。**

日没時の集団は「これから出産する寸前の個体（106 tick）」から
「今出産したばかりの個体（83 tick）」「新生児（77 tick）」までの分布になる。
夜は100 tick。**分布の大部分が100を下回る。** 実測の夜間死亡率97.6%と整合する。

## 2-3. 支配しているのは1つの無次元量

```text
R = 夜の長さ / (到達可能なreserveでの夜生存tick)
```

| 条件 | 生存tick | 夜 | **R** | 帰結 |
|---|---:|---:|---:|---|
| Exp13 baseline（repro 0.6 / 夜100） | 106 | 100 | **0.94** | 崩壊 |
| 繁殖しないと仮定（満タン） | 176 | 100 | 0.57 | 生存 |
| A4 相当（repro 0.8 / 夜100） | 141 | 100 | 0.71 | 生存 |
| A2 相当（repro 0.6 / 夜40） | 106 | 40 | 0.38 | 生存 |

**`R ≈ 0.94` は「ぎりぎり足りない」であって「桁違いに足りない」ではない。**
だから少数個体が毎晩生き残り、翌日また増え、また崩れる — boom-bustの形になる。

そして重要なのは:

> **`light_max` は R の分子にも分母にも現れない。**

## 2-4. だから light_max 0.8〜4.0 が全部同じ結果になった

`light_max` を上げると:

- 昼の1個体あたり取得速度は上がる（midday `I=4.0` で `H(4.0,0.6)=0.869`、
  raw demand ≈ 3.48 E/tick に対し維持費は 0.57 E/tick — **昼は約6倍の余剰**）
- しかし余剰は `0.6 E_max` を超えた瞬間に出産へ流れる
- 結果、**日没時のreserveは変わらず、個体数だけが増える**
- 増えた個体は新生児の割合が高く、reserveはむしろ**浅い**

`docs/Exp13_結果考察_中間.md` §1.3 が「光を増やしても単調に安定化しない」と
書いているのは、この機構の直接の帰結である。**非単調性は異常ではなく予測どおり**である。

## 2-5. tick 1 の一斉出産は初期条件の副作用

```text
initial_energy = 50 / initial_matter = 0.8 / body_size = 1.0
-> E_max = 80 / 繁殖閾値 = 0.6 * 80 = 48
-> 初期個体は全員 E=50 >= 48 かつ M=0.8 >= 0.8 を満たす
```

**したがって全初期個体が最初のtickで出産する。** 実測の「開始直後に約200へ増殖」は
これで完全に説明できる。しかも run は夜明け（factor≈0.03）から始まるので、
**まだ1 Eも稼いでいない状態で全員が reserve を半分吐き出す。**

これは定常機構とは別の、独立した初期条件アーティファクトである。

## 2-6. V1.7の平衡body_sizeとの衝突（前回 M-4 の続き）

前回レビュー M-4 で「Exp13は body_size=1.0 で検証しているが、
Exp12が確定した平衡は 0.2459」と指摘した。今回の機構を当てると:

| M | 満タンでの夜生存 | 0.6·E_max での夜生存 |
|---:|---:|---:|
| **0.2459**（V1.7平衡） | **81** | **49** |
| 0.30 | 92 | 55 |
| 0.40 | 109 | 66 |
| 1.00（Exp13の設定） | 176 | 106 |

```text
満タン基準で夜100 tickを越える臨界 body_size  ≈ 0.341
実際に到達する 0.6*E_max 基準の臨界          ≈ 0.869
```

**Exp13が使った body_size=1.0 は臨界 0.869 のすぐ上（R=0.94）にあり、
V1.7が確定した平衡 0.2459 は臨界の 1/3.5 でしかない。**

つまり `bmr_core=0.15` が作った世界の平衡サイズでは、
**満タンにしても夜を越えられない。** V1.7の校正とV1.8の昼夜は、
現在の値のままでは両立しない。

# 4. Exp14 実験計画のレビュー

## 4-0. 支持する点

- **light_max を闇雲に伸ばさず原因切り分けへ切り替えた判断は正しい**
- **A1 の設計が特に良い。** cycle OFF + `light_max = 4/π ≈ 1.27324` で
  「時間平均供給を保ったまま連続暗期だけ除去する」のは、
  交絡のない綺麗な対照である。`4.0 × (1/π) = 1.2732` の計算も正しい
- 15 run × 2,000 tick は現象再現に十分で、コストも妥当（10周期観測できる）
- Exp14 で working `light_max` を確定しないと明記している
- Exp13 の chemical 結果を再sweepせず保存する判断
- Exp13 を条件変更して再開せず、**別experiment番号にした**のは絶対原則13どおり
- §8 の technical修正（`late_pop_ok` の意味論、SCIENTIFIC_STOP と TECHNICAL_FAIL の分離）を
  **実行前に**やると決めている点

## 4-1. MUST FIX ①: §9 の読み方ルールだと、正しいデータから誤った結論が出る

§9 は各armが「改善」したかを個別に見て、
**「複数条件が改善 → 原因は単独ではなくinteraction」**と読むと定めている。

§2-3 の R を各armへ当てると、予測はこうなる。

| arm | 変更 | 予測 R | 予測結果 |
|---|---|---:|---|
| A0 | baseline | 0.94 | **絶滅**（Exp13再現） |
| A1 | 夜を除去 | 0 | 存続 |
| A2 | 夜 100→40 | 0.38 | 存続 |
| A3 | light 4.0→8.0 | **0.94（不変）** | **絶滅** |
| A4 | repro 0.6→0.8 | 0.71 | 存続 |

**A1・A2・A4 がすべて改善する。** §9 のルールをそのまま適用すると
「3条件が改善したのでinteraction」という結論になる。

しかし実態は interaction ではない。**A1・A2・A4 は同じ1つの無次元量 R を
別々の経路で下げているだけ**である。A1は分子を0に、A2は分子を0.4倍に、
A4は分母を1.33倍にしている。

そのまま走らせると、**Exp14は正しいデータを取りながら
「原因は複合的」という弱い結論を出し、次に不要なfactorial mapを設計してしまう。**

### 変更提案（MUST FIX）

**R を主要読み出し量として事前登録する。**

```text
各armについて、run前に決定論計算で
  R = 夜長 / night_survival(0.6 * E_max, M)
を出しておく（シミュレーション不要）。

判定:
  (a) 全armの「崩壊 / 存続」が R の単調関数で説明できるか
      -> できる  : 単一機構。interactionではない。R の閾値が remedy を直接与える
      -> できない: そこで初めて interaction を疑う

  (b) A3 が改善したら、R 仮説は反証される（重要）
```

これで Exp14 は「改善したか」の定性比較から
**「1つの無次元量で説明できるかの定量的検証」**になる。追加runは0である。

## 4-2. MUST FIX ②: 「改善」の定義が事前登録されていない

§9 は「A1改善」「A2改善」と繰り返すが、**改善の定義がどこにも無い。**
§10 の終了条件も「比較できれば終了」であって判定基準ではない。

これは Exp11（`late_drift<=0.10` と tick予算の不整合）、
Exp12（B2 gate）で2回続けて踏んだのと**同じ型の失敗**である。
前回レビューで一般則として提案した

```text
判定閾値は、実行予定の条件で到達可能かを事前に検算する
```

が、まだ Exp14 には適用されていない。

### 変更提案（MUST FIX）

結果を見る前に、たとえば次を確定する。

```text
SURVIVES:  2,000 tick 到達（= 10周期完走）かつ最終population > 0 を 3/3 seed
MARGINAL:  2/3 seed
COLLAPSE:  0〜1/3 seed

補助（連続量。3 seedでも解像度が出る）:
  extinction tick の中央値
  生き延びた夜の数
  night_min / preceding_day_peak の周期ごとの推移
```

とくに `night_min / day_peak` は **R の実測版**なので、
これを主要指標に据えると §4-1 の検証がそのまま回る。

## 4-3. MUST FIX ③: A4 は2つの効果を同時に変えている

`repro_energy_frac` を 0.6 → 0.8 にすると:

1. **定常機構**: 夜前reserve上限が `0.6·E_max` → `0.8·E_max`（106 → 141 tick）
2. **初期条件**: 繁殖閾値 `0.8 × 80 = 64 > initial_energy 50` となり、
   **§2-5 の tick 1 一斉出産が起きなくなる**

§5 A4 は 2 を「影響も弱める」と副次効果として書いているが、
**これは副次効果ではなく交絡**である。A4 が改善したとき、
定常機構のおかげなのか初期条件アーティファクトが消えたおかげなのか分離できない。

### 変更提案（MUST FIX）

3 run 追加で分離できる。

```text
A5（新設）: 初期条件のみ変更
  baseline と同一（cycle ON / period 200 / light_max 4.0 / repro 0.6）
  initial_energy = 40   ← 繁殖閾値48を下回るので tick1一斉出産が起きない
  seed 1..3 / 2,000 tick

A5がA0と変わらない -> tick1一斉出産は主要因ではない -> A4の改善は定常機構による
A5がA0より改善     -> 初期条件の寄与が無視できない -> A4の解釈は分離が必要
```

`initial_energy` は世界ルールではなく初期条件なので、
「初期genomeを環境へ適応させて救済しない」（§3）には抵触しない。

## 4-4. SHOULD FIX ①: 貯蔵容量 `energy_capacity` を振るarmが無い

R の分母は `energy_capacity × M × reserve_fraction / drain` である。
Exp14 は分子（A2）と `reserve_fraction`（A4）を振るが、
**`energy_capacity = 100` は一度も触らない。**

診断としては次元的に A2/A4 と重複するが、**remedy としては最も筋が良い**。

```text
remedy候補           性格
1. 夜を短くする       惑星を生物に合わせる。最も筋が悪い
2. 繁殖閾値を上げる   繁殖生理の変更。副作用が広い
3. 貯蔵容量を上げる   昼夜世界の生物が現実に採る解（貯蔵多糖など）
4. 夜の低活動         行動の変更。現状 idle機構が存在しない（§4-8）
```

`energy_capacity = 100` は **V1.1で、昼夜が存在しない世界のために置かれた値**である。

## 4-5. SHOULD FIX ②: 進化OFF条件の結論範囲を明記する

## 4-7. SHOULD FIX ④: A1 は「供給」は揃うが「実効吸収」は揃わない

A1 は `light_max = 4/π` で **cellへの供給flux の時間平均**を A0 と一致させる。
これは正しい。ただし吸収は

```text
raw = light_uptake_coef * light_absorption * A_eff * phi * H(I, 0.6)
```

で、`H` が I に対して非線形である。

```text
A0 midday   I = 4.00  -> H = 0.869
A1 constant I = 1.273 -> H = 0.680
```

個体密度が高く供給律速の間はこの差は表に出ないが、
**個体数が少ない局面（夜明け直後など）では A1 のほうが1個体あたり取得が遅い。**

### 変更提案（SHOULD FIX）

A1 を変更する必要はない（供給を揃えるのが主目的で正しい）。
観測として **`H` の実現値と「実効吸収の時間平均」を A0/A1 で併記**し、
「供給は揃えたが吸収は完全には揃っていない」ことを結果文書に明記する。

## 4-8. SHOULD FIX ⑤: 夜も全個体が移動し続けている（休止機構が存在しない）

```python
if org.energy >= satiety_energy_frac * e_max and org.matter >= org.target_size:
```

M=1.0 での夜の支出内訳:

```text

```

支配的ではないが無視もできない。しかも**収入が厳密に0の時間帯に
移動を続けることに適応的意味がない**（光刺激が0なので走光性も働かない）。

なお `Config.idle_prob`（「刺激なし時に静止する確率」）は**定義だけ残っていて
どのコードからも読まれていない**（V1.6で参照が消えた）。

### 変更提案（SHOULD FIX）

Exp14 では変更しない（診断軸を増やさない）。ただし記録として:

```text
- 現在、夜間の休止機構は存在しない（idle_prob は dead config）
- remedy候補4として「刺激が無いときの低活動」は
  light userだけを止めるのではなく全個体対称のルールなので、
  絶対原則8（特定生態型へ直接ボーナスを与えない）に抵触しない
```

を Exp14 か V1.8仕様の「今後の選択肢」へ残すことを提案する。

# 7. 付録 — 検算スクリプト

`evosim/physiology.py` の `maintenance_and_movement` / `repair`、
`evosim/behavior.py` の wander速度、`evosim/simulation.py` の `_try_reproduce` を
そのまま写したもの。リポジトリのコードは変更していない。

```python
import math
SENS,MEM,DR,POWER,EFF,REP = 0.4,0.5,0.5,0.5,1.0,0.3
ORGAN = 2.0+0.3+0.5+0.05+0.2          # light specialist (light_absorption=2.0)
BMR_COEF,BMR_CORE = 0.3,0.15          # V1.7 close
E_CAP,D_CAP,PHI_FLOOR = 100.0,10.0,0.1
MET_DMG,MOV_DMG = 0.02,0.005
REPAIR_SPEND,REPAIR_EFF = 0.2,0.5

def night_survival(M, E0):
    """light=0 の夜を、維持費+移動+damage+repair を回して何tick持つか。"""
    E, D, t = E0, 0.0, 0
    while E > 0 and t < 100000:
        phi = max(PHI_FLOOR, 1.0 - D/(D_CAP*M*(1+DR)))
        v = 0.6*3.0*POWER/math.sqrt(M)*phi        # 夜も random walk（idle機構なし）
        E -= (BMR_CORE + (BMR_COEF-BMR_CORE)*M**0.75
              + 0.05*M*ORGAN + 0.02*SENS**2 + 0.03*MEM*M**0.5
              + 0.02*DR*M + 0.05*M*v*v/EFF)
        D += MET_DMG*M + MOV_DMG*M*v*v
        if E > 0 and D > 0:
            phi2 = max(PHI_FLOOR, 1.0 - D/(D_CAP*M*(1+DR)))
            spend = min(REPAIR_SPEND*REP*M*phi2, E, D/REPAIR_EFF)
            E -= spend; D -= REPAIR_EFF*spend
        t += 1
    return t

M = 1.0
print("満タン        ", night_survival(M, E_CAP*M))          # 176
print("satiety 0.85  ", night_survival(M, 0.85*E_CAP*M))     # 150
print("繁殖閾値 0.6  ", night_survival(M, 0.6*E_CAP*M))      # 106  <- 夜100に対しR=0.94

# 出産直後（親 M=1.2 / E=0.6*E_max=72 で出産、_try_reproduce と同じ順序）
Mp, Ep = 1.2, 0.6*E_CAP*1.2
m_child = 0.35*Mp
e_child = min(0.4*Ep, E_CAP*m_child)
print("親", night_survival(Mp-m_child, Ep-0.4*Ep-2.0))       # 83  -> 餓死
print("子", night_survival(m_child, e_child))                # 77  -> 餓死
```
