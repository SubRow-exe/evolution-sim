## 1. Exp11で確認したかったこと

Exp11の目的は、V1.7で導入した縮小不能な基礎維持代謝 `bmr_core` が、現行モデルで見られていた `body_size` の過度な小型化傾向を弱め、体サイズが環境に応じた内部領域へ進化できる余地を作れるかを調べることだった。

ここで重要なのは、**大きな個体を作ること自体が目的ではない**ことである。

狙いは、従来のBMR式では体が小さくなるほど維持コスト上の有利さが強まりやすかったため、体サイズを小さくすればするほど得をする構造を弱めることにある。

`bmr_core` は身体サイズに比例して縮小しない最低限の維持コストを加える。そのため小型化によって節約できるBMRの割合が小さくなり、理論的には小型個体の相対的な優位性を弱める方向に働く。

Exp11ではこの効果を他の遺伝子進化から切り離すため、`body_size` だけを進化可能とし、他13遺伝子を固定した。

# 2. まず正式判定をどう読むべきか

Exp11の事前登録判定は、

```text
SCIENTIFIC_VERDICT = NO_SELECTION / REVIEW
理由: CONTROL_NOT_REPRODUCED
```

となった。

B1の `bmr_core=0` 対照で、事前に「小型化シグナル」と定義した

```text
p_low >= 0.50
```

を満たすseedが8本中0本だったためである。

これは事前登録した判定手続きを守った結果であり、**この判定自体は変更しない**。

ただし、この結果を

> `bmr_core` に効果がなかった

と解釈してはいけない。

事前登録判定が失敗した理由は、10,000 tick時点の `bmr_core=0` が予想したほど明確に下限へ張り付かなかったためである。

一方、実測データを見ると、B1では `bmr_core` を増やすにつれて `body_size` が系統的に大型側へ移動している。

つまりExp11から言えることは、

1. **事前に想定した「対照が10,000 tickで明確に下限張り付きする」という前提は成立しなかった**
2. しかし、**`bmr_core` がbody_size進化へ影響するという現象自体は明瞭に観測された**

の2点である。

正式判定と事後的な科学解釈は分離して扱う必要がある。

# 3. B1では `bmr_core` に対する明瞭なbody_size応答がある

B1 light-only環境の最終body_size中央値は代表点で次のように変化した。

```text
bmr_core=0.000 -> 0.2164
bmr_core=0.030 -> 0.2334
bmr_core=0.050 -> 0.2577
bmr_core=0.075 -> 0.2716
bmr_core=0.100 -> 0.3356
bmr_core=0.150 -> 0.4088
bmr_core=0.200 -> 0.4389
bmr_core=0.300 -> 0.6273
```

低値域にはseedばらつきと非単調な細かな揺れがあるが、大局的には明確な正の関係である。

特に `bmr_core≈0.075–0.100` 以降では、`bmr_core=0` と比べて大型側へのシフトがかなり明瞭になる。

また `p_low` も、`bmr_core` が増えるにつれてほぼ消失する。

代表例:

```text
bmr_core=0.000 -> p_low median 0.3846
bmr_core=0.050 -> p_low median 0.1100
bmr_core=0.075 -> p_low median 0.0794
bmr_core=0.100 -> p_low median 0.0048
bmr_core>=0.150 -> ほぼ0
```

したがって、少なくとも10,000 tickまでの範囲では、`bmr_core` は狙いどおり**小型側への進化を抑える方向に働いている**。

---

# 4. なぜ `bmr_core` を上げると大型側へ移動するのか

V1.7のBMRは

```text
BMR = bmr_core + (bmr_coef - bmr_core) * M^0.75
```

である。

従来の `bmr_core=0` では、体が小さくなるほどBMR自体も強く小さくなる。

そのため小型個体は、少ないMatterで生存できるだけでなく、基礎維持Energyも低く抑えられる。

`bmr_core>0` では、身体を小さくしても消えない維持費が残る。

つまり

```text
小型化によって節約できる維持コスト
```

が減少する。

結果として、小型化による相対的な利益が弱まり、従来より大型側のbody_sizeでも競争できるようになったと考えるのが自然である。

ここで重要なのは、`bmr_core` が大型化を直接報酬しているわけではないことである。

主な作用は、**過度な小型化に対する既存のコスト上の優位性を削ること**である。

したがって、Exp11で見えた大型化は「大型個体を作る新しい力」というより、これまで小型側へ強く傾いていた選択圧のバランスを戻した結果と解釈するのが適切である。

---

# 5. `bmr_core` が強いほどpopulationが減るのは自然な副作用

B1では `bmr_core` 増加に伴ってfinal populationが減少した。

代表例:

```text
bmr_core=0.000 -> final population median 5658
bmr_core=0.050 -> 4216.5
bmr_core=0.100 -> 3036
bmr_core=0.150 -> 2339.5
bmr_core=0.200 -> 2049.5
bmr_core=0.300 -> 1421
```

これは少なくとも一部は、個体が大型化したことによるMatter配分の変化で説明できる。

系全体のMatterは保存されるため、平均的な1個体当たりMatterが増えれば、同じ総Matterから維持できる個体数は減る。

さらに `bmr_core` 自体が小型個体にも最低維持費を課すため、非常に多数の小型個体を低コストで維持する構造も弱くなる。

したがって、population低下は単独で「生態が悪化した」とは判断できない。

Exp11の目的の一つには、小型多数化による計算量増大を副次的に緩和できるかを見ることも含まれていたため、この方向自体は必ずしも問題ではない。

ただし、高すぎる `bmr_core` によりpopulation・biomass・繁殖機会が必要以上に縮むなら別問題であるため、恒久値選定時にはbody_sizeだけでなく生態全体とのトレードオフを見る必要がある。

# 6. biomass_fraction低下の意味

B1では `bmr_core` 増加に伴ってbiomass_fractionも低下している。

代表例:

```text
bmr_core=0.000 -> 0.4658
bmr_core=0.050 -> 0.4075
bmr_core=0.100 -> 0.3724
bmr_core=0.150 -> 0.3489
bmr_core=0.200 -> 0.3289
bmr_core=0.300 -> 0.3265
```

これは `bmr_core` を高くするほど、生物群集が系全体Matterのより小さい割合しか保持できなくなることを示す。

したがって `bmr_core` は単にbody_sizeの選択圧だけでなく、生態系のMatter配分にも影響している。

低〜中程度の `bmr_core` では「小型化圧を弱める」という狙いに対して許容可能な副作用かもしれないが、0.15–0.30のような高値では生態構造をかなり変えている可能性がある。

そのため、**body_sizeが大きくなったから高い `bmr_core` ほど良い、とはならない**。

恒久値は目的を満たす最小限の変更を選ぶべきである。

# 7. B2/B3は「環境によって選ばれるサイズが違う」可能性を残している

Exp11ではB1だけでなく、B2 chemical-only、B3 mixedでも同じ `bmr_core` 水準を調べた。

重要なのは、`bmr_core=0` の時点から環境ごとのbody_size状態が大きく異なることである。

特にB2では、B1のような強い小型化状態ではなく、より大きなbody_size領域が維持されている。

このことから、body_sizeがモデル全体で単一の値へ機械的に張り付いているわけではなく、**資源環境によって異なる選択圧が存在している可能性**がある。

これはV1.7の狙いに対して重要である。

望ましいのはbody_sizeを一律1.0付近へ固定することではなく、環境ごとに異なる体サイズへ進化できることである。

Exp11の結果は少なくとも、`bmr_core` を導入した瞬間に全環境が同じbody_sizeへ潰れるような挙動ではないことを示している。

ただし、Exp11の事前登録判定ではB1から候補が選出されなかったため、B2/B3を用いた正式なenvironmental vetoは実施対象にならなかった。

したがってB2/B3は現時点では補助的な証拠として扱う。

# 8. 10,000 tick時点では進化がまだ止まっていない可能性が高い

Exp11の解釈で最も重要な未解決点が `late_drift` である。

B1の代表値は次の通りだった。

```text
bmr_core=0.000 -> late_drift median 0.3952
bmr_core=0.050 -> 0.3149
bmr_core=0.100 -> 0.3055
bmr_core=0.150 -> 0.2374
bmr_core=0.200 -> 0.2438
bmr_core=0.300 -> 0.1264
```

高 `bmr_core` ほど概ね小さくなる傾向はあるものの、10,000 tick時点でも無視できない変化量が残っている。

したがって、Exp11のfinal body_sizeをそのまま「平衡body_size」と呼ぶことはできない。

ここから生じる二つの仮説がある。

## 8.1 平衡変更仮説

`bmr_core` が実際に選択圧のバランスを変えた結果、

```text
bmr_coreごとに異なる内部body_sizeへ収束している途中
```

である可能性。

この場合、さらに長く走らせればbody_sizeの時間変化は徐々に小さくなり、各 `bmr_core` に応じた異なる内部領域で安定するはずである。

## 8.2 単なる遅延仮説

`bmr_core` によって個体が大型化し、世代交代や進化速度が遅くなった結果、

```text
10,000 tickではまだ小型化し切っていないだけ
```

である可能性。

この場合、十分長く走らせれば `bmr_core>0` 条件でもbody_sizeはさらに低下し、最終的に `bmr_core=0` と似た小型領域へ向かう可能性がある。

Exp11だけではこの2つを区別できない。

# 9. 世代交代が遅くなる可能性について

`bmr_core` を高くするとbody_sizeが大型化し、それに伴い世代交代が遅くなる可能性がある。

考えられる理由は一つではない。

- 大型個体ほどEnergy容量が大きくなり、餓死まで長く生きる可能性
- 繁殖条件を満たすために必要なMatter / Energy規模が大きくなる可能性
- 個体寿命が延び、同じtick数中に経験する世代数が減る可能性
- populationが小さくなることで突然変異の総試行回数が減る可能性

したがって、単純に

```text
50,000 tick走ったから十分長い
```

とは限らない。

進化平衡を議論する際にはtickだけでなく、どれだけ世代交代したかも併記する必要がある。

Exp11で記録された `max_generation` はこの観点で重要な指標であるが、これまでcollect処理にsnapshot読込不具合があった経緯もあるため、**世代指標の解釈はExp12で改めて検証する**。

Exp12では最低限 `max_generation` を再確認し、可能ならgeneration分布の中央値や高分位も併記する方が望ましい。

# 10. `bmr_core=0` の対照が失敗した理由の解釈

事前登録では、`bmr_core=0` B1が10,000 tickまでに十分強い小型化を再現すると想定していた。

しかし実際には `p_low>=0.50` を満たしたseedは0/8だった。

これは現行式に小型化圧が存在しないことを直接意味しない。

実際、最終body_size中央値は0.2164と下限0.2のかなり近くまで低下しており、多くのseedでもp_lowは相当量存在する。

したがって、より自然な解釈は、

> **小型化方向の圧力自体は見えているが、10,000 tickという時間と `p_low>=0.50` という事前閾値では「明確な下限張り付き」と判定できるほど進行しなかった**

である。

この点も、Exp12で `bmr_core=0` を長期追跡する理由になる。

もし長期runで0.2近傍への収束が進めば、Exp11のcontrol failureは主として時間スケールと事前閾値の問題だったと理解できる。

逆に `bmr_core=0` 自体が0.2より上の内部領域で安定するなら、「現行モデルはそもそもbody_size-only条件では下限張り付きしない」という、より根本的な理解修正が必要になる。

# 11. Exp11から現時点で言えること

Exp11の結果から、現時点では次のように整理する。

## 比較的強く言えること

1. **`bmr_core` はbody_size進化へ実際に影響している。**
2. B1では `bmr_core` 増加に伴ってbody_sizeが大型側へ系統的に移動する。
3. `bmr_core` は小型側個体の割合 `p_low` を大きく減少させる。
4. したがって、V1.7の設計意図である「小型化の維持コスト上の優位性を弱める」作用は少なくとも10,000 tick範囲で観測されている。
5. 高い `bmr_core` ほどpopulationとbiomass_fractionを下げるため、副作用とのトレードオフが存在する。
6. 環境によってbody_size応答は異なり、一律のサイズへ固定される単純な挙動ではない。

## まだ言えないこと

1. 10,000 tick時点のbody_sizeが最終的な進化平衡か。
2. `bmr_core` が平衡点そのものを変えたのか、単に小型化を遅くしただけなのか。
3. `bmr_core=0` が十分長期には本当に下限0.2へ張り付くのか。
4. 高 `bmr_core` 条件の見かけの安定が世代交代不足ではないか。
5. V1.7の恒久値をどこに置くべきか。

したがって、Exp11だけで恒久 `bmr_core` を確定するのは早い。

# 12. Exp12へ持ち越す中心課題

Exp12の最優先課題は新しい候補探索ではなく、Exp11で見えた現象の意味を確定することである。

中心問いは一つにまとめられる。

> **`bmr_core` によってbody_sizeの長期的な進化平衡そのものが変わったのか、それとも進化速度が遅くなっただけなのか。**

そのためExp12では、

- Exp11 B1と同じ環境
- body_sizeのみ進化
- 代表的な `bmr_core` 水準
- 同じseed群
- 10,000 tickより大幅に長い連続run

を使用し、body_size trajectoryを追跡する。

重要なのはfinal値だけではなく、後半windowの**符号付き変化**を見ることである。

例えば、

```text
10k -> 20k -> 30k -> 40k -> 50k
```

でbody_sizeがほぼ変化しなくなれば平衡変更仮説を支持する。

一方、高 `bmr_core` 条件でも時間とともに継続してbody_sizeが低下するなら、単なる遅延仮説が強くなる。

同時にgeneration指標を追跡し、tick基準の見かけの収束が世代交代不足によるものではないか確認する。

# 13. V1.7に対する現段階の評価

Exp11終了時点で、V1.7の `bmr_core` は**棄却すべき案ではない**。

むしろ、狙っていた方向の効果はかなり明瞭に出ている。

ただし、Exp11はその効果が「長期平衡の変更」であることまでは証明していない。

したがって現段階の評価は、

```text
機構として有望
ただし恒久値選定は保留
長期収束をExp12で確認する
```

とするのが最も妥当である。

Exp12で内部平衡が確認できた場合、その後に初めて

```text
どの程度の bmr_core が、最小限の変更で小型化圧を適切に弱めるか
```

という恒久値選定へ進む。

逆にExp12で全候補が長期的に0.2近傍へ向かうなら、`bmr_core` 単独では根本解決になっておらず、V1.7の設計を再検討する必要がある。
