# 0. 方針転換の理由

physical mode移行後、自然選択を直接観測することを狙った実験では、複数回にわたり明瞭な選択を確認できていない。

根本的な問題は、現在の計算予算では1 runあたり概ね数世代しか進まず、変異から十分な形質差が生じるまで進化を待つ設計と整合しないことである。またExp20の診断では、個体数比ベースのearly fitness指標に対してseed間変動が大きく、V1.11 phototrophyの理論効果量を3 seedで検出することは現実的でないことが確認された。

したがって今後は、

> **「進化が起こるまで待つ」から「形質変更がfitnessへ与える効果を直接測る」へ方法論を変更する。**

進化・invasion実験は最後に行い、その前に効果量と必要seed数を直接推定する。

# 1. 用語と測定の二段階化

## 1.1 Stage 1 — paired fitness-effect assay

同一seed・同一初期配置から、baseline runとvariant runを作り、対象形質／能力だけを変更する。

例:

```text
Run A: baseline
Run B: storage_capacity +20%
```

比較する連続量:

```text
mean matter
mean stored Energy
cumulative growth
maintenance expenditure
starvation exposure / starvation death
reproduction timing
survival time
resource uptake
```

これは厳密な意味での「選択係数」そのものではなく、

> **その形質変更が、その環境でfitness関連量をどちら向きへどの程度動かすか**

を高感度に測るmechanistic fitness-effect assayと位置付ける。

同一seedを使うことでcommon random numbersによる大幅な分散低減を狙う。ただしrun間で出生・死亡・イベント順が分岐した後まで乱数系列が完全一致する保証はないため、「seed雑音が完全に0」とは扱わない。

## 1.2 Stage 2 — competition assay

Stage 1で明瞭なfitness effectが確認された形質について、baseline lineageとvariant lineageを同一環境内で競争させる。

例:

```text
50% baseline
50% variant
```

ここでlineage比の変化、per-capita birth/death、survivalなどから相対的なselectionを測る。

**Stage 1 = 高感度な機構／fitness効果検証**  
**Stage 2 = 実際の競争下での相対選択検証**

と明確に分離する。

# 2. まず実施する修正・gate

phototrophyに関するExp20 Attempt 1の問題は、実験方法論の変更とは独立に修正する。

## 2.1 legacy light経路除去

physical modeでは旧 `_absorb_light()` によるEnergy流入を完全に排除する。

## 2.2 production-step test

`Simulation.step()` を実際に通し、phototrophy由来Energy差が独立計算したphysical上界内に収まることを確認する。

上界計算では、N制限側の動的absorptanceに追随させず、N非制限側の理論最大 `1 - exp(-light_absorption)` を用いる。

## 2.3 G7 — effective config一致gate

formal run前に、`effective_config.json` が事前登録した条件表とfield単位で一致することを自動assertする。

Exp20 Attempt 1では計画上 `light_cycle = OFF` に対して実際は `light_cycle_enabled=True` が継承されていたため、この種の不一致を恒久的に防ぐ。

## 2.4 daylight coupling

現行V1.11 physical phototrophy経路では `daylight_factor` がphoton fluxへ掛かっておらず、夜でも同じ光量でphototrophyが動く。

これは既知の設計欠落として記録し、少なくとも「V1.11では結合しない」のか「今回修正して結合する」のかを明示的に決める。mechanical calibrationではlight cycleをOFFにして係数1.0で検証可能である。

# 3. 汎用 paired-fitness harness

今後の形質検証を共通化するため、個別実験ごとに比較コードを書くのではなく汎用ハーネスを作る。

最低要件:

```text
- 同一base config / seed / initial stateを生成
- baseline と variant の差分parameterだけを明示
- effective config差分をartifactへ保存
- 初期個体／genomeの一致を検証
- lineage別・run別の連続量trajectoryを同じcadenceで保存
- paired differenceを時系列で出力
- run分岐後のRNG状態差も診断可能にする
- C/N/P, H2, Energy等の既存ledger gateを保持
```

このハーネスは既存3形質・phototrophy・将来の新形質に共通利用する。

# 4. 最優先実験 — 既存3形質のfitness effect再検証

phototrophyより先に、V1.9以降持ち越されている既存生理形質の適応価値を直接測る。

対象:

```text
storage_capacity
starvation_horizon
reproduction_horizon
```

初期variant候補:

```text
baseline × 0.5
baseline × 0.8
baseline × 1.2
baseline × 1.5
```

環境:

```text
A0_STATIC
A2_DYNAMIC_VENT
```

まずStage 1 paired assayを24–48 h程度で行う。

## 4.1 主質問

> **同じ形質変更でも、static環境とdynamic vent環境でfitness effectの方向・大きさが変わるか？**

特に、例えばstorage_capacityについて:

```text
A0_STATIC      : effect ≈ 0
A2_DYNAMIC_VENT: +storage が正のeffect
```

が得られれば、dynamic ventが形質依存の選択圧を作る環境として機能している直接的証拠になる。

## 4.2 Stage 1 readout

形質ごとに少なくとも:

```text
Δ mean matter(t)
Δ stored Energy(t)
Δ cumulative growth
Δ survival time / hazard
Δ starvation exposure
Δ reproduction timing
```

をpaired differenceとして評価する。

結果の大きさ・単調性・seed間再現性を見て、Stage 2へ進める形質／水準を選ぶ。

## 4.3 Stage 2 competition

Stage 1で明瞭な差が出た形質のみ、baselineとvariantを同一世界で競争させる。

ここで初めてlineage比の変化から実際の相対selectionを評価する。

# 5. phototrophyは既存3形質の後に校正する

土台となる生理形質に環境依存のfitness effectが存在することを確認した後、同じpaired harnessでphototrophyを評価する。

## 5.1 photon flux calibration

候補:

```text
0.015
0.05
0.15
0.5
1.5
umol/m2/s
```

同一seed・同一初期状態の:

```text
phototrophy capability OFF
vs
phototrophy capability ON
```

で比較する。

主readout:

```text
mean matter trajectory
cumulative growth
mean stored Energy
maintenance offset
survival time / hazard (dynamic環境)
physical Energy上界との整合
```

目的は、単に「差がある光量」を探すのではなく、

> **後段のcompetition / invasion実験で現実的なseed数で検出可能な効果量が得られる光量域を特定すること**

である。

効率やstructural N costを同時に動かさず、まずphoton fluxの1軸校正とする。

# 6. invasion / evolutionは最後に設計する

paired assayおよびcompetition assayから得られた実測効果量・seed間変動を用いて、初めてformal invasion / evolution実験を設計する。

事前に決める:

```text
expected effect size
noise / seed variance
required seed count
required duration / generations
founder frequency
primary endpoint
stopping rule
```

必要seed数や必要世代数が現実的でない場合は、formal evolution runを行わない。

**「走らせてから検出できるか考える」のではなく、「検出可能性を確認してから走らせる」ことを原則とする。**

# 8. この方針で解消する宿題

このロードマップの最初の目的はphototrophyだけではない。

V1.9以降持ち越されている:

> **physical modeのdynamic環境で、既存の生理形質に本当に環境依存の適応価値が存在するか**

を先に直接検証する。

これが確認できれば:

1. dynamic vent自体がselection pressureとして成立していることを示せる
2. 既存3形質の適応価値を定量化できる
3. phototrophyの効果を土台の生理形質と切り分けやすくなる
4. 今後の新形質も同じpaired assay → competition → evolutionの順で検証できる

---

# 9. 方法論上の恒久原則

今後の機構追加・進化実験では以下を標準とする。

```text
A. まずcontinuous fitness-related readoutで効果量を測る
B. 次にcompetitionでrelative selectionを測る
C. 最後にinvasion/evolutionを行う
D. common-random-number paired runは分散低減手法であり、完全な無雑音とはみなさない
E. endpointの分解能と理論効果量を実行前に比較する
F. effective configをpreregistrationと自動照合する
G. 異常に完全一致したseed結果や2^n同期挙動は再現性ではなくmechanism auditのtriggerとする
```

この方針をV1.11以降の選択圧検証の標準方法論とする。
