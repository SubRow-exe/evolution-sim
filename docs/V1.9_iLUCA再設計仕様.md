# 0. V1.9の目的

V1.9は、単なる「phototrophy起源実験」ではない。

> **より生物学的に妥当なchemical-first iLUCA baselineを再構築し、環境側を生存に合わせて曲げるのではなく、生物自身が自然な環境圧へ生理・進化で応答できる土台を作る。**

V1.8でday/night機構を導入した結果、既存iLUCAには飢餓時の状態依存生理や進化可能な貯蔵・繁殖戦略が不足していることが判明した。
したがってV1.8のparameter tuningを続けず、V1.9で祖先モデルを再設計する。

比較的支持の強いLUCA像として、V1.9は以下を採用する。

- chemical-first / anaerobic chemoautotrophyをcoarse-grainで表現
- H2-like substrateを明示する
- CO2は十分存在する暗黙の共基質とする
- light利用は祖先能力として与えない
- predationは祖先能力として与えない
- ATP/ADPやWood-Ljungdahl enzyme networkは分子レベルでは再現しない

主要参考:
- Moody et al. 2024, Nature Ecology & Evolution, DOI: 10.1038/s41559-024-02461-1
- Weiss et al. 2016, Nature Microbiology, DOI: 10.1038/nmicrobiol.2016.116

```text

```

```text

```

HARD RULE:

```text
PHOTOTROPHY OFF -> light_absorptionは必ず0として機能する
PREDATION OFF   -> predation_efficiencyは必ず0として機能する
```

continuous mutationの加算項だけでgateを迂回してはいけない。

# 4. 1-pool Energy / storage capacity

個体内部Energyは1変数 `energy` のままとする。

capacity:

```text
E_max = energy_capacity_base * genome[storage_capacity] * matter
```

Config implementation reference:

```text
energy_capacity_base = 100.0
storage_upkeep_coef  = 0.02
```

旧 `energy_capacity` はV1.9内部ではdeprecatedとし、新ロジックでは `energy_capacity_base` を使う。

## 4.1 storage capacityのcost

容量を持つこと自体を無料にしない。

```text
storage_upkeep = storage_upkeep_coef * storage_capacity * matter
```

これは「大容量だから人工的に罰するfitness penalty」ではなく、貯蔵構造・物質を維持するcoarse-grained生理costとしてmaintenanceへ含める。

大容量には:

```text
+ 飢餓耐性
- 維持費
```

のtrade-offが生じる。

## 4.2 capacity縮小時

matter低下、mutation、捕食等で `E_max` が現在Energyを下回った場合:

```text
excess = max(0, energy - E_max)
energy = min(energy, E_max)
excess -> heat / energy_out_cum
```

保存則を必ず閉じるhelperを置くこと。

# 5. starvation signal = runway

Energy残量率やE_targetを状態信号に使わない。

個体の「通常活動時にあと何tick維持できるか」を内部状態として使う。

```text
P_full = full_activity_expenditure_rate(org)
runway = energy / max(P_full, eps)
```

`P_full` はactivity suppressionを掛ける前のreference expenditureで、現在のmatter / genome / damage stateのみから決める。
未来の環境・日没・将来収入は一切参照しない。

## 5.1 P_fullに含めるもの

少なくとも以下を含める。

```text
full BMR
organ upkeep
sense upkeep
membrane upkeep
resistance upkeep
storage upkeep
full repair budget (現在damageで必要な範囲まで)
reference wander movement cost
```

reference wander movement costは、activity suppression無しの現在 `v_max` から既存 `wander_speed_frac` を使って求める。

以下はepisodicなのでP_fullから除外する。

```text
attack event cost
birth_overhead
matter assimilation event cost
```

P_fullはfitnessではなく、現在の内部需給状態を無次元化するための生理referenceである。

---

# 6. starvation_horizon / homeostasis

遺伝子:

```text
H = genome[starvation_horizon]  # tick
```

状態:

```text
state = clip(runway / max(H, eps), 0, 1)
```

V1.9ではresponse curveに追加geneを持たせず、まず線形 `state` を使う。

Config implementation reference:

```text
starvation_metabolic_floor = 0.10
starvation_uptake_floor    = 0.50
```

係数:

```text
metabolic_factor = starvation_metabolic_floor
                 + (1-starvation_metabolic_floor) * state

uptake_factor    = starvation_uptake_floor
                 + (1-starvation_uptake_floor) * state
```

意図:

- runwayが十分 -> 1.0 / 通常活動
- runway不足 -> 支出を強く抑える
- 同時にuptake能力も弱く低下するため、恒常的な省エネが無償の純益にならない
- 時計・夜認識・未来予測は無い

## 6.1 metabolic_factorを掛ける対象

掛ける:

```text
BMRのbmr_core以外の可変部分
repair spend/budget
```

掛けない:

```text
bmr_core
organ upkeep
sense upkeep
membrane upkeep
resistance upkeep
storage upkeep
movement speed / movement cost
attack/birth event cost
```

movementをV1.9の飢餓応答へ直接結合しない。
資源探索能力そのものをstarvation geneで固定的に弱めるのを避けるため。

## 6.2 uptake_factorを掛ける対象

少なくとも:

```text
H2 uptake capacity
light uptake capacity (phototrophy ON時)
nutrient uptake capacity
```

corpse/predationはV1.9 homeostasisの主対象にしない。

この非対称抑制により、資源が無いときは省エネが有利、資源が豊富なときは通常代謝・高uptakeが有利、という条件依存trade-offを作る。

# 7. reproduction strategy

旧world constant `repro_energy_frac` をV1.9の繁殖Energy gateとして使わない。

遺伝子:

```text
R_h = genome[reproduction_horizon]
```

Energy gate:

```text
runway >= R_h
```

Matter gateはV1.9では既存構造を維持する。

```text
matter >= repro_matter_frac * target_size
```

これにより繁殖タイミングをstorage capacity fractionから分離する。

## 7.1 分裂処理

順序を固定する。

```text
1. runway gate
2. Matter gate
3. birth_overheadを親Energyから支払えるか確認
4. continuous mutation + capability mutationでchild genotype生成
5. child matter = child_matter_frac * parent matter
6. parent matterからchild matterを差し引く
7. child Energy offer = parent reproduction_investment * parent post-overhead Energy
8. childのmutated storage_capacityとchild matterからE_max_childを算出
9. child capacityまでEnergyを移す
10. parent/child双方でcapacity clampし、overflowはheatへ
```

既存 `reproduction_investment` gene と `child_matter_frac` は維持する。

高い `reproduction_horizon` は安全余裕を増やすが世代交代を遅らせる。低い値は繁殖を早めるが、分裂後の親子が飢餓に近づきやすい。

# 9. H2 vent配置

V1.9 baselineは:

```text
複数vent
全vent同一総flux
固定位置
非重複
世界端で欠けない
```

とする。

既定:

```text
n_vents = 4
vent_radius_cells = 2
```

## 9.1 center sampling

vent中心候補は:

```text
vx in [r, grid_w-r-1]
vy in [r, grid_h-r-1]
```

のみとする。

既存ventとsource diskが重なる候補は除外する。
候補集合を決定的な順序で構築し、その中からrngで選ぶ。
配置不可能なら明示的ValueError。

これにより:

- edge clippingによるセル当たりflux差をなくす
- vent重複による隠れ高fluxをなくす
- seed間で総fluxとsource geometryを揃える

vent間の静的な強弱はV1.9では入れない。
将来、vent寿命・盛衰・新生など時間変動として検討する。

# 10. H2 spatial physics

旧chemicalの「source円盤内は平坦 / 外は0」の階段場をやめる。
H2には明示的な拡散を入れ、source周辺にhalo/勾配を作る。

Config implementation reference:

```text
h2_vent_flux       = 16.0   # substrate/tick/vent
h2_loss_frac       = 0.10
h2_diffusion       = 0.05
h2_uptake_coef     = 0.5
h2_uptake_half     = 6.15
h2_energy_yield    = 1.0
h2_conversion_eff  = 0.60
```

数値はimplementation referenceであり、生物学的最終値ではない。

## 10.1 world update order

1 tick:

```text
1. environmental loss
2. source influx
3. 4-neighbor Laplacian diffusion
```

拡散境界は既存nutrientと同じreflecting boundaryを使い、拡散自体は総H2量を保存する。
`h2_diffusion` はexplicit 2D Laplacianの安定範囲をConfig validationで守ること。

## 10.2 initial stock

開始時だけ人工的パルスを置かない。
新しいdiffusion+loss+source方程式の定常場を厳密に解く必要はないが、初期化で極端な一過性を作らないこと。

推奨実装:

- zeroからwarm-upして初期fieldを作るhelperを用意する、または
- deterministic fixed-point iterationで生物不在定常場へ収束させる

この初期field構築はsimulation RNGを消費してはいけない。

# 11. H2 uptake / competition

局所H2濃度 `C` に対し:

```text
H(C,K) = C/(C+K)

J_demand = h2_uptake_coef
         * chemical_absorption
         * effective_surface(matter)
         * phi
         * uptake_factor
         * H(C, h2_uptake_half)
```

`J_demand` はH2 substrate demand。
同一セルの個体間競合は既存V1.4以降の需要比例配分原則を再利用する。

取得substrate `J`:

```text
chemical_free_energy = J * h2_energy_yield
usable_gain = chemical_free_energy * h2_conversion_eff
conversion_loss = chemical_free_energy - usable_gain
```

usable_gainを1-pool `energy`へcreditし、E_maxを超えた分はheat。
conversion_lossもenergy_outへ記録する。

H2 stockは必ず実取得量だけ減らす。

# 12. Energy ledger

H2はsubstrateだが、保存則検証ではEnergy-equivalentを持たせる。

```text
H2_energy_equiv = total_h2 * h2_energy_yield
```

外部source:

```text
energy_in += h2_source_amount * h2_energy_yield
```

環境H2 loss:

```text
energy_out += h2_loss_amount * h2_energy_yield
```

H2 -> usable Energy変換loss、capacity overflow、maintenance、movement、repair、birth overhead等も既存方針通りenergy_outへ閉じる。

`system_energy()` は少なくとも:

```text
organism Energy
+ corpse recoverable Energy
+ H2 energy-equivalent
```

を含む。

lightはflow型のため既存ledger方針を維持する。

# 13. initial placement

V1.9 baselineの初期個体は**世界全体へuniform random spawn**とする。

H2濃度依存spawn、vent座標注入、source-biased initializationは行わない。

理由:

- H2 diffusionで自然なhalo/勾配を作る
- temporal sensing / chemotaxisが資源探索に本当に機能するか検証可能にする
- 初期配置で正解habitatを人間が与えない

既存 `diagnostic_placement="vent"` は診断用に残してよいが、baselineでは使わない。

initial_energyは当面既存referenceを維持し、source位置を知らせる補正は加えない。

# 14. structural innovation

通常の量的変異と、新能力の起源を分離する。

分類:

```text
continuous:
  body_size, storage_capacity, starvation_horizon,
  reproduction_horizon 等

innovation-gated:
  phototrophy

locked in V1.9:
  predation
```

## 14.1 phototrophy

初期:

```text
PHOTOTROPHY = OFF
light_absorption = 0
```

通常continuous mutationではOFFからONにならない。

出生時にfitness/environmentと独立したstructural innovation eventを判定する。

Config implementation reference:

```text
phototrophy_innovation_prob = 1e-4  # per birth, coarse-grained structural event
phototrophy_seed_absorption = 0.01
phototrophy_loss_prob       = 1e-3  # per birth, capability loss event
```

これらは現実の分子突然変異率を主張する値ではない。formal experiment前に別途扱う。

OFF -> innovation発生時:

```text
PHOTOTROPHY = ON
light_absorption = max(light_absorption, phototrophy_seed_absorption)
```

ON後は `light_absorption` が通常のcontinuous mutationで量的進化する。

loss event:

```text
PHOTOTROPHY = OFF
light_absorption = 0
```

phototrophyがONなら、既存organ upkeep式の `light_absorption` costがそのまま維持costとして効くため、光利用を無料能力にしない。

## 14.2 predation

V1.9では:

```text
PREDATION = OFF
predation_efficiency = 0
```

structural innovation handlerをまだ実装しない、または常にdisabledとする。
continuous mutationの加算項で正値になってもgateがOFFなので機能させない。

将来、前提能力を定義できるversionで解禁する。

## 14.3 RNG / determinism

各出生でstructural innovation/loss用RNGを固定順序で消費する。
capability状態によって乱数消費数を変えないこと。

これにより同seed determinismと診断比較を守る。

# 15. continuous mutation

既存の乗算変異 + 加算項はcontinuous genesで維持する。

ただしcapability-gated geneについては:

```text
PHOTOTROPHY OFF -> mutation後もLIGHT_ABS=0へ正規化
PREDATION OFF   -> mutation後もPREDATION=0へ正規化
```

`GENE_SCALE`を全遺伝子一律に大きくしてinnovationを起こそうとしてはいけない。
能力起源はstructural innovationで扱う。

fixed_genes診断機構との互換性を保つ。
必要ならcapability固定用の診断機構を別に追加するが、baseline進化ロジックへ観測情報を戻さない。

# 16. day/nightの扱い

V1.8 day/night mechanismは残す。

初期iLUCAはPHOTOTROPHY OFFなので、day/nightは初期Energy routeへ直接影響しない。
phototrophyが創発した後にのみ:

```text
昼 -> light routeから追加Energy
夜 -> light routeは消失
```

という自然な周期圧になる。

個体は時刻・日没・周期長を参照しない。
`starvation_horizon` が環境圧により進化するかは、将来の実験readoutであり、人間が夜長へ合わせて設定しない。

# 21. HARD RULES

- 適応度関数を直接置かない
- 特定生態型への固定bonusを置かない
- 環境を「生存するように」後付けで緩めない
- 日没/未来収入を予測させない
- storage/starvation/reproduction geneへ無償の一方向利益を作らない
- innovation eventはfitnessや環境を見ない
- phototrophyを出したいからinnovation probabilityを自動調整しない
- predationを通常加算変異だけで復活させない
- Energy/Matter保存則を破らない
- Recorderを進化へ戻さない
- 同seed決定性を守る
- fixed ancestor sanityとevolution-ON sanityを分離する
