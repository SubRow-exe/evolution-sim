## 1. 候補格子の検算 — 格子は妥当。ただし `p_high` は空振りする見込み

Exp11の実表現型（B1/B2は `organ_upkeep` に効く5能力の和 = 3.05、B3は 2.75）で、
`INITIAL_GENOME`・健全度 φ=1・wander速度のもと、**競争制限下の効率最適サイズ**
＝ `total_maintenance / M^(2/3)` の最小点 `M*` を計算した。

`M*` は「単位交換能力あたりの維持費が最小になる身体量」であり、資源が飽和して
個体間競争が効く状況で有利になるサイズの一次近似である。適応度計算ではない。

| 0.005 | 0.400 | 0.429 | ×1.020 |
| 0.010 | 0.448 | 0.480 | ×1.041 |
| 0.015 | 0.496 | 0.532 | ×1.061 |
| 0.020 | 0.545 | 0.585 | ×1.081 |
| 0.025 | 0.595 | 0.639 | ×1.102 |

| 0.050 | 0.854 | 0.921 | ×1.203 |
| 0.060 | 0.963 | 1.039 | ×1.244 |
| 0.075 | 1.131 | 1.222 | ×1.305 |

読み取れること:

- **候補格子は転換域をよく覆っている。** 動きの中心は `C_core ∈ [0.03, 0.10]` で、
  そこに 0.040 / 0.050 / 0.060 / 0.075 / 0.100 の5点がある。低値密・高値疎という配分も正しい。
  計画 §3.1 の「狭い候補範囲を先に決めるのは危険」という判断は支持する
- **`p_high < 0.25` のvetoはほぼ作動しない見込み。** 法定上限 `C_core=0.3` ですら
  `M*≈4.3`（B1表現型）で、閾値9.5には届かない。さらに §3-3 のr選択が下方向へ効くので
  実測はもっと小さくなるはず
- したがって仕様案 §4.1 の「強すぎると `body_size=10` 側への張り付きが起こりうる」という
  懸念は、実係数では**現実味が薄い**

> 条件として `p_high` を残すのは安全なので構わない。ただし
> **「p_high を通った」ことを大型化が起きない証拠として解釈しないこと**を
> 計画へ明記すべき。ほぼ確実に通るので、通過は情報を持たない。

なお仕様案 §3 の3つの主張（`sense_upkeep` は身体量非依存 / `birth_overhead` は固定費 /
random walk時の移動費は概ね身体量非依存）は現行実装で確認した。とくに移動費は
`v_wander = 0.6 · speed_coef · power / √M` を `move = move_cost · M · v² / eff` へ入れると
`M` が厳密に消えるので、主張どおり厳密にサイズ非依存である。

## 2. 実行前に埋めるべき穴（要修正）

### 2-1. POP_HALT run の指標が未定義 ★最優先

計画 §13 は「late-window mean（8,000–10,000 tick）」「6,000–8,000 vs 8,000–10,000 の
late drift」を要求し、§15 は「**final** `p_low < 0.25`」をGreen条件にしている。
一方 §14 はPOP_HALTを正当な科学的結果として扱う。

**tick 3,000でhaltしたrunの "final" と "late window" が定義されていない。**
`Recorder.finalize()` は中断時にも最終statsとsnapshotを残すのでデータ自体は出るが、
tickが揃わない。ここを決めずに走らせると、結果を見てから定義を決めることになる。

対応案: 事前登録へ「halt runの final = `finalize` が書いた最終snapshot」
「late-windowは halt tick 直前の N tick」等を明記する。

### 2-2. `C_core=0` 対照の妥当性チェックが無い ★重要

計画全体が「`C_core=0` なら `body_size` が0.2付近へ崩壊する」を前提にしている。
**これは未検証である。**

- exploratory 旧B1: **12遺伝子が自由進化**（`docs/Exp10_結果考察.md` §該当節）
- Exp11 B1: **body_size 1遺伝子のみ自由**。`movement_power` / `repair_rate` /
  `reproduction_investment` 等は共進化できない

`C_core=0` で崩壊が再現しなければ、除去すべき信号自体が存在せず
「最小 `C_core`」の選定規則が無意味になる。240 runを投じてから気付くのは高すぎる。

対応案: **「B1の `C_core=0` が `p_low ≥ 0.5` を過半seedで満たさなければ
NO SELECTION / REVIEW」**という対照妥当性条件を事前登録へ入れる。
これは結果を見た後付け変更ではなく、事前に置く条件なので絶対原則13に抵触しない。

### 2-3. 「最初に通る最小 `C_core`」は seed 8 に対して統計的に脆い ★重要

8 seedで「≥7/8」は非常にきつい閾値である。真のseed成功率が0.9でも
P(≥7/8) = 0.81、0.8なら P = 0.50。これを15候補に対して**最初の通過点**という
順序統計量で拾うと、**真の転換点より下の候補がまぐれで通る方向に系統的に偏る**。

対応案: **選定規則を「その候補**および**それより大きい全候補が通る最小 `C_core`」
（単調性要求）へ変更する。** 15候補は結果に関係なく全部走らせるので
**追加計算ゼロ**で、単発のまぐれ通過を除去できる。
本レビューで最も費用対効果が高い修正。

### 2-4. B2/B3 の 4 seed veto は判定能力がほぼ無い ★重要

Exp10正式実測（`experiments/exp10_phaseB_20260901/NOTES.md` の主要実測値表）では
B2 chem-onlyの最終pop中央値は **control 16 / treatment 68**、controlは **2/20絶滅**。

`C_core` を上げると平衡個体数はさらに下がる。vent供給は
`chem_vent_flux 16 × n_vents 4 = 64 E/tick` で固定なので、平衡個体数の上限は
おおよそ `64 / 個体あたり維持費`。`C_core=0.2` 相当（`M*≈2.75`、維持費≈1.6/tick）なら
40個体程度になる。

つまり **B2の絶滅は「生態破綻」ではなく人口統計的ノイズで起きる**。
4 seed・閾値「EXTINCT ≤ 1/4」では1 seedの絶滅で候補がvetoされ、選定が上振れする。
しかもベースライン（同条件の `C_core=0`）と比較せず絶対閾値で判定している。

対応案（どちらか）:
1. B2/B3のseedを増やす。256枠に収めるなら候補を14へ減らす等のトレードオフが要る
   （0.200 は 0.150 と 0.300 に挟まれており情報量が小さい）
2. 少なくとも **vetoを「同一条件の `C_core=0` に対する悪化」として定義**する。
   `C_core=0` は格子内にあるので内部ベースラインとして使える

### 2-5. 平衡到達（stationarity）が Green の条件に入っていない ★重要

`C_core` が大きいほど個体数が減り、世代交代が遅くなる。極端には、
**10,000 tickで body_size がほぼ初期値1.0から動かないだけで `p_low` も `p_high` も
余裕で通過する**。「進化が遅くて動かなかった」と「内部に平衡がある」が区別できない。

§13 に late drift は指標としてあるが、**Greenの必須条件になっていない**のが問題。

対応案: `stats.csv` には既に `max_generation` がある（`evosim/recorder.py`）。
追加実装なしで「到達世代数」と「late driftが閾値以下」を事前登録の必須条件へ入れられる。

### 2-6. `exp11.yml` を default branch へ置く前提が書かれていない

Exp10 は `exp10.yml` が main に無く `workflow_dispatch` が404で起動不能になった。
Exp11計画にこの運用前提の記述がない。

対応案: §4「実行前提」へ「`exp11.yml` と45 Configを main へマージ済みであること」を明記する。

## 3. 設計上の論点（人間判断向け）

### 3-1. この式は「小型に床を足す」だけでなく「大型のBMRを下げる」両面変更である

`M=1` ピボットを守る代償として、大型側はV1.6より**安くなる**:

```text
maint(M=10)   C_core=0 → 2.553      C_core=0.3 → 1.166   (約 -54%)
```

仕様案 §4.1 は「大型化ボーナスを別に追加したものではない」と書いているが、
V1.6との差分としては**明確に大型優遇**である。絶対原則9（原則1軸ずつ）を厳密に適用すると、
純加算形

```text
BMR = C_core + bmr_coef * M^0.75
```

は「小型の床だけ」を足す1方向変更で、`C_core=0` 完全一致も保ち、
`C_core <= bmr_coef` という制約も不要になる（代わりに `M=1` 不変性を失う）。

どちらも妥当な設計である。ただし **「再配分形を選び、加算形を捨てた」ことと理由を
仕様案へ明記すべき**。現状は加算形が検討された形跡がなく、後から
「なぜ大型が有利になる形にしたのか」を再構成できない。

### 3-2. 「M=1 で BMR 不変」は1点の不変性にすぎない

実際の個体のmatterは `[0.8, 1.2] × body_size` を動く
（`repro_matter_frac = 0.8` / `matter_cap_frac = 1.2`）。しかも
**`initial_matter = 0.8` は body_size に依らない絶対値**である。

つまり **t=0 の全個体は M=0.8 にいて、`C_core > 0` のあらゆる条件で必ずBMRが増える**:

```text
BMR(M=0.8):  C_core=0 → 0.2538      C_core=0.3 → 0.3000   (+18%)
```

これは初期絶滅リスクをサイズ選択と無関係に押し上げる交絡になりうる。

対応案: Phase A A1 の M 系列へ **0.8 を必ず含める**。
また §8 の共通条件へ `initial_matter` を明記する（現在は未記載）。

### 3-3. Phase A が静的すぎる — 実際の選択圧は r であって効率ではない

Phase A A1 は maintenance landscape（エネルギー効率の視点）だけだが、
小型化を駆動しているのは主に**増殖速度**である。

- 繁殖閾値 `E >= repro_energy_frac * E_max = 60M`、収入 ∝ `M^(2/3)`
  → **世代時間 ∝ M^(1/3)**。M=0.2 は M=1 の約0.58倍、つまり約1.7倍速い
- `v_max = speed_coef * power / sqrt(M) * phi` → **小型ほど速く動く**。
  M=0.2 の wander速度は M=1 の約2.24倍。移動*コスト*はサイズ非依存（§1参照）なので、
  **速度優位だけが残る**

`C_core` はこのどちらにも直接は効かない。効率最適 `M* = 0.354`（`C_core=0`、B1表現型）に対し
exploratory実測が 0.226 とさらに下だったのは、これで説明が付く可能性が高い。

対応案: **Phase A に A3 として「決定論的1個体ライフサイクル計算
（競争なし・固定収入・intake一定）による初回繁殖までのtickと r(M)」を追加する。**
世界シミュレーション不要で安く、`C_core` ごとの転換点をPhase Bの前に定量予測できる。
A1 の表にも `v_wander` と世代時間の列を足す。

これは「候補を削る」ためではなく（§6の方針どおり削ってはいけない）、
Phase B の結果を解釈するための予測を事前に固定するためである。

### 3-4. Matter 制限の可能性 — `C_core` は Energy 側しか触らない

総Matterは3280（`nutrient_initial 2.0 × 1,600セル = 3,200` + 初期個体 `100 × 0.8 = 80`）。
exploratory の 6,500個体 × body_size 0.226 は
**約1,470 M ≈ 全Matterの45%が体内に固定**されていた計算になる。

この領域では平衡が **Energy制限ではなくMatter制限**で決まっている可能性があり、
その場合 `C_core`（Energyコスト）の効きは鈍る。

対応案: §13 の指標へ **「自由 nutrient プール総量」と「体内Matter / 総Matter比」の
時系列**を追加する。`C_core` を上げてもサイズが動かない場合、この2指標が原因を切り分ける。
環境snapshotに nutrient場が入っているので追加実装は最小で済む。

### 3-5. POP_HALT と `p_low` は独立な証拠ではない

Matter保存下では `population ≈ 利用可能Matter / 平均matter` なので、
POP_HALT は平均サイズのほぼ決定論的な関数である。
§15 で「POP_HALT ≤ 1/8」と「`p_low < 0.25`」を並べると**同じ信号を二重計上**することになる。

判定を無効化するほどではないが、考察でこれを独立な2つの証拠として扱わないよう
§14 へ注記すべき。

## 6. 付録 — §1 の検算スクリプト

現行 `evosim/physiology.py` の `maintenance_and_movement` と `evosim/genome.py` の
`INITIAL_GENOME`、および Exp11 計画 §9–§11 の表現型固定値から起こしたもの。
`C_core` の項だけを V1.7 候補式へ差し替えてある。リポジトリには追加していない。

```python
import numpy as np

SENS, MEM, DR, POWER, EFF = 0.4, 0.5, 0.5, 0.5, 1.0   # INITIAL_GENOME

def maint(M, C, organ_sum, coef=0.3):
    bmr   = C + (coef - C) * M ** 0.75                  # V1.7候補式
    organ = 0.05 * M * organ_sum                        # organ_upkeep
    sense = 0.02 * SENS ** 2                            # sense_upkeep
    memb  = 0.03 * MEM * M ** 0.5                       # membrane_upkeep
    res   = 0.02 * DR * M                               # resist_upkeep
    v     = 0.6 * 3.0 * POWER / np.sqrt(M)              # wander速度 (phi=1)
    move  = 0.05 * M * v * v / EFF                      # move_cost
    return bmr + organ + sense + memb + res + move

cands = [0.0, 0.005, 0.010, 0.015, 0.020, 0.025, 0.030, 0.040,
         0.050, 0.060, 0.075, 0.100, 0.150, 0.200, 0.300]
Ms = np.linspace(0.2, 10.0, 40000)

# organ_sum = light_abs + chem_abs + nutrient_abs + predation + corpse_dig
# B1/B2 specialist: 2.0 + 0.3 + 0.5 + 0.05 + 0.2 = 3.05
# B3 generalist   : 1.0 + 1.0 + 0.5 + 0.05 + 0.2 = 2.75
for name, osum in [("B1/B2", 3.05), ("B3", 2.75)]:
    for C in cands:
```
