# V1.7 総括 — 基礎維持代謝 `bmr_core`

更新: 2026-09-03
状態: **科学判断完了 / `bmr_core=0.15` 採用 / default反映とv1.7-final保存を残す**

---

## 1. V1.7の目的

V1.6までの世界では、body_sizeが小さいほど維持費・繁殖必要量などで有利になり、light-only環境でbody_sizeが下限付近へ強く張り付いた。

V1.7ではbody_sizeへ直接penaltyを与えず、全生命に共通する縮小不能な基礎維持代謝を導入した。

```text
BMR = bmr_core + (bmr_coef - bmr_core) * M^0.75
bmr_coef = 0.3
0 <= bmr_core <= 0.3
```

狙いは特定サイズを作ることではなく、**極端な小型化が無条件に有利になる構造を弱められるか**を確認すること。

---

## 2. Exp11 — 広い候補探索

Exp11は15水準の`bmr_core`を3環境で10,000 tick評価した。

正式255 runは全て技術的に完了したが、事前登録判定は:

```text
SCIENTIFIC_VERDICT = NO_SELECTION / REVIEW
reason = CONTROL_NOT_REPRODUCED
```

となった。

重要な事後解釈:
- `bmr_core >= 0.10`では小型化抑制方向の効果自体は見えた
- しかし10k時点でbody_sizeはまだ大きく動いており、stationarity条件を満たさなかった
- 対照`bmr_core=0`も下限直前まで縮小していたが、事前閾値をわずかに外れた
- したがって「bmr_coreに効果がない」のではなく、**10kでは長期平衡を判定するには短かった**

Exp11から直接恒久値を選ばず、Exp12へ延長した判断は妥当だった。

技術面では以下の事故と再発防止を得た。
- fixed_genesの誤名/欠落 → canonical `GENE_NAMES`から導出
- snapshot形式誤認 → 実Recorder出力を使うE2E回帰test
- artifact大量取得欠落 → 完全性checkerと`gh run download`系運用
- 科学STOPと集計/技術FAILを分離

## 3. Exp12 — 50kで平衡変更か遅延かを確認

B1 = light-only / light specialist / body_sizeのみ進化。

50k後半の代表値:

| bmr_core | body_size中央値 | 8 seed分類 |
|---:|---:|---|
| 0.000 | 0.2088 | lower-bound 8/8 |
| 0.050 | 0.2138 | lower-bound 8/8 |
| 0.075 | 0.2176 | lower-bound 8/8 |
| 0.100 | 0.2238 | lower-bound 8/8 |
| 0.150 | 0.2459 | interior 8/8 |
| 0.200 | 0.3021 | interior 7/8 + converging 1 |
| 0.300 | 0.4142 | interior 6/8 + converging 2 |

B1で`DELAY_CONTINUES`は0 run。

tick-spaceだけでなくgeneration-spaceでも、`bmr_core>=0.15`は単なる世代交代遅延だけでは説明しにくく、長期body_size平衡を内部側へ動かしていると判断した。

### Exp11との違い

10k時点の高bmr条件は50k平衡よりかなり大型に見えていた。

したがって:
- Exp11の効果方向は有用だった
- Exp11の効果量は過大だった
- 長期runで確認したことに意味があった

## 4. Exp12 B2 method control

B2 = chemical-only / chemical specialist。

事前登録ではB2を「既知のstationary positive control」と仮定したが、50kまで延長するとB2自身が10k以降も大きく変化していた。

事前登録機械判定は:

```text
SCIENTIFIC_VERDICT = INVALID_OR_METHOD_REVIEW
reason = B2 method-control gate未達
```

である。この履歴は消さない。

一方、人間判断は:

```text
METHOD CONTROL ASSUMPTION INVALID
```

とする。

すなわち:
- classifierがstationaryを誤って拒否したのではない
- B2をstationaryとみなした前提が誤っていた
- B2科学run自体を「失敗」としない
- V1.7の目的のためにB2を100k等へ延長する追加実験は不要

今後method classifierの正当性は合成軌跡unit testで検証し、自然runを既知stationaryと仮定しない。

## 5. V1.7最終値

恒久採用:

```text
bmr_core = 0.15
```

理由:
1. 事前に決めた候補格子の中で、下限張り付きを解除した最小側
2. B1 8/8 seedで内部平衡分類
3. 0.20/0.30ほど大型側へ強く動かさない
4. 特定body_sizeへ合わせた事後調整ではない

注意:
- 0.15は自然界の普遍定数ではない
- 0.10の50k中央値0.2238と0.23 sentinelの差は0.0062であり、0.15は「物理的相転移点」ではなく**事前sentinelを最初に超えた試験格子点**
- V1.8以降で新しい選択圧が入ればbody_size平衡は再確認しうる

## 6. V1.7で得た一般的な教訓

1. **tick数と判定閾値の到達可能性を事前検算する**
2. 10k等の中間状態を平衡と決めつけない
3. tick-spaceだけでなくgeneration-spaceも使う
4. method controlの「正解」は自然runへ仮定せず、合成データtestを優先する
5. 技術FAILと科学的STOP/REVIEWを分離する
6. 生成器・checker・testが同じ誤定数を共有しない独立オラクルを持つ
7. artifact完全性を機械検証する
8. Hosted Runnerを跨ぐbit一致をHARD GATEにしない
9. single-run時間とmatrix全体wall-clockを分けて見積もる

へ分化する。
