## 1. 目的

V1.8ではlightとchemicalを「同じEnergyの別field」として扱うだけでなく、一次Energy源として異なる生態的性質を持たせる。

狙う構造:

```text
light
- 空間的に広い
- renewable flow
- 1地点・1tickの利用可能fluxは比較的薄い
- 昼夜で周期的に0になる
- 一日の平均供給は静的世界より低くなり得る
- 受光面積と局所光強度に依存
- 使わなかったlightはstockとして残らない

chemical
- vent近傍へ局在
- 局所stock
- 見つければ高い局所Energy取得速度を持ち得る
- 個体が使うとstockが減る
- 同じstockを個体間で奪い合う
- geological sourceから再供給する
- stockが薄くなれば吸収速度も低下する
```

**「light型を弱くする」「chemical型を強くする」という直接適応度補正は入れない。**

環境場・時間構造・濃度依存吸収・既存生理コストから結果を生じさせる。

# 4. day/night cycle

`World.light`は**昼のbase/peak空間field**として保持する。破壊的に毎tick書き換えない。

そのtickで利用可能なlight:

```text
F_light(ix, iy, tick) = World.light[ix, iy] * daylight_factor(tick)
```

### 4.1 cycle shape

half-sine固定:

```text
phase = (tick mod period) / period

if phase < day_fraction:
    u = phase / day_fraction
    daylight_factor = sin(pi * u)
else:
    daylight_factor = 0
```

period=200 / day_fraction=0.5では:
- 100 tick daylight
- 100 tick night
- sunrise = 0
- midday = 1
- sunset = 0
- night = exactly 0

### 4.2 energy中立化しない

重要な人間判断:

**daylight factorを平均1へ正規化しない。**

half-sine / day_fraction=0.5 の一周期平均factorは約0.318。したがって同一`light_max`ならV1.7静的世界より一周期総lightは少なくなる。

これは意図した性質:

> 光は広く供給されるが夜があり、平均的には薄い。

昼を3.14倍して旧worldと一日総量を一致させる処理は入れない。

`light_max`自体をExp13で広くsweepしてworking referenceを選ぶ。

### 4.3 tick基準

`daylight_factor`は1 simulation stepにつき一度、**step開始時のcurrent tick**から決め、そのstep中の:
- sensing
- light supply
- light uptake
- recorderのcycle factor

で同一値を使う。処理途中にtickを進めて別factorを読む実装は禁止。

`light_cycle_enabled=False`では常時1.0とし、feature OFF時V1.7回帰を守る。

# 5. 局所密度依存の一次Energy吸収

V1.4以降の有効表面積:

```text
A_eff = matter^(2/3)
```

と、同一cell内の需要比例公平配分は維持する。

共通response:

```text
H(x,K) = x / (x + K)
```

性質:
- x=0 -> 0
- x=K -> 0.5
- x増加で単調増加
- 高濃度で1へ飽和

V1.5の**知覚用**`*_stimulus_half`とは別物。流用しない。

`primary_energy_density_response=False`ならV1.7吸収式へ完全回帰する。

このresponseはlight/chemicalの直接一次Energy吸収だけへ適用する。

**nutrient / corpse / predationへ適用しない。**

---

# 6. light吸収

そのtickのcell light flux:

```text
I = World.light[ix,iy] * daylight_factor
```

feature ON時の個体i要求量:

```text
raw_i = light_uptake_coef
        * light_absorption_i
        * A_eff_i
        * phi_i
        * H(I, light_uptake_half)
```

Energy容量残りでcapし、その後cell supply `I`へ需要比例配分する。

必須不変条件:

```text
sum(light_gain_i in cell) <= I
```

lightはstockとして減算しない。

night `I=0`ではgainは厳密0。

`light_uptake_half=0.6`は現行light scaleに対する初期設定としてExp13では固定する。V1.8の主校正軸は`light_max`とし、halfまで同時に多軸sweepしない。

---

# 7. chemical吸収

cell chemical stock:

```text
C = world.chemical[ix,iy]
```

feature ON時の個体i要求量:

```text
raw_i = chem_uptake
        * chemical_absorption_i
        * A_eff_i
        * phi_i
        * H(C, chemical_uptake_half)
```

Energy容量残りでcapし、その後stock `C`へ需要比例配分する。

```text
sum(chemical_gain_i) <= C
world.chemical[cell] -= sum(chemical_gain_i)
```

既存地質source/loss:

```text
loss = chem_loss_frac * stock
stock = stock - loss + chem_source_flux
```

は変更しない。

### 7.1 `chemical_uptake_half`はExp13で選ぶ

旧暫定値6.15は「生物不在標準vent平衡stock約12.3の半分」から置いた値であり、生物占有時の実stock帯より高すぎる可能性がある。

Exp13候補:

```text
chemical_uptake_half = 0.5, 1.5, 3.0, 6.15
chem_uptake          = 0.5, 1.0, 2.0, 4.0
```

実際のoccupied ventでの:
- stock
- `H(C,K)`分布
- Energy gain
- depletion/recovery
- population

からworking referenceを選ぶ。

half値が実運転点に対し:
- ほぼ常時H<0.05
- ほぼ常時H>0.95

となる組合せは「responseの飽和形を実際には使えていない」と診断する。

# 8. sensing / behavior

V1.6 temporal sensingは維持する。

light sensingはそのtickの**effective light**を読む。

```text
night -> R_light = 0
```

chemical sensingはcurrent stockを読む。nightでもchemicalは利用可能。

変更しない:
- `light_stimulus_half=1.2`
- `chemical_stimulus_half=12.3`
- memory_tau=10
- response_gain=64
- random walk / temporal response式

V1.8でlight userだけmovementを強制抑制しない。

# 9. Energy ledger / observation

昼夜導入後は静的light供給×tickで`light_supply_cum`を計算してはいけない。

毎stepの**effective world light supply**を積算する。

追加/明確化:

```text
light_cycle_factor
light_supply_rate
light_supply_cum = actual effective external supply integral
flow_light_cum  = organismsが実際に吸収したlight Energy
```

night supplyは0。

`World.light` static snapshotは「base/peak habitat field」として保存。

既存`mean_local_light`等の意味を黙って変えない。必要なら新列を追加し、観測機能がRNG・simulation stateへ影響しないことをtestする。

V1.7以前の`light_supply_cum`と意味が変わる場合、バージョン境界を明記し、過去値と無条件に直比較しない。

# 10. feature flagsの独立性

Phase 0で以下4組合せを短時間実Simulationで確認する。

```text
density OFF / cycle OFF  -> V1.7回帰
density ON  / cycle OFF  -> density response単独
density OFF / cycle ON   -> day/night単独
density ON  / cycle ON   -> V1.8 combined
```

目的:
- 2機構が独立にON/OFF可能
- OFF/OFFがV1.7へ完全回帰
- one-featureだけのpathに実装漏れがない

正式Exp13は原則density ON + 必要条件でcycle ONを使う。
