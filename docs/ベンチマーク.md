# 計算性能ベンチマーク

更新: 2026-08-29

将来のクラウド計算環境の選定に向けて、**同一条件で環境間の性能を比較する**ための仕組み。
ローカルPC / GitHub Codespaces / クラウド計算環境で同じコマンドを実行し、
出力JSONを突き合わせる。

## 使い方

```bash
uv run python tools/benchmark.py                    # 標準 (約3〜5分)
uv run python tools/benchmark.py --quick            # 短縮 (約40秒。疎通確認用)
uv run python tools/benchmark.py --full \
    --scaling 1,2,4,8,16 \
    --label codespaces-4core \
    --out benchmarks/codespaces_4core.json          # 環境比較用の完全版
uv run python tools/benchmark.py --compare benchmarks/*.json   # 保存済みを比較
```

`--label` に環境名を付け、`benchmarks/` へJSONを保存して比較する。

## 測定していること

**既存コードは一切変更していない。** `evosim` を import して使うだけなので、
シミュレーション結果への影響はない。

### 単一プロセス性能

描画・記録I/Oを除いた純粋な計算性能。3シナリオ。

| シナリオ | 条件 | 目的 |
|---|---|---|
| light | 既定Config、seed 1、warmup 300 | 低密度 (個体数約200) |
| standard | 既定Config、seed 1、warmup 5,000 | 通常運用域 (約360) |
| dense | `initial_population=3000`、seed 11、warmup 200 | 高密度 (約1,900) |

個体数は世代とともに増えるため、「初期個体数 + ウォームアップtick数」を固定して
測定時点の個体数を決定的にしている (結果に個体数を併記)。

取得値: 総実行時間 / ms per step (平均・中央値・p95) / step per second /
CPU使用コア数 / 最大RSS。

### 環境情報

OS / CPU型番 / 物理・論理コア数 / 利用可能コア数 / cgroup CPU制限 (コンテナ用) /
メモリ / Python版 / NumPy版。

Codespaces等のコンテナでは `os.cpu_count()` が実際の割当と一致しないため、
`sched_getaffinity` と cgroup の制限値も取る。

### 付随項目 (`--full`)

- **処理フェーズ内訳**: cProfile を行動判断・接触判定・生理・環境更新などへ集約
- **記録I/Oの影響**: Recorder 有効時との速度差
- **描画コスト**: SDLのダミードライバで画面なしに1フレームの時間を測る
- **並列スケーリング**: 同一負荷をNプロセス同時実行し総スループットの伸びを測る
  (プロセス起動時間を含む「実測」と、除いた「計算のみ」の両方)

## 基準値: ローカルPC (2026-08-29)

Intel Core i7-14700F (物理20 / 論理28、P-core 8 + E-core 12)、Windows 11、
Python 3.12.11、NumPy 2.5.2

## 注意

- ベンチマーク結果は**数値実行環境に依存する速度の話**であり、
  シミュレーション結果 (再現性) とは別問題。結果の同一性は
  `tools/golden.py` / `tools/verify_vs_ref.py` が担当する
- クラウドの共有vCPUはノイジーネイバーの影響を受ける。
  同一環境で複数回実行してばらつきを確認すること
- 測定中は他の重いプロセスを動かさないこと
