## 1. V1.4へ上げる理由

V1.3ではchemical環境側の供給則を修正した。Exp07により、完成chemical利用型は新しい地質sourceモデルで長期生存できることを確認した。

その後のコード監査で、生物側に以下の非対称を確認した。

- 光: `light_absorption × matter × health` は主にセル光量の分配比率で、単独個体なら低能力でもセル光をほぼ全取得する
- chemical: `chem_uptake × chemical_absorption × matter × health` で個体ごとの吸収上限がある
- chemicalはstock不足時に個体リスト順で先着有利
- light/chemical/nutrientの直接吸収が概ねmatter（体積）比例
- 光は移動前セル、chemical/nutrientは移動後セルを参照していた

これは世界ルールに関わる設計修正なので **V1.3 → V1.4** とする。

V1.4の目的は光を人工的に弱体化することではない。

> 環境フィールドから直接取り込むEnergy/Matterを、身体と環境の接触面・個体能力・利用可能資源から決まる統一的な吸収則へ変更する。

特定の生態型へ直接ボーナスを与えない。

## 2. 目標とする一次Energy源の性格

### 光

- 世界の広い範囲へ継続供給
- 未利用分は蓄積せずそのtickで失われる
- 個体は入射光を無制限に生体Energyへ変換できない
- 受光面と`light_absorption`が個体の変換速度を制限する

### 地質chemical

- 熱水噴出孔・冷湧水等の局所sourceから継続供給
- 局所stockとして一時蓄積
- 混合・流出・希釈・酸化等を粗視化した環境損失あり
- 生物はsourceそのものを枯渇させないが、局所stockを低下させられる
- 世界総量は光より小さくても、vent近傍では高い局所出力を取り得る

目標:

```text
光        = 広く・得やすい・個体出力は受光能力と入射量で律速
chemical  = 狭く・局所的・stock型・高い利用能力なら局所高出力を利用可能
```

動物的移動を直接促進するルールはV1.4では入れない。

## 3. 有効表面積

現行には形状遺伝子がない。第一近似として同形状の3次元物体を想定し、環境との直接交換面を:

```text
A_eff = matter^(2/3)
```

とする。

意味:
- matterを概ね体積/身体量とみなす
- matter 1 → A_eff 1
- matter 8 → A_eff 4
- 大型化すると交換面積は増えるが、身体量と同じ比例では増えない

共通helperを作り、light/chemical/nutrientで同じ計算を使う。

```python
def effective_surface(matter: float) -> float:
    return max(matter, eps) ** (2.0 / 3.0)
```

`2/3`は恒久的形状モデルではない。将来、扁平化・枝分かれ・葉状等の形状進化を入れた場合は実表面積モデルへ置換する。

## 4. 光吸収

### 4.1 旧問題

旧式:

```text
weight_i = light_absorption_i × matter_i × health_i
share_i  = cell_light × weight_i / sum(weight)
```

単独個体なら `share_i = cell_light` となり、`light_absorption`が吸収能力の上限として機能しない。

### 4.2 新式

個体の1 tickあたり最大光変換要求量:

```text
raw_light_demand_i
= light_uptake_coef
× light_absorption_i
× A_eff_i
× health_i
```

実要求量はEnergy空き容量でもcapする。

```text
light_demand_i
= min(raw_light_demand_i, E_max_i - E_i)
```

セル供給 `L`、セル内総需要 `D=sum(light_demand_i)` として:

- `D <= L`: 各個体は自身のdemandを取得、`L-D`は未利用光として消失
- `D > L`: 全個体へ同一比率 `L/D` を掛け、需要比例で配分

要件:
- 低能力の単独個体はセル光を自動的に全取得しない
- 総取得量は `min(L,D)`
- 個体リスト順を変えても各個体の状態が同じなら配分結果は同じ

### 4.3 `light_uptake_coef`

`light_uptake_coef`は世界共通の「光利用能力を実吸収速度へ変換する係数」。Configへ追加する。

実装上の暫定defaultは **2.0** とするが、恒久defaultではない。Exp08で校正する。

祖先 (`matter≈0.8`, `light_absorption≈0.3`) の静止維持費は約0.332 E/tick。`A_eff≈0.862`なので修復を無視した単純break-evenは係数≈1.29。代謝損傷修復まで含めれば実効break-evenは概ね1.4付近。

ただし初期個体は初期Energyを持ち、現行では開始時点で繁殖条件を満たし得るため、係数1.0を「即絶滅」と事前断定しない。負の収支側を含む診断条件として扱う。

Exp08でL0に用いる水準:

```text
1.0 / 1.5 / 2.0 / 3.0 / 4.0
```

- 1.0: 赤字側の負の対照候補
- 1.5: break-even近傍
- 2.0: 中央候補
- 3.0 / 4.0: 十分黒字な高吸収速度側

結果を見て同一Exp08内で追加・削除しない。

## 5. chemical吸収

V1.3の環境側source/stock/loss式は変更しない。

個体要求量のみ:

```text
raw_chemical_demand_i
= chem_uptake
× chemical_absorption_i
× A_eff_i
× health_i
```

Energy空き容量でcap:

```text
chemical_demand_i
= min(raw_chemical_demand_i, E_max_i - E_i)
```

セルstock `C`、総需要 `D` に対し:

- `D <= C`: 全員がdemand取得
- `D > C`: 全員に`C/D`を掛ける

総取得は必ず`min(C,D)`。

### 5.1 `chem_uptake`

`chem_uptake`と`light_uptake_coef`はどちらも「遺伝するabsorption能力を実吸収速度へ変換する世界共通係数」という同種のパラメータである。

ただし値を機械的に同じにしない。資源メカニズムと生理の違いを表すため別パラメータとして保持する。

Exp08では:

```text
chem_uptake = 0.5 固定
```

とし、供給量と吸収速度係数を同時変更しない。

`chemical_absorption=2`, `matter=0.8`では最大吸収は約0.86 E/tickだが、`chemical_absorption=5`なら約2.15 E/tickまで上がる。したがって現行`chem_uptake=0.5`でも高chemical能力へ進化すればV1.1明部光の約1.2 E/tickを超える潜在能力はある。

Exp08 Phase0ではlight/chemical双方について、同matter・同absorptionでの個体吸収ceilingを必ず併記する。

## 6. 無機栄養吸収

無機栄養も環境から直接取り込むMatterなので:

```text
raw_nutrient_demand_i
= nutrient_uptake
× nutrient_absorption_i
× A_eff_i
× health_i
```

とする。

ただし公平配分前に、現行仕様の以下2つでもcapする。

1. 個体がそのtickに取り込めるMatter余地
2. 同化Energyコストを現在Energyで支払える量

概念的に:

```text
nutrient_demand_i
= min(
    raw_nutrient_demand_i,
    assimilable_matter_room_i,
    affordable_matter_from_current_energy_i
)
```

その後セルstock不足時は需要比例配分する。

要件:
- どの個体も事前demandを超えて取得しない
- 総取得=`min(cell_stock, sum(demand))`
- 同化EnergyコストでEnergyを負にしない
- Matter保存を守る

既存のMatter上限・同化Energyコストの意味自体は変更しない。

## 7. 維持費は変更しない

`organ_upkeep`、基礎代謝、修復、繁殖コスト等はV1.4では変更しない。

吸収利益側を表面積則へ直すだけで身体サイズへの選択圧は変化する。維持費まで同時変更すると因果分離できない。

現状では維持費は概ねmatter比例、環境直接吸収利益はsurface比例になるため、大型化ほどsurface/volume比が悪化する。この効果をまず観察する。

## 8. tick内処理 — 最小限の再構成

フルフェーズ化は行わない。公平配分に必要な最小変更に限定する。

V1.4推奨順:

```text
1. 環境更新
2. tick開始時の刺激場を参照し、全個体が従来原理で行動決定
3. 全個体を移動
4. 移動後の空間hashを再構築
5. light / chemical / nutrient の各個体demandを計算
6. 各セルで需要比例配分
7. 以降は可能な限り現行の個体逐次処理順を維持
   corpse利用 → predation → 生理/修復 → 死亡 → 繁殖 → 記録
```

これにより:
- light/chemical/nutrientはすべて移動後位置から吸収
- chemicalの先着biasを廃止
- 光だけ移動前セルを参照する不整合を解消

副次的にcorpse/predationは「全個体移動後に再構築したhash」を参照することになる。現行と遭遇率が変わり得るため、V1.4世界境界の副作用として明記する。

死亡・繁殖まで全面フェーズ化してRNG消費順を大きく変えることは今回の目的ではない。可能な限り既存逐次順を維持する。

## 9. 行動 — 未来Energy予測は禁止

V1.4で以下は採用しない。

```text
候補セルごとに将来得られるEnergyを予測
→ 最も収益が高い場所へ移動
```

原始生物として高度すぎるため。

原則:

> 生物は現在感じる刺激へ反射的に反応する。

- 光: 現在の明るさへの走光性
- chemical: 現在の局所濃度への走化性
- nutrient: 現在の資源刺激

現行は異なる単位のraw fieldを直接比較するため、光+chemical混合世界では不適切。ただしExp08は各sourceを単独評価するため、この比較則はExp08では変更しない。

**最初の光+chemical同居実験前に**、未来収益ではなく受容器応答として無次元化する方法を別途事前登録する。

## 10. chemical供給量の候補

Exp07では`chem_vent_flux=8`でも完成chemical型は成立した。

典型13セル/ventなら:

```text
flux 8  → 約0.62 E/tick/cell
flux 16 → 約1.23 E/tick/cell
flux 24 → 約1.85 E/tick/cell
```

V1.1光は約0.36〜1.2 E/tick/cell。

設計目標「世界全体では光より少なく、vent近傍では高密度」を考えると、**16〜24 E/tick/ventを恒久default候補**とする。

ただし`matter→matter^(2/3)`はmatter<1ではchemical吸収能力を少し増やすため、Exp08でflux8が不安定になることをdefault引き上げの根拠にはしない。

16/24を候補にする理由は生存率の事後説明ではなく、**局所供給密度を光帯と同等〜それ以上に設定するという事前の設計目標**である。

Exp08 Phase Bは8/16/24で、生存・population・stock・利用率・個体吸収量を確認する。

## 11. 実装テスト要件

最低限:

1. `matter=1 → A_eff=1`, `matter=8 → A_eff=4`
2. 低`light_absorption`単独個体がセル光を全取得しない
3. light総需要<supplyなら未利用光が残る
4. light総需要>supplyなら総取得=supply
5. lightの個体順を変えても同じ配分
6. chemicalの個体順を変えても同じ配分
7. chemical総取得<=stock
8. nutrient取得は各個体demandを超えない
9. nutrient総取得=`min(stock,total demand)`
10. nutrient同化コストでEnergy非負
11. Matter保存
12. Energy台帳保存
13. 光/chemical/nutrientがすべてpost-moveセルを参照
14. density testのshuffleはSimulation本体のRNGを消費しない別RNGで行う
15. V1.3以前とは結果が異なる世界バージョン境界であることをgolden/CIに反映

V1.4では未利用光が大幅に増え、`flow_light_cum / light_supply_cum`が低下する可能性が高い。これは新吸収上限の意図した結果であり、保存則異常と誤認しない。

## 12. Exp08実装時の乱数条件

光単独Phase Aでもvent生成の乱数消費を変えないため:

```text
n_vents = 4 を維持
chem_vent_flux = 0.0
```

とする。`n_vents=0`へ変更しない。

診断用の個体順shuffleにはSimulation.rngを使わない。

配分の実装メモ:

- セルごとに全個体のdemandを先に求め、`min(1, 供給/総需要)` を全員へ掛ける。
  総需要の合算は `math.fsum` なので、個体の並び順を変えても縮小率はビット単位で同じ。
- 資源間の順序 (光 → 化学 → 無機栄養) はV1.3以前と同じ。有効表面積と健全度は
  セル処理の開始時点で一度だけ求め、3資源で共有する。
- 未利用光は台帳へ計上しない (V1.3以前と同じく、実際に得た分だけ `energy_in_cum`)。
  したがって保存則の式は変更していない。
