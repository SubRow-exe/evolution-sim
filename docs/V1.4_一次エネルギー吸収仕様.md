# V1.4 一次エネルギー吸収メカニズム再設計

更新: 2026-08-31
状態: **実装方針確定 / 実装前**

背景:
- `docs/Exp07_結果考察.md`
- `docs/V1.3_化学資源モデル仕様.md`

## 1. V1.4へ上げる理由

V1.3ではchemical環境側の供給則を修正した。

Exp07後の監査で、今度は生物側に以下の非対称があることが判明した。

```text
光:
低い light_absorption でも、セルに1匹ならセル光量をほぼ全量取得可能

chemical:
chem_uptake × chemical_absorption × matter × health
で個体吸収速度が明確に制限
```

これは単なるパラメータ変更ではなく「生物が環境Energyを取り込む基本則」の変更である。

したがって世界バージョンを **V1.3 → V1.4** とする。

V1.4の目的は光を人工的に弱体化することではない。

> 光・chemical・無機栄養など環境フィールドから直接吸収するものについて、身体と環境の接触面・個体能力・利用可能資源から吸収量が決まる統一的な物理/生理則へ変更する。

特定生態型への直接ボーナスは与えない。

## 2. 自然環境との対応

### 光

- 世界の広い範囲へ継続的に到達する
- 未利用分は蓄積せず失われる
- 生物が受けた光を全て生体Energyへ変換できるわけではない
- 個体の受光面・光利用機構が1 tick当たりの最大変換量を制限する

### 地質chemical

- 熱水噴出孔・冷湧水等の局所sourceから継続供給
- 周辺に局所stockとして一時蓄積
- 混合・流出・希釈・酸化等で失われる
- 生物はsource自体を枯渇させられないが、局所stockを低下させられる
- 世界全体では光より少なくても、vent近傍では高い局所Energy密度を持ち得る

目標とする性格:

```text
光        = 広く・得やすい・個体出力は受光能力で律速
chemical  = 狭く・局所的・stock型・完成利用型は高い局所出力を利用可能
```

動物的移動を直接促進するルールはV1.4では入れない。

## 3. 身体の「有効表面積」

現行には形状遺伝子がないため、同じ形状の3次元物体を粗視化した第一近似として:

```text
A_eff = matter^(2/3)
```

を導入する。

意味:
- `matter` は現在の身体量・概ね体積に対応
- 体積が8倍なら、同形状なら線寸法2倍・表面積4倍
- したがって環境との直接交換能力は8倍ではなく4倍程度になる

この `2/3` は恒久的な生物形状モデルではない。
将来、扁平化・枝分かれ・葉状・長細化等の形状を遺伝させる場合は、実際の表面積モデルへ置換する。

実装上は共通helperを作り、光/chemical/無機栄養で別々の式を書かない。

例:

```python
def effective_surface(matter: float) -> float:
    return max(matter, eps) ** (2.0 / 3.0)
```

## 4. 光吸収の新ルール

### 4.1 問題

旧式では:

```text
weight_i = light_absorption_i × matter_i × health_i
share_i  = cell_light × weight_i / sum(weight)
```

であり、1個体なら `light_absorption` が低くても `share = cell_light` になる。

### 4.2 新式

個体ごとに「このtickに最大何Energyを光から変換できるか」を設定する。

```text
light_demand_i
= light_uptake_coef
× light_absorption_i
× A_eff_i
× health_i
```

ここで:
- `light_uptake_coef`: 世界共通の光吸収速度係数
- `light_absorption`: 遺伝する個体能力
- `A_eff`: 有効表面積
- `health`: 現行の健全度係数

実際の要求量はEnergy空き容量でも上限する。

```text
demand_i = min(light_demand_i, E_max_i - E_i)
```

セル内で:

```text
D = sum(demand_i)
L = cell light supply
```

- `D <= L`: 各個体は自身のdemandを取得。残光は未利用で消失
- `D > L`: 全個体のdemandを同じ比率 `L/D` で縮小して配分

したがって低能力個体1匹がセル光量を全取得することはない。

### 4.3 `light_uptake_coef` の初期値

V1.4実装時にConfigへ追加するが、**恒久defaultはExp08で校正する**。

現行祖先 (`matter=0.8`, `light_absorption≈0.3`) の静止維持費は概算約0.33 E/tick。
`A_eff≈0.862` なので、光だけで維持費と釣り合う係数は概算:

```text
light_uptake_coef ≈ 1.29
```

修復・繁殖等を含めれば実効境界はこれより高い。

Exp08の候補として:

```text
1.0 / 1.5 / 2.0
```

を比較する。結果を見て恣意的に追加せず、必要なら追加実験として事前登録する。

## 5. chemical吸収のV1.4変更

V1.3の環境供給式は維持する。

変更点は生物吸収側のみ。

旧:

```text
chem_uptake × chemical_absorption × matter × health
```

新:

```text
chemical_demand_i
= chem_uptake
× chemical_absorption_i
× A_eff_i
× health_i
```

Energy空き容量で上限する。

### 5.1 個体処理順biasの廃止

旧実装は個体Aがstockから取った後に個体Bを処理するため、stock不足時にリスト順が有利不利を作る。

V1.4ではセルごとに全個体のdemandを先に計算する。

```text
D = sum(chemical_demand_i)
C = current cell stock
```

- `D <= C`: 全員がdemandを取得
- `D > C`: `C/D` を全員へ掛けて需要比例で配分

合計取得量は必ずstock以下。

個体リスト順を並べ替えても配分結果が同じであることをunit testする。

## 6. 無機栄養の直接吸収

無機栄養も環境から直接取り込む溶存/微粒子状Matterとして扱っているため、同じ原理を適用する。

旧:

```text
nutrient_uptake × nutrient_absorption × matter × health
```

新:

```text
nutrient_demand_i
= nutrient_uptake
× nutrient_absorption_i
× A_eff_i
× health_i
```

Matter上限・同化Energyコストは現行を維持する。

同一セルで栄養stockが不足する場合も需要比例配分を基本とする。

理由:
- light/chemicalだけ表面積則にし、無機栄養だけ体積比例に残すと大型化に別の人工的利得が残る
- 「環境フィールドから直接取り込む」という共通メカニズムを一本化できる

## 7. V1.4で変更しない維持費

現行の `organ_upkeep` 等はV1.4では変更しない。

直接吸収能力の利益側を表面積則へ直すだけでも身体サイズへの進化圧は変わる。
維持費まで同時変更すると、どちらが結果を動かしたか分からなくなるため。

特に現行では吸収器官を含む器官維持費が概ねmatter比例であり、吸収利益が表面積比例になると大型個体ほど交換面/身体量比が悪くなる。

これは原始的な単細胞・単純体制で自然に生じるsurface-to-volume constraintとしてまず観察する。

結果が過剰なら次版で維持費スケーリングを独立診断する。

## 8. tick内処理順の統一

光とchemicalの公平配分を実装するため、環境フィールド吸収を個体ごとの逐次処理から分離する。

推奨構造:

```text
1. 環境更新
2. tick開始時の刺激場/個体配置を参照して各個体が行動決定
3. 全個体を移動
4. 移動後の空間hashを再構築
5. light / chemical / nutrient のセル別demandを全個体分計算
6. 各セルで需要比例配分
7. corpse / predation 等の局所相互作用
8. 維持費・修復
9. 死亡
10. 繁殖
11. 記録
```

少なくともlightとchemicalが「片方は移動前セル、片方は移動後セル」のような異なる時点を参照しないよう統一する。

この処理順変更は結果を変えるためV1.4境界として扱う。

## 9. 行動 — 「未来のEnergy予測」はしない

V1.4で以下は採用しない:

```text
各セルで次tick何Energy取れるか計算
→ 最も期待収益が高い場所へ移動
```

理由:
- 原始的な生物として高度すぎる
- 過去傾向から未来収益を予測する知能を暗黙に導入する
- 将来の神経/学習進化の余地を潰す

基本原則:

> 生物は現在感じる刺激へ反射的に反応する。

想定:
- 光: 明るさに対する走光性
- chemical: 現在の局所濃度に対する走化性
- nutrient: 現在の資源刺激

### 9.1 現在残る問題

現行は:

```text
score = ability × raw field value
```

で光の「E/tick/セル」とchemicalの「stock E」を直接比較している。
単位が異なるため、光+chemical混合世界では不適切。

ただしExp08は各Energy sourceを単独評価するため、この異種刺激比較はExp08の主判定を妨げない。

**最初の光+chemical同居実験の前に**、未来収益ではなく受容器刺激として無次元化する方法を別途確定する。

候補は固定半飽和型の受容器応答などだが、V1.4実装時に勝手に値を確定しない。

## 10. chemicalの絶対供給量

V1.3 default `chem_vent_flux=8` はExp07で完成chemical型を成立させた。

ただし目標は:

```text
光        : 世界全体では大きな供給 / 広域 / 低〜中局所出力
chemical  : 世界全体では少量 / 局所 / 高い局所出力を取り得る
```

現行ventが約13セルの場合:

```text
chem_vent_flux=8  → 約0.62 E/tick/cell
chem_vent_flux=16 → 約1.23 E/tick/cell
chem_vent_flux=24 → 約1.85 E/tick/cell
```

V1.1光は概ね0.4-1.2 E/tick/cell。

したがって **16-24 E/tick/ventを恒久default候補**とする。
ただし光吸収則変更後の実獲得量をExp08で確認してから決める。

`chem_uptake=0.5` はExp08では固定し、chemical側の吸収速度係数まで同時に動かさない。

## 11. V1.4で直すテスト

最低限:

1. `matter=1` と `matter=8` で `A_eff` 比が1:4
2. light_absorptionが低い単独個体がセル光を全取得しない
3. 光demand合計 < supplyなら未利用光が残る
4. 光demand合計 > supplyなら総取得=supply
5. light個体リスト順を変えても同じ配分
6. chemical個体リスト順を変えても同じ配分
7. chemical総取得 <= cell stock
8. nutrient Matter保存
9. Energy台帳保存
10. V1.3以前とは結果が異なることを世界バージョン境界として明記
