- 適応度関数なしで方向性選択が発生する
- 現行世界には**小型化・高光利用化への強い選択圧**がある
- Exp03では40,000 tickまでに主判定で **13/20 seed (65%)** が selective sweep に到達した

## 2. Ver.1.1で残す必須作業

### Step 1: Exp04 — 主要遺伝子アブレーション / Issue #4

**問い**: selective sweep にどの遺伝子の可変性が必要か。

baseline比較:
- seed 1〜20
- 40,000 tick
- 主判定 `top_lineage_frac >= 0.5`
- 感度解析 0.3 / 0.5 / 0.7

固定対象:
- `body_size`
- `light_absorption`
- `reproduction_investment`
- `mutation_rate`

```bash
for G in body_size reproduction_investment mutation_rate light_absorption; do
  uv run python tools/run_batch.py --seeds 1-20 --ticks 40000 --workers 14 \
    --fix-genes $G --out runs/exp04_fix_$G
done
```

判定:
- 固定しても転移が起きる → その遺伝子は必要条件ではない
- 累積発生率がbaseline 13/20から大きく低下 → 必要条件候補
- 差が小さければ「不明」とする

### 交絡に注意: 「転移しなかった」の2つの理由を区別する

遺伝子を初期値で固定することは中立な対照ではない。変異性を奪うと同時に
適応そのものを封じる。たとえば `light_absorption` を0.3に固定すると、
転移が起きなくても

1. その遺伝子の可変性が sweep に必要だった
2. 集団が別のレジーム（小さいまま）に落ちただけ

のどちらか判別できない。

**そこで各条件で集団の成立性も併せて記録し、baselineと比較する。**

| 記録項目 | 目的 |
|---|---|
| 最終個体数 / 個体数推移 | 集団が baseline と同等に成立しているか |
| 光利用率 (`flow_light_cum` / `light_supply_cum`) | 資源を使えているか |
| 総生体量 | 物質を生体へ取り込めているか |
| 系統数 | 多様性が保たれているか |

集団が baseline 並みに成立しているのに転移だけ消えたなら (1)。
集団自体が縮小しているなら (2) の可能性が高く、必要条件の主張はできない。

### 出生率・死亡率も見る (Issue #18の結果を受けて)

Issue #18 で、支配系統は sweep のずっと前から出生率が集団平均の約1.25倍
ありながら、同等の死亡率上昇で相殺され人口が増えていなかったことが分かった。

そのため Exp04 では、遺伝子固定が**出生率と死亡率のどちらに効くか**も
`tools/analyze_trigger.py` で確認すると解像度が上がる。

### Step 2: 転移トリガー解析 / Issue #18 ✅ 一次解析完了 (2026-08-29)

**結果**: `experiments/exp03_20seeds_40k/trigger_analysis/NOTES.md`
Exp03の既存 `events.csv` を再解析。**再実行は不要だった。**

- 支配系統は sweep の6,000〜2,000 tick前から出生率が集団平均の**1.25倍**（中央値）
- しかし死亡率も同じだけ高く、**純増余地は1.02**（13 seed中11 seedで0.98〜1.13）。
  つまり繁殖優位は存在したが**人口増加へ変換されていなかった**
- 「出生率が高い系統が勝つ」という単純な図式は否定される。
  勝者は多産多死で頭を抑えられていた系統だった
- ただし sweep 直前の内訳は一様でない。死亡率が下がるseed（20: 0.62、18: 0.78）と
  出生率がさらに伸びるseed（1: 1.59、10: 1.49）がある。
  **「死亡率低下が引き金」と一言でまとめることはできない**
- 残る最大の問い: なぜ「出生増＝死亡増」の均衡が破れるのか

## 5. Ver.1.2へ移行

V1.1終了後は Issue #19 を開始する。

### 目的

生物側の能力を「多様化させるため」に調整するのではなく、**世界側の情報量・環境差を少し増やす**。

### 原則

- 抽象的な環境ペナルティを安易に置かない
- 温度・光・資源など意味のある環境量にする
- 一度に1つの環境軸だけ追加する
- V1.1 baselineモードを残す
- 同一seed・同一数値実行環境でV1.1と比較する

### 第一候補

**時間的な光変動**。

V1.1で最も強い選択圧だった光が時間変動したとき、
小型・高光利用型への収斂やselective sweepがどこまで維持されるかを見る。

次候補:
- 温度場
- 資源の空間偏在/時間変動

詳細: [Ver1.2_環境更新候補.md](Ver1.2_環境更新候補.md)
