## 2. V1.7の1軸

コード・Config名は `bmr_core` に統一する。

```text
BMR = bmr_core + (bmr_coef - bmr_core) * M^0.75
bmr_coef = 0.3
0 <= bmr_core <= 0.3
```

性質:

- `bmr_core=0` -> V1.6完全一致
- `M=1` -> BMR=0.3維持
- 小型化してもBMRが0へ消えない
- `M>1`では既存よりBMRが相対的に低くなり、大型側にもcore償却メリットが生じる

純加算式も検討したが、M=1 referenceの総BMRまで上げるため不採用。既存BMRをcore+scalableへ再解釈する再配分式を採用する。

温度、body_size上下限、繁殖、吸収、行動、捕食、新規遺伝子はV1.7では変更しない。

## 4. 選定の骨格

1. Phase 0 integrity Green
2. B1 `bmr_core=0` でsmall-size signal (`p_low>=0.50`) が5/8以上なければ `NO_SELECTION`
3. B1候補per-seed Green:
   - COMPLETE
   - `p_low<0.25`
   - `p_high<0.25`
   - same-seed baseline比で十分な `max_generation`
   - `late_drift<=0.10`
4. per-seed Green 7/8以上でB1 Green
5. **連続3候補がB1 Green**の最小側を `TRANSITION_ELIGIBLE`
6. B2/B3で `bmr_core=0` baseline viability確認
7. baseline比で重大な健康run減少または大型上限張り付きがあればveto
8. vetoされない最小 `TRANSITION_ELIGIBLE` を恒久値候補にする

平均body_size=1やpopulation最小は選定条件にしない。

候補が残らなければ式・候補・閾値を後付け変更せず `NO_SELECTION / REVIEW`。

詳細は必ず `docs/Exp11_実験計画案.md` を読む。

## 5. Actions / 実装運用

正式dispatch前に以下を**mainへマージ済み**にする。

- V1.7実装
- Exp11 45 Config
- `exp11.yml`
- checker / summarizer / tests

正式runは同一SHA・同一数値環境。途中で科学コード・Config生成則・判定ロジックを変えない。

run status:

```text
COMPLETE
EXTINCT
POP_HALT
INCOMPLETE_RESOURCE
INTEGRITY_FAIL
```

EXTINCT / POP_HALTは科学的結果。timeout等は `INCOMPLETE_RESOURCE` で、同一SHA/Configによる技術的再実行を許可する。integrity failureは正式結果として無効。

job timeoutは350分を基準とする。collectorは可能な限り完了済み結果を保持する。

## 6. 設計原則

「小型化を抑えるためだけの人工的ペナルティは入れない」は維持する。

`bmr_core` はbody_sizeへ直接罰点を与えるのではなく、LUCA-inspired参照に基づく全生命共通の一般生理則として導入する。`max_population_halt`も生態ルールではなく計算安全停止である。

Exp11が結論するのは**他13遺伝子固定下のbody_size進化**であり、全14遺伝子共進化の平衡ではない。
