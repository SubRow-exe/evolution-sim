# 1. V1.8の目的

V1.8では light / chemical を同じEnergyの別fieldとして扱う状態から離れ、異なる一次Energy源としての性質を導入した。

```text
light
- broad renewable flow
- day/nightで周期的に0
- stockとして残らない
- 局所強度依存の取得

chemical
- localized stock
- depletable / competitive
- geological sourceで再供給
- 局所stock依存の取得
```

実装した主要世界ルール:

- non-normalized half-sine day/night cycle
- effective light fluxの時間変化
- light / chemical一次Energyへの density response `H(x,K)=x/(x+K)`
- actual light supply ledger

機構実装自体は完了している。

# 4. Exp15事前レビュー / 短期probeで得た追加知見

元Exp15をformal実行する前に、正しいlight specialistで短期実走を行った。

主要な観察:

```text
cycle OFF / density OFF -> 生存・複数世代
cycle OFF / density ON  -> ほぼ同様に生存
cycle ON  / density OFF -> 約170 tick前後で絶滅
cycle ON  / density ON  -> 約170 tick前後で絶滅
```

よって、正しいlight specialist条件では少なくとも短期的にdensity responseよりday/night側の寄与が大きい。

さらに一周期平均のlight inputをcontinuous-light条件と揃えてもcycle ONでは絶滅したため、問題は単純な平均光量だけではない。

`light_max`を大幅に増やしても絶滅時刻は大きく改善せず、一方で:

- cycle period短縮
- energy capacity増加
- reproduction threshold上昇
- day fraction増加

では短期生存が改善した。

特にperiod短縮は平均光量を変えずに救済したため、**現在の代謝時間スケールに対して連続無収入時間が長い**ことが重要と判断した。

ただし、これは「夜を短くすべき」という採用判断ではない。

# 5. V1.8で判明した根本問題

コード確認により、現行iLUCAはEnergy残量が低下しても:

- 移動速度
- 非core代謝
- repair budget

等がほぼ変化せず、内部状態依存の恒常性が無い。

また環境への適応に必要な主要レバーの多くが遺伝形質ではない。

```text
夜/飢餓で活動を落とす      -> 遺伝的レバーなし
Energy storage容量           -> world constant
繁殖開始threshold             -> world constant
```

さらに近年の成立確認実験は多数の遺伝子を固定しており、主に「固定表現型が生きられるか」を見ていた。

したがってV1.8で環境parameterを追い続けると:

> 生物側に不足している恒常性・貯蔵・繁殖戦略を、夜長・光量等の環境側調整で代償する

危険がある。

これは本プロジェクトの長期目的:

> 自然に近い環境条件を置き、その中で自然に生じた進化圧から適応を創発させる

と逆向きである。
