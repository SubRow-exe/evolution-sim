# 2. V1.2 光場の確定仕様

## 2.1 Control: 既存 `vertical`

現行式を一切変更しない。

グリッド行 `j=0..gh-1`、正規化縦座標:

```python
u = (j + 0.5) / gh
frac = light_floor + (1.0 - light_floor) * (1.0 - u)
light = light_max * frac
```

既定値:
- `light_max = 1.2`
- `light_floor = 0.3`
- `gh = 40`

40行平均 `frac = 0.65`。
世界全体光供給量:

```text
40 × 40 × 1.2 × 0.65 = 1,248 E/tick
```

この挙動はV1.1 Controlとして完全維持する。

## 2.2 Treatment: `high_contrast_vertical`

### Config追加値

```python
light_hc_bright_frac: float = 0.50
light_hc_transition_frac: float = 0.30
light_hc_dark_floor: float = 0.0
```

`light_pattern` の許容値:

```text
vertical | uniform | high_contrast_vertical
```

### 数式

正規化縦座標:

```python
u = (j + 0.5) / gh  # 北0 → 南1
b = cfg.light_hc_bright_frac       # 0.50
t = cfg.light_hc_transition_frac   # 0.30
f = cfg.light_hc_dark_floor        # 0.0

if u < b:
    frac = 1.0
elif u < b + t:
    z = (u - b) / t
    frac = 1.0 - (1.0 - f) * z
else:
    frac = f

light = cfg.light_max * frac
```

### 40×40既定世界での意味

- 北側20行（50%）: `1.0 × light_max` の明部
- 次の12行（30%）: 1.0 → 0.0 の線形遷移
- 南側8行（20%）: 完全暗部 0.0

遷移部のセル中心値は概ね:

```text
0.9583, 0.8750, 0.7917, 0.7083,
0.6250, 0.5417, 0.4583, 0.3750,
0.2917, 0.2083, 0.1250, 0.0417
```

### 重要: 総光量はControlと厳密一致

既定40行では平均 `frac = 0.65` となるように設計している。

したがって:

```text
Control              = 1,248 E/tick
high_contrast_vertical = 1,248 E/tick
```

Exp05では **総光量を変えず、空間分布だけを変更する**。

### 意図

- 明部ではV1.1と同様に光利用が有効
- 暗部では `light_absorption` を上げても直接得られる光Energyは0
- 遷移帯では光利用能力の価値が連続的に変わる
- 高光利用型へ人工的な負のペナルティは追加しない
- 暗部での生存は化学・死骸・捕食・移動等、既存経路の帰結に任せる

# 3. 光場実装のコード方針

## `evosim/config.py`

追加:

```python
light_hc_bright_frac: float = 0.50
light_hc_transition_frac: float = 0.30
light_hc_dark_floor: float = 0.0
```

## `evosim/world.py`

光場生成を小さなpure helperへ分離してよい。
例:

```python
def _build_light_field(cfg: Config) -> np.ndarray:
    ...
```

要求:
- `vertical` の計算順・式を変えない
- `uniform` の挙動を変えない
- `high_contrast_vertical` は上記確定式
- 光場生成では乱数を一切使用しない
- 未知の `light_pattern` は明示的 `ValueError`

### パラメータ検証

`high_contrast_vertical` 使用時:

```text
0 <= light_hc_dark_floor <= 1
0 < light_hc_bright_frac < 1
0 < light_hc_transition_frac <= 1
light_hc_bright_frac + light_hc_transition_frac <= 1
```

違反時は `ValueError`。

# 6. 空間・行動指標

## 6.1 地理帯の固定定義

Control/Treatmentで同じ地理領域を比較するため、光強度そのものではなく **y位置で固定した3帯**を使う。

```text
North / bright-design band:      0.00 <= y/H < 0.50
Middle / transition-design band: 0.50 <= y/H < 0.80
South / dark-design band:        0.80 <= y/H <= 1.00
```

Treatmentではそれぞれ明部/遷移/暗部に対応。
Controlでも同じ面積・位置を比較できる。

### `stats.csv` 追加候補

最低限:
- `pop_north_band`
- `pop_middle_band`
- `pop_south_band`
- `frac_north_band`
- `frac_middle_band`
- `frac_south_band`
- `mean_local_light`
- `vent_cell_population`
- `vent_cell_frac`

各band面積が固定なので、必要なら後処理でcell密度を算出できる。

## 6.2 lineage空間指標

既存 `lineages.csv` の上位lineage行へ以下を追加する。

- `occupied_cells`
- `centroid_x`
- `centroid_y`
- `mean_radius_from_centroid`
- `mean_move_per_org_tick`
- `mean_local_light`
- `vent_cell_frac`
- `mean_chemical_absorption`

### occupied_cells

現在個体が占有する環境セルのunique数。

### centroid

```text
centroid_x = mean(x)
centroid_y = mean(y)
```

### 分布幅

各個体のcentroidからのユークリッド距離平均:

```text
mean_radius_from_centroid = mean(sqrt((x-cx)^2 + (y-cy)^2))
```

境界を跨ぐ周期世界ではないため通常距離でよい。

## 6.3 移動量

`behavior.decide_and_move()` は既に実移動速度/距離 `v` を返す。
この値を科学状態へ戻さず、Recorder側へ観測値として渡す。

例:

```python
v = behavior.decide_and_move(org, self)
if self.recorder:
    self.recorder.observe_move(org.lineage_id, v)
```

Recorderでstats区間ごとに:

```text
move_sum_by_lineage
move_observations_by_lineage
```

を蓄積し、

```text
mean_move_per_org_tick = move_sum / move_observations
```

として記録後リセット。

重要:
- RNGを消費しない
- orgの状態を書き換えない
- 記録OFF時の結果と完全一致する

# 7. PNG/GIF後処理

新規ツール:

```text
tools/render_spatial.py
```

例:

```bash
uv run python tools/render_spatial.py runs/<run> --background light --gif --fps 6
```

対応background:

```text
light | chemical | nutrient
```

## 入力

- `config.json`
- `meta.json`
- `snapshots/snap_*.csv`
- `environment/static.npz`
- `environment/env_*.npz`

## PNG

出力例:

```text
spatial/light/frame_00000000.png
spatial/light/frame_00001000.png
...
```

描画:
- 背景: 選択環境のheatmap
- 個体: scatter
- 色: lineage_idから**決定的に**生成した色
- 点サイズ: `matter` を反映（極端値は表示上clipしてよい）
- title: tick / population / background名
- world座標と画像の上下方向が一致すること

lineage色はPython `hash()`を使わない。
例: lineage_idから固定したHSV/colormap indexを計算する。

## GIF

PNG連番から後処理で生成。
標準:
- fps=6
- loop=true

GIF生成の失敗はシミュレーション科学結果を無効にしない。
ただしExp05成果物としては再生成して残す。

## Exp05標準成果物

全40 runについて:
- raw snapshot CSV
- environment NPZ
- light背景PNG/GIF

chemical/nutrient GIFはツールで再生成可能にするが、全runでの事前生成は必須としない。
代表runを結果レビュー時に追加生成できる。

# 10. Exp05本番前パイロット

事前固定:

```text
seed: 1,2,3
ticks: 5,000
条件: Control + high_contrast
合計: 6 run
```

確認するのは以下のみ:
- crashしない
- intended light fieldになっている
- Control/Treatmentの総光量一致
- snapshot / env NPZ / spatial CSV列が揃う
- light PNG/GIFが生成できる
- 観測ON/OFF不変性テストGreen
- 固定した本番パラメータがrun configへ保存される

### 注意

Treatmentで予想外の大量死や暗部無人化が起きても、それ自体が正しいモデル帰結なら「望む結果にするため」に光場を調整しない。

パラメータを変更してよいのは:
- 数式実装ミス
- 総光量不一致
- zone境界のoff-by-one
- 出力不備
- 明らかな仕様不一致

のみ。

生物学的に不都合な結果を理由に変更する場合は、パイロットを破棄して仕様変更として明示的に再事前登録する。
