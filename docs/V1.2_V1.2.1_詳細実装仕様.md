# 2. V1.2 光場の確定仕様

## 2.1 Control: 既存 `vertical`

現行式を一切変更しない。

```python
u = (j + 0.5) / gh
frac = light_floor + (1.0 - light_floor) * (1.0 - u)
light = light_max * frac
```

既定値:
- `light_max = 1.2`
- `light_floor = 0.3`
- `gh = 40`

40行平均 `frac = 0.65`。
世界全体光供給量:

```text
40 × 40 × 1.2 × 0.65 = 1,248 E/tick
```

この挙動はV1.1 Controlとして完全維持する。

## 2.2 Treatment: `high_contrast_vertical`

### Config追加値

```python
light_hc_bright_frac: float = 0.20
light_hc_transition_frac: float = 0.50
light_hc_dark_floor: float = 0.0
light_hc_total_scale: float = 1.0
```

`light_pattern` の許容値:

```text
vertical | uniform | high_contrast_vertical
```

### 形状

まず総量正規化前のshapeを作る。

```python
u = (j + 0.5) / gh
b = cfg.light_hc_bright_frac       # 0.20
t = cfg.light_hc_transition_frac   # 0.50
f = cfg.light_hc_dark_floor        # 0.0

if u < b:
    shape = 1.0
elif u < b + t:
    z = (u - b) / t
    shape = 1.0 - (1.0 - f) * z
else:
    shape = f
```

### 総光量の正規化

`high_contrast_vertical` はshapeを作った後、**同じConfigの `vertical` が持つ総光供給量**を基準に全セルを一様スケールする。

```python
control_total = float(vertical_field.sum())
raw = cfg.light_max * shape_field
raw_total = float(raw.sum())
target_total = control_total * cfg.light_hc_total_scale
light = raw * (target_total / raw_total)
```

要求:
- `light_hc_total_scale=1.0` ならControlと総光量を数値誤差範囲で一致させる
- 正規化でRNGを消費しない
- shape自体は総量とは独立に定義する

この設計により、将来の光量実験では**同じ勾配のまま `light_hc_total_scale` だけ変更**できる。

例:
```text
1.00 = V1.1と同じ総光量
0.75 = 総光量25%減
1.25 = 総光量25%増
```

ただしExp05では **1.00固定**。

### 40×40既定世界での意味

- 北側8行（20%）: 最大光量plateau
- 次の20行（50%）: 最大 → 0へ線形遷移
- 南側12行（30%）: 完全暗部 0

正規化前shape平均は0.45。
Control平均は0.65なので、Exp05では正規化倍率:

```text
0.65 / 0.45 = 13/9 ≈ 1.444444
```

したがってTreatmentの実効最大セル光量は:

```text
1.2 × 13/9 = 1.733333... E/tick
```

総光量は:

```text
Control   = 1,248 E/tick
Treatment = 1,248 E/tick
```

### この比率を採用する理由

50/30/20案は光100%域が世界の半分を占め、V1.1の高光利用型にとって利用可能領域が広すぎる。
一方、明部を極端に狭めると総量維持のため局所ピークが過大になり、「空間偏在」以上に極端な高光量環境を導入してしまう。

初回は:

```text
Bright plateau 20%
Transition     50%
Dark           30%
```

とし、
- 完全暗部を30%確保
- 最大光量plateauを20%まで狭める
- 50%の広い連続勾配を残す
- 実効ピーク上昇はV1.1比約44%に留める

という折衷を採用する。

### 意図

- 明部では高光利用型が依然として有利
- 暗部では `light_absorption` を上げても直接光Energyを得られない
- 遷移帯では光利用能力の価値が連続的に変わる
- 高光利用型へ人工的な負のペナルティを入れない
- 暗部での生存はchemical / corpse / predation / movement等の既存経路の帰結に任せる

# 3. コード実装方針

## `evosim/config.py`

追加:

```python
light_hc_bright_frac: float = 0.20
light_hc_transition_frac: float = 0.50
light_hc_dark_floor: float = 0.0
light_hc_total_scale: float = 1.0
```

## `evosim/world.py`

光場生成をpure helperへ分離してよい。

```python
def _build_vertical_light(cfg: Config) -> np.ndarray: ...
def _build_high_contrast_light(cfg: Config) -> np.ndarray: ...
```

要求:
- `vertical` の既存計算式・結果を変えない
- `uniform` の挙動を変えない
- high contrast生成で乱数を使わない
- 未知patternは `ValueError`
- high contrastはshape生成→総量正規化の順

### Validation

```text
0 <= light_hc_dark_floor < 1
0 < light_hc_bright_frac < 1
0 < light_hc_transition_frac <= 1
light_hc_bright_frac + light_hc_transition_frac <= 1
light_hc_total_scale > 0
```

# 11. Exp05後の光環境実験系列

V1.2は「光環境を振る」最初の系列とする。
Exp05結果後、次の世界ルール更新では一度に1軸だけ追加で変更する。

候補A: **総光量1.0を維持したまま、さらに偏在を強くする**
- bright領域をさらに狭める
- dark領域をさらに広げる
- shapeだけ変更

候補B: **Exp05のshapeを固定し、総光量だけ変更する**
- `light_hc_total_scale` を0.75 / 1.25等へ変更
- spatial shapeは同じ

まずExp05で「総量一定・強い空間偏在」の効果を観察し、その結果からAかBを選ぶ。
