## 1. 目的

Exp10 の正式結果では V1.6 temporal biased random walk が Green となった。一方、
進化OFF実装漏れで偶然得られた exploratory run では、個体が移動できるようになった
世界で `body_size` が約1.0から約0.2へ縮小し、population が約6,500まで増えた。
これは Exp10 の正式結果ではないが、現行世界に**極端な小型化への強い選択圧**が
存在する可能性と、個体数増大による計算コスト問題を示す設計上の手掛かりである。

V1.7では、小型化を禁止する下限変更やpopulation制御を入れるのではなく、
**生命1個体として存在するために縮小しきれない基礎維持代謝**を世界ルールへ追加し、
小型・大型の双方に自然なトレードオフが生じる余地を作る。

目標は特定の `body_size` を設計者が正解として与えることではない。

> 小型ほど無条件に有利、という一方向性を崩し、環境によって異なるサイズが
> 自然選択されうる世界へ近づける。

## 2. 生物学的な位置づけ

`docs/LUCA参照モデル方針.md` に従い、LUCAそのものを再現しない。
現実から借りるのは主に**構造・因果・スケーリング**であり、Joule/秒などの絶対値を
未校正の `Energy` / tick へ直接移植しない。

微生物では、増殖に直接使われない maintenance metabolism / basal power requirement が
存在し、特に最小クラスの細胞では maintenance が total metabolism に近づき、
細胞サイズの下限を制約しうることが示されている。

参考:
- Kempes et al. (2017), *Drivers of Bacterial Maintenance and Minimal Energy Requirements*, Frontiers in Microbiology 8:31.
  https://www.frontiersin.org/journals/microbiology/articles/10.3389/fmicb.2017.00031/full
- LaRowe & Amend (2015), *Power limits for microbial life*, Frontiers in Microbiology 6:718.
  https://www.frontiersin.org/journals/microbiology/articles/10.3389/fmicb.2015.00718/full
- Moody et al. (2024), *The nature of the last universal common ancestor and its impact on the early Earth system*, Nature Ecology & Evolution 8:1654–1666.
  https://www.nature.com/articles/s41559-024-02461-1

LUCAの推定代謝量そのものを `C_core` にするわけではない。

## 3. 現行モデルには既に「個体数を増やすコスト」が一部存在する

現行の維持費には、完全に身体量比例ではない項がすでにある。

- `sense_upkeep * sensory_range^2` は身体量に依存しない
- `birth_overhead = 2.0 E` は1回の繁殖ごとの固定費
- random walk 時は `v_max ∝ 1/sqrt(matter)` のため、固定形質・健全時の移動費
  `move_cost * matter * v^2 / efficiency` は概ね身体量非依存になる

それでも exploratory run では `mean_body_size ≈ 0.226` まで縮小した。
したがって、現行の固定的なコストだけでは、資源交換面積・繁殖必要Matter・速度などから
生じる小型化メリットを十分に相殺していない。

V1.7では新しい「小型個体への罰」を足すのではなく、現在のBMRの一部を
**サイズを縮めても消えない生命維持部分**として再解釈する。

---

## 4. 採用候補式

現行:

```text
BMR_old = bmr_coef * M^0.75
bmr_coef = 0.3
```

V1.7候補:

```text
BMR_new = C_core + (bmr_coef - C_core) * M^0.75
```

ここで:

- `M` は従来どおり **現在の身体Matter (`org.matter`)**
- `C_core` は個体ごとの縮小不能な基礎維持代謝 `[E/tick/individual]`
- コード上のConfig名候補は `bmr_core`
- 制約は `0 <= C_core <= bmr_coef`

### 4.1 この式を選ぶ理由

#### `C_core = 0` ならV1.6と完全一致

```text
BMR_new = 0.3 * M^0.75
```

したがって新規機構を無効化した対照が厳密に作れる。

#### `M = 1` の基準個体は全候補でBMR=0.3

```text
BMR_new(M=1) = C_core + (0.3-C_core) = 0.3
```

LUCA-inspired reference organism の基準サイズを `M=1` と解釈したとき、
現在まで使ってきた基準BMRを変更せず、**BMRの内訳だけを再配分**できる。

#### `M -> 0` ではBMRが `C_core` に近づく

身体を小さくしても、生命維持に必要な基礎機構のコストが0へ消えない。

#### 大型側も自然に変わる

`C_core > 0` ではサイズ依存部分の係数が小さくなるため、大型個体はcoreをより大きな身体で
償却できる。この効果は「大型化ボーナス」を別に追加したものではなく、
BMRをcore + scalable部分へ分解した結果として生じる。

これは意図した性質だが、強すぎると `body_size=10` 側への張り付きが起こりうる。
Exp11では小型境界だけでなく**上限境界への張り付きも同時に測る**。

## 5. V1.7で変更しないもの

Exp11で `C_core` の効果を1軸で切り分けるため、以下は変更しない。

- `body_size` 遺伝子の範囲 `0.2 .. 10.0`
- 有効表面積 `M^(2/3)`
- Energy容量・Damage容量
- 移動速度・移動費
- 器官維持費・sense維持費・膜維持費・耐性維持費
- reproduction threshold / `child_matter_frac` / `birth_overhead`
- light / chemical / nutrient 吸収則
- V1.6 temporal biased random walk
- 温度・熱損失
- 捕食/防御ルール
- 新規遺伝子
- populationを人為的に減らす処理

`C_core` は**遺伝子にしない**。これは個体の能力ではなく、当面は細胞生命に共通する
基礎生理ルールとして扱う。

## 6. Config / 実装方針

候補:

```python
bmr_coef: float = 0.3   # M=1での基準BMR
bmr_core: float = 0.0   # V1.7: 縮小不能なcore BMR
```

実装:

```python
bmr = cfg.bmr_core + (cfg.bmr_coef - cfg.bmr_core) * s ** 0.75
```

入力時またはSimulation初期化時に

```text
0 <= bmr_core <= bmr_coef
```

を検証し、範囲外は `ValueError` とする。

Energy台帳上は従来BMRと同じく散逸Energyとして扱う。

Exp11の選定までは `bmr_core=0` を暫定defaultとし、通常Configの結果を変えない。
Exp11で恒久値が選定された場合のみ、別commitでdefaultへ反映する。

## 7. V1.7着手前のV1.6確定処理

2026-09-01時点で、Exp10の人間判断では

```text
memory_tau = 10
response_gain = 64
```

を現行参照値として採用したが、`evosim/config.py` の通常defaultはまだ
`response_gain=16` のままである。

これはV1.7の実験軸へ混ぜない。

V1.7実装前に別commitで:

1. `response_gain` defaultを **64** へ反映
2. Exp10選定値の反映としてテスト・CI基準を更新
3. `v1.6-final` branchを保存
4. その後にV1.7 `bmr_core` を実装

とする。

Exp11 Configでは安全のため `memory_tau=10 / response_gain=64` を明示指定し、
グローバルdefaultへの暗黙依存を避ける。

## 8. 必須テスト

実装時に最低限以下を固定する。

1. `bmr_core=0` で旧V1.6式と完全一致
2. `M=1` では任意の合法 `bmr_core` でBMRが厳密に `bmr_coef`
3. `M>0` / `0<=core<=coef` でBMR非負
4. `bmr_core=bmr_coef` ではBMRがサイズ非依存
5. `bmr_core<0` / `bmr_core>bmr_coef` を拒否
6. Energy台帳・Matter保存
7. 同一seed決定性
8. 観測追加がRNG系列を変えない

Exp11 Phase 0 の詳細は `docs/Exp11_実験計画案.md` を正本とする。
