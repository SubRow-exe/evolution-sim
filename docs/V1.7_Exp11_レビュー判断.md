## 2. 要修正6点

### 2-1 POP_HALT指標未定義 — 採用

- halt時 `final` = `finalize()` が保存する最終snapshot
- halt snapshotからfinal body-size統計 / `p_low` / `p_high` は報告可能
- COMPLETEでないrunのlate-window / stationarityはN/A
- POP_HALTはB1 per-seed Greenには数えない

### 2-2 `bmr_core=0` 対照妥当性 — 採用

body_sizeだけ進化ONでも小型化圧が再現することを内部対照で確認する。

B1 `bmr_core=0` で `p_low>=0.50` が8 seed中5以上なければ `CONTROL_NOT_REPRODUCED / NO_SELECTION / REVIEW`。全runは集約するが恒久値は選ばない。

### 2-3 最初の単発Greenが脆い — 指摘採用、Claude修正案は一部変更

Claude案「候補およびそれより大きい全候補がGreen」は採らない。極端に大きい `bmr_core` が別の理由で生態を壊した場合、妥当な中間値まで無効化するため。

代わりに**連続3候補Green**を要求する。

```text
b_i, b_(i+1), b_(i+2) がすべてB1 Green
-> b_i = TRANSITION_ELIGIBLE
```

### 2-4 B2/B3 4 seed vetoが弱い — 採用・修正

Actions matrix 256枠を使い、B2のみseed1-5へ増やす。

```text
B1 15×8 = 120
B2 15×5 = 75
B3 15×4 = 60
合計255
```

絶対的な1 seed絶滅でvetoせず、同環境 `bmr_core=0` を内部baselineとして相対悪化を見る。詳細はExp11 §11.4–11.5。

### 2-5 stationarity / 進化機会 — 採用

B1 per-seed Greenへ:

- same-seed baselineに対する `max_generation` 条件
- `late_drift<=0.10`

を追加する。初期値付近から動かなかっただけのrunをGreenにしない。

### 2-6 workflowをmainへ置く — 採用

V1.7実装・45 Config・`exp11.yml`をmainへマージしてからworkflow_dispatchする。

## 3. 設計論点

### 3-1 再配分型は大型側BMRも下げる — 意図的に維持

採用式:

```text
BMR = bmr_core + (0.3-bmr_core)*M^0.75
```

は `M>1` でV1.6よりBMRを下げ、大型側にも相対的メリットを作る。この点を明示したうえで維持する。

純加算形:

```text
0.3*M^0.75 + bmr_core
```

も検討したが、M=1 reference organismの総BMRまで引き上げるため不採用。現在の0.3をcore+scalableへ再解釈する再配分型を選ぶ。

### 3-2 initial_matter=0.8 — 採用

M=1不変だけを強調せず、A1へM=0.8を追加し、正式runの `initial_matter=0.8` を明記する。初期BMR増による影響を監査する。

### 3-3 Phase Aが静的 — 採用

A3 reproductive-opportunity proxyを追加する。世代時間・wander速度を含む事前診断だが、適応度計算や候補削減には使わない。

### 3-4 Matter制限 — 採用

free nutrient、total biomass、biomass fraction等を時系列診断へ追加する。選定条件にはしない。

### 3-5 POP_HALTとp_lowの従属性 — 採用

両者を独立証拠として二重に解釈しない。

## 4. 軽微事項

- パラメータ名はコード・Config・実験文書とも **`bmr_core` に統一**
- 非ゼロ `bmr_core` JSON round-trip / runmeta / fingerprint / checkerを追加
- job timeoutは120分ではなく **350分**を基準とする
- timeout等は科学的STOPではなく `INCOMPLETE_RESOURCE`。完了済み結果はcollectorで保持し、同一SHA/Configで技術的不完了jobのみ再実行可能
- A2はparent matter `0.8 / 1.0 / 1.2 × target` を監査
- `p_low/p_high` はsnapshot由来であること、halt時finalize snapshotを使うことを明記
- Exp11結果は**他13遺伝子固定条件**のbody-size進化であり、全14遺伝子共進化へ一般化しない
- B2 `diagnostic_placement=vent`、B1/B3=randomを明記
- 「小型化を抑えるだけの人工ペナルティを入れない」原則は維持し、`bmr_core`が一般生理則として許容される理由をAGENTSへ残す

## 5. 最終実行方針

実装後、Phase 0を通過したら255 runを**最初から一括登録**する。

途中でPhase A/B1結果を見て候補を削らない。科学的STOP/REVIEWが出ても、技術的に実行可能な残り条件を止めない。

結果確定後は事前登録規則で機械的に恒久 `bmr_core` 候補を選ぶ。条件を満たす値がなければ、値を後付け調整せず `NO_SELECTION / REVIEW` とする。
