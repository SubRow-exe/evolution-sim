更新: 2026-09-08  
状態: **IMPLEMENTATION PLAN / Claude実装用正本**

## 0. Version位置づけ

V1.10.1は新しい生物学・化学原理を追加するversionではない。

> **V1.10で成立したH2/C/N/P世界を維持したまま、熱水噴出口の場所・供給流量・時間変動を実験条件として明示的に制御可能にする条件系更新。**

したがってmajor/minor world-rule更新のV1.11には上げず、V1.10.1とする。

V1.10から変更しないもの:

- H2 -> usable Energy変換
- H2 uptake kinetics
- H2 diffusion
- H2 exchange/loss `tau=900 s`
- iLUCA physiology
- Energy/homeostasis
- growth/reproduction
- C/N/P stoichiometry / ledger
- 行動則・変異則
- phototrophy/predation OFF

V1.10.1で扱うのはH2 source条件のみ。

---

# 1. 目的

現在のformal V1.10 H2 sourceは、4つのsource cellを各substepで10 mMへDirichlet復元するため、良いpatchを見つけた後の環境が長期的に安定しすぎる。

V1.10.1では以下を可能にする。

1. H2供給を `mol/s` で明示的に指定する
2. ventの供給を時間的にON/OFFできる
3. vent位置を一定間隔で入れ替えられる
4. 条件間で世界全体のH2供給量を揃えた比較を行える
5. V1.10 legacy Dirichlet sourceを再現可能な互換モードとして残す

目的は「生物を生存させるようH2を再調整すること」ではない。

---

# 2. H2 source mode

Configにsource modeを追加する。

```python
h2_source_mode: str = "dirichlet"  # backward-compatible default
```

許可値:

```text
dirichlet  # V1.10以前を完全再現
flux       # V1.10.1 formal mode
```

`dirichlet`時は既存ロジックを変更しない。

`flux`時はsource cellへ、各substepで

```text
Delta_n_H2 = vent_flux_mol_s * dt_sub
Delta_C = Delta_n_H2 / voxel_volume
```

を加える。

順序は原則:

```text
source injection -> exchange/loss -> diffusion
```

とする。

H2 ledgerの `source_in_mol` は実際に加えたmol数を積算する。

濃度上限を人工的にclampしない。非負性・有限値のみ保証する。

# 4. finite flux基準値の決め方

vent flux値を恣意的に置かない。

Exp18 Phase 0で、V1.10 legacy Dirichlet sourceについて:

```text
4 vents
10 mM source concentration
D_H2 = 5e-9 m2/s
tau = 900 s
organismなし
```

で十分warm-upした後、定常状態での実source補給量を測る。

定義:

```text
F_total_legacy = steady-state source_in_mol / elapsed_s
F0 = F_total_legacy / 4
```

V1.10.1 static finite-flux controlの1 ventあたりfluxを `F0` とする。

**Exp18結果を見てF0を生存側へ調整してはいけない。**

finite-flux化により、生物が局所H2を消費してもsource自身が自動的に補給量を増やさない点は、Dirichlet sourceとの意図した差である。

# 5. temporal fluctuation

Config候補:

```python
h2_vent_temporal_enabled: bool = False
h2_vent_cycle_period_s: float = 43200.0   # 12 h
h2_vent_duty_fraction: float = 0.5
h2_vent_on_flux_multiplier: float = 2.0
h2_vent_phase_mode: str = "paired_staggered"
```

Exp18 formal条件では:

```text
cycle = 12 h
ON = 6 h
OFF = 6 h
ON中flux = 2 * F0
```

4 ventを2組へ分け、位相を6 hずらす。

```text
vent 0,1 : t mod 12h in [0,6h) でON
vent 2,3 : t mod 12h in [6h,12h) でON
```

したがって常に2 ventがONで:

```text
2 * (2 F0) = 4 F0
```

となり、**瞬間総fluxもstatic controlと一致**する。

時間変動の効果と総供給量の効果を分離するため、この等価性をtestで保証する。

# 6. vent turnover / relocation

Config候補:

```python
h2_vent_turnover_enabled: bool = False
h2_vent_turnover_interval_s: float = 172800.0  # 48 h
h2_vent_turnover_count: int = 1
h2_vent_min_separation_cells: int = 4
```

formal条件:

- 常にvent数 = 4
- 48 hごとに1 ventだけ消滅
- 同時刻に別セルへ1 vent新生
- flux総量は変えない
- vent radiusは1 cell
- world端から最低1 cell内側
- 他ventとの最小距離条件を満たす

turnover対象はindex順にrotationしてよい。

新位置はrun seedから導出した**専用environment RNG**で決める。

重要:

> vent relocationの乱数消費がorganism mutation / movement RNG列をずらしてはいけない。

推奨:

```python
SeedSequence([run_seed, fixed_environment_stream_id])
```

から独立PCG64を作り、run開始時に必要なturnover scheduleを全てprecomputeする。

同一seed/configでscheduleは完全再現可能であること。

# 7. H2初期場

条件間の初期差を不要に混ぜないため、全Exp18 Phase A/Bでt=0のH2 fieldは共通化する。

推奨:

1. 旧V1.10 square 4-source / 10 mM Dirichletでabiotic warm-up
2. 得られたH2 fieldをt=0 initial fieldとしてコピー
3. t=0から各V1.10.1 source scheduleへ切り替える

これにより初期populationが見るH2 fieldを同じにし、以後の差をsource dynamicsへ限定する。

warm-up中のsource入出力はformal ledgerへ含めない。t=0でledger resetする。
