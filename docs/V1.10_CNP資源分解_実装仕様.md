# V1.10 C/N/P資源分解 — 実装仕様

更新: 2026-09-07  
状態: **IMPLEMENTATION DRAFT / Claude実装可能レベル**

## 0. 目的

V1.9の環境 `nutrient` は「身体を作るMatterそのもの」に近い抽象資源で、初期stockしかなく、Exp16ではこれが実質的なcarrying capacityを決めていた。

V1.10では **Organism.matter は乾燥細胞質量 (dry biomass) として残すが、環境中のgeneric Matter資源を廃止し、細胞を作る主要構成資源を最低限だけ明示化する。**

目的はLUCA完全再現ではない。以下を達成すればclose可能。

1. 「Energyはあるが材料が無い」「CはあるがN/Pが無い」を表現できる
2. biomass growthのC/N/P収支が追跡可能
3. V1.9で隠れていた有限Matter stock依存を除去する
4. 将来のcross-feeding / oxygen / ecologyへ接続できる

# 1. V1.10で明示する資源

## 1.1 DIC / CO2-equivalent inorganic carbon

コード名候補: `inorganic_carbon` または `dic`
単位: `mol C / m3`

ユーザー向けには「CO2由来の無機炭素」と呼ぶ。

水中ではCO2(aq), HCO3-, CO3--の比率はpHで変わるが、V1.10ではpHをまだ持たない。そのため **全bioavailable inorganic carbonをCO2-equivalent 1 mol C = 1 mol carbon substrateとしてcollapse**する。

将来pH導入時にspeciationを分けられるinterfaceにする。

reference background:
- `dic_background_molm3 = 2.2`  # 2.2 mM C-equivalent

Lost City周辺のambient seawater DIC約2.2 mMをorder anchorにする。歴史上のLUCA海洋の真値とは主張しない。

## 1.2 fixed nitrogen

コード名候補: `fixed_nitrogen`
単位: `mol N / m3`

NH4+を主な初期イメージとするが、V1.10では窒素speciationを作らない。NO3-/NH4+/N2固定能力の進化は後続phase。

reference background:
- `fixed_n_background_molm3 = 0.010`  # 10 uM N-equivalent

これはhydrothermal/seawater-mixed habitatのorder reference。厳密LUCA値ではない。

## 1.3 phosphate phosphorus

コード名候補: `phosphate`
単位: `mol P / m3`

reference background:
- `phosphate_background_molm3 = 0.001`  # 1 uM P

early-Earth phosphate abundanceは不確実性が大きい。したがって1 uMはreferenceであり最適値ではない。

## 1.4 V1.10では明示しないもの

- H2O: 水中worldなので十分存在すると仮定。陸上/乾燥phaseでexplicit化候補
- H/O: 水・無機炭素から十分供給されると仮定
- S, Fe, Mg, K, Na, Ca, trace metals: **V1.10ではnon-limiting implicit pool**
- FeS/cofactor制約: optional environmental axisへ保留

理由: C/N/Pは独立した主要律速軸になりやすい。一方S/金属まで同時に分割すると校正軸だけが増え、V1.10の目的を超える。

# 2. Biomass stoichiometry

V1.10では全iLUCA/子孫のdry biomass組成をまず固定する。新geneにはしない。

reference mass fractions:

```text
C = 0.47 kg C / kgDW
N = 0.11 kg N / kgDW
P = 0.02 kg P / kgDW
```

残り約40%はH/O/S/ash等としてimplicit。

細菌dry biomassではC約45-50%、N約9-13%が一般的orderで、Pも数%order。LUCAの真値ではなくmicrobial biomass proxy。

1 kgDW増加に必要なmol量:

```text
C_req = 0.47 / 0.012011  ~= 39.13 mol C/kgDW
N_req = 0.11 / 0.014007  ~= 7.85 mol N/kgDW
P_req = 0.02 / 0.030974  ~= 0.646 mol P/kgDW
```

Configにはmass fractionを正本として持ち、mol/kgDWはruntimeで計算してもよい。

新規Config候補:

```python
biomass_carbon_mass_frac = 0.47
biomass_nitrogen_mass_frac = 0.11
biomass_phosphorus_mass_frac = 0.02
```

validation:
- 各0以上
- 合計 < 1

# 3. Organism.matterの意味

`Organism.matter` は廃止しない。

意味を明文化:

> `matter` = cell dry biomass expressed in V1.9 matter units

physical mode:

```text
kgDW = matter * matter_unit_to_kgdw
```

環境から直接 `matter` を吸う機構だけを廃止する。

# 4. Growth algorithm

V1.9のmaintenance-first / protected runwayは維持。

各セルでgrowthを処理するとき:

## 4.1 各個体の最大growth request

個体iについて:

```text
dm_room    = matter_cap - current_matter
dm_kinetic = current V1.9 growth kinetic ceiling * nutrient_absorption_gene * dt
dm_energy  = E_growth_available / (growth_energy_j_per_kgdw * matter_unit_to_kgdw)

dm_req_i = min(dm_room, dm_kinetic, dm_energy)
```

`nutrient_absorption` geneはV1.10では **generic inorganic assimilation capacity** と読み替えて維持する。新しいC/N/P uptake geneは追加しない。

## 4.2 cell全体のstoichiometric requirement

```text
kgDW_req_total = sum(dm_req_i) * matter_unit_to_kgdw
C_req_mol = kgDW_req_total * carbon_mol_per_kgdw
N_req_mol = kgDW_req_total * nitrogen_mol_per_kgdw
P_req_mol = kgDW_req_total * phosphorus_mol_per_kgdw
```

cellのavailable stockから共通scaleを計算:

```text
s_C = available_C / C_req
s_N = available_N / N_req
s_P = available_P / P_req
s = clip(min(1, s_C, s_N, s_P), 0, 1)
```

全個体へ同じ`scale=s`を掛ける。

これにより同じcell内で資源不足時も順序依存を避ける。

## 4.3 実growth

```text
dm_i = dm_req_i * s
```

- organism.matter += dm_i
- Energy -= synthesis cost
- C/N/P fieldから固定stoichiometryで差し引く
- concentrationは0未満にしない

**intracellular precursor poolはV1.10では作らない。** 取得とbiomass assimilationを同stepでcoarse-grainする。

# 5. Resource transport

3 fieldとも4近傍diffusion + background mixingを持つ。

reference diffusion coefficients:

```text
D_DIC = 2.0e-9 m2/s
D_N   = 2.0e-9 m2/s
D_P   = 0.8e-9 m2/s
```

H2と同じCFL subcycle utilityを再利用する。resourceごとに同じコードをcopyしない。generic scalar diffusion helperへ寄せることを推奨。

## 5.1 background exchange

V1.10 reference worldはhydrothermal plumeとambient seawaterの混合系とみなし、C/N/Pはuniform background reservoirへ緩和する。

```text
dC/dt = (C_background - C) / tau_mix
```

同じhydrodynamic mixingを粗視化するため、初期defaultは:

```text
cnp_exchange_tau_s = 900 s
```

とし、H2の`h2_exchange_tau_s`と同orderに置く。

注意:
- これは分子固有値ではない
- V1.11 dynamic hydrothermal / advection導入時に再設計対象
- Exp17結果を見て生存しやすいように調整しない

backgroundより局所濃度が高い場合はoutflow、低い場合はinflowとなる。

# 6. Death / corpse / predation / recycling

固定biomass組成なので、`matter`が環境へ戻るときはC/N/Pへ固定比で戻す。

## 6.1 corpse decay

corpse matter `dm` がdecayしたら:

```text
kgDW = dm * matter_unit_to_kgdw
C -> DIC field
N -> fixed_nitrogen field
P -> phosphate field
```

corpse自体はdecay前までC/N/Pを内包しているものとしてledgerに数える。

## 6.2 predation / corpse eating waste

prey matter taken - predator assimilated matter の差分はwasteとして同じC/N/P比でlocal fieldへ戻す。

## 6.3 reproduction

parent matter -> child matterの移動だけなので環境fieldは変化しない。

# 12. 科学的positioning

V1.10は「LUCAの元素組成を完全再現するversion」ではない。

> **generic Matter 1本を、今後の進化で意味のある最小のC/N/P resource systemへ置換するversion**

である。

現実側のanchor:
- bacterial dry biomassはC約45-50%、N約10%前後、P数%order
- water中CO2 diffusionは約2e-9 m2/s order
- Lost City ambient seawater DICは約2.2 mM
- Lost City endmember fixed Nは低いが、混合海水も含め実際のbioavailable Nは空間依存

reference値はoriginを生存させるための最適値ではなくorder anchorとして扱う。
