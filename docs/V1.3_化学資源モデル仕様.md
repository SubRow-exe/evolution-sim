# V1.3 化学資源モデル仕様

更新: 2026-08-30
状態: **実装仕様確定 / 未実装**

## 1. 背景

Exp06では、光を完全に0にし、通常祖先/vent配置/chemical_absorption=2.0固定などを組み合わせた4条件を各10 seedで実行したが、全条件が数百tick以内に絶滅した。

特に positive control の `chemical_absorption=2.0固定 + 全個体vent上配置` も10/10で絶滅した。したがって、問題は初期chemical能力やvent発見だけではない。

さらに現行chemical更新式を再点検した結果、化学噴出口を想定しているにもかかわらず、

```text
regen = r * stock * (1 - stock / K)
```

というロジスティック増殖式を用いていたことが根本的な設計不整合と判断した。

この式は「その場に存在する資源自身が増殖する」草・藻類・微生物等には適するが、地下・地殻から継続供給される熱水由来の還元性物質を表すには不自然である。stockを生物が減らすほど供給速度まで低下し、0付近では外部供給がほぼ止まるため、光との間に意図しない構造的非対称を作っていた。

## 2. V1.3でchemicalが表すもの

chemical fieldは、**海底熱水噴出孔・冷湧水等から供給されるH2S/H2/CH4/Fe2+等の還元性物質が持つ、生物が利用可能な化学自由エネルギーの粗視化量**として扱う。

重要な性質:

1. sourceは地質側にあり、生物の消費量とは独立に継続供給される
2. 噴出したchemicalは局所に一時的に蓄積可能
3. 蓄積は無限ではない
4. 生物が吸収しなくても、海水との混合・流出・希釈・酸化・沈殿等により利用可能状態から失われる
5. 生物はsourceそのものを枯渇させられないが、局所stockを一時的に低濃度まで消費できる
6. 次tickもsource fluxは変わらず供給される

光との共通点は「外部一次Energy source」であることだけ。chemicalは **局在・stock・滞留・局所枯渇・環境損失**を持つ点で光と異なる。

## 3. 新しい更新式

ventセルごとのchemical stockを `C` [E/cell]、そのセルへの外部供給を `S` [E/tick/cell]、環境損失率を `lambda` [1/tick]、生物吸収を `U` とする。

1 tickは次の順で処理する。

### 3.1 環境損失

```text
L = lambda * C_t
C1 = C_t - L
```

`L`は海水混合・流出・希釈・酸化等をまとめた粗視化Energy loss。`energy_out_cum`へ必ず計上する。

### 3.2 地質sourceからの供給

```text
C2 = C1 + S
```

`S`は生物や現在stockに依存しない一定source flux。
`sum(S)` は `energy_in_cum` に計上する。

**source全量がstockへ入る。上限クリップ (capacity) は設けない。**

stockが発散しないのは損失項があるためで、生物不在なら

```text
C* = S / lambda
```

へ収束する。`lambda=0.10` なら平衡stockは `10*S` で有限。
「有限のstock」は容量上限ではなく**滞留時間**が作る。

#### capacity clippingを廃止した理由

初期案では `chem_capacity` を局所保持容量とし、超過分をoverflowとして
系外へ捨てる設計だった。これは実験設計上の欠陥になる。

`chem_source_flux` は「1 ventの総fluxを、そのventの世界内円盤セルへ均等分配」
するため、world edgeで欠けたvent (13セル→9セル等) や他ventと重なるセルでは
1セルあたりのSが上がる。すると平衡stock `S/lambda` がcapacityを超え、
超過分がoverflowとして捨てられる。

seed 1-10 の実際のvent配置で試算すると、平衡状態で捨てられるsourceは:

| chem_vent_flux | clippingが起きるseed | 捨てられるsource最大 |
|---:|---|---:|
| 4〜24 | なし | 0.0% |
| 32 | 1 | 0.4% |
| 48 | 1, 4, 5, 8 | 5.6% |
| 64 | 1, 4, 5, 8, 9, 10 | 10.8% |

`sum(chem_source_flux)` は設定どおりでも、**実際に生物が使えるsourceが
seedごとに最大10%変わる**。§4がchem_source_flux fieldで排除しようとした
seed依存が、capacity側から入り込む。しかもflux 48/64というExp07の探索上端で
効くため、成立境界の判定を歪める。

したがってV1.3ではcapacityによるクリップを行わず、
**source全量流入 + 一次環境損失のみでstockを有限化する**。

### 3.3 生物吸収

現行吸収式:

```text
request = chem_uptake * chemical_absorption * matter * phi
U = min(request, local_stock, energy_capacity余裕)
```

をV1.3では維持する。

生物が大量に存在すれば `C2` をそのtick内に低値まで消費できるが、次tickの `S` は変化しない。

## 4. source fieldの生成

現行の `chem_mask` はunion maskのみで、ventが端にある場合や互いに重なる場合に世界全体の供給量がseedごとに変わり得る。

V1.3では `chem_source_flux[ix, iy]` を新設する。

各ventについて:

1. 現行と同じ乱数でvent中心を決める
2. `vent_radius_cells` の円盤内かつworld内のセルを列挙
3. そのventの総供給量 `chem_vent_flux` を列挙セルへ均等分配
4. 重複セルでは複数ventの寄与を加算

したがって、どのseedでも原則

```text
world chemical source = n_vents * chem_vent_flux
```

となる。端で円盤が欠けても、そのventの総flux自体は変えない。

`chem_mask = chem_source_flux > 0` としてよい。

## 5. Config

V1.3で使用:

```text
chem_vent_flux = 8.0          # 1 ventあたり総外部供給 [E/tick/vent]
chem_loss_frac = 0.10         # stockの環境損失割合/tick
chem_uptake = 0.5             # 生物側吸収係数。現行値を維持
```

`chem_vent_flux=8.0` はExp07前の暫定default。4 ventsなら世界総flux=32 E/tickで、旧モデルの理論最大約32.5 E/tickとほぼ同程度の供給規模を基準点として持たせるためである。恒久値はExp07結果後に判断する。

旧:

```text
chem_regen        # ロジスティック回復率
chem_min_stock    # 0からの回復下限
chem_capacity     # 局所stock上限 (clipping廃止により不要)
```

はV1.3 sourceモデルでは使用しない。Configから削除する。

`chem_capacity` はGUIのchemical可視化スケールにも使われていたため、
V1.3では `max(chem_source_flux) / chem_loss_frac` (=最大平衡stock) を
正規化基準に置き換える。世界ルールには影響しない表示のみの変更。

### chem_loss_fracの位置づけ

`0.10/tick`は実時間への校正値ではなく、粗視化した局所滞留時間を与える暫定値。生物がいなければ、理論平衡stockは

```text
C* = S / lambda
```

となる。`lambda` を下げるとstockが厚くなり、上げると薄く回転が速くなる。

Exp07ではlossを固定しsource fluxだけを振る。loss感度はchemical生態が成立した後の別実験で扱う。

## 6. 初期chemical stock

旧モデルの `0.5 * chem_capacity` 固定初期stockは廃止する。

V1.3では生物がいない定常状態から開始するため、各セルを

```text
chemical_initial = chem_source_flux / chem_loss_frac
```

で初期化する。これは§3の更新式の不動点そのものであり、
生物がいなければstockはこの値を保つ。

これにより「実験開始時だけ大量のchemical stockが置かれている」という人工的な一過性パルスを避ける。

## 7. Energy台帳

`World.update()` は最低限、

```text
chemical_influx              # sum(chem_source_flux)。毎tick一定
chemical_environment_loss    # chem_loss_frac * stock の合計
```

をSimulationへ返せる形に変更する。capacity clippingを廃止したため
overflow項は存在しない。

Simulation側:

```text
energy_in_cum  += chemical_influx
energy_out_cum += chemical_environment_loss
```

を行う。

Energy保存テスト:

```text
initial_system_energy
+ external_energy_in
- energy_out
= current_system_energy
```

が従来同様成立すること。

## 8. V1.3で変更しないもの

Exp07の因果を読めるよう、以下は変更しない。

- lightモデル
- chemical_absorption遺伝子の意味
- `chem_uptake`
- body_size/matterの吸収依存
- 生理コスト
- 繁殖仕様
- mutation仕様
- vent数・半径
- nutrient
- sensory/移動
- corpse/predation

## 9. 今回まだ入れないもの

### chemical diffusion / plume

実際にはvent fluidは周囲海水へ拡散・移流し、濃度勾配を作る。しかしV1.3ではsource diskの外へchemicalを拡散させない。

`chem_loss_frac` が「今回観測領域から失われる」効果を粗視化して代表する。

将来候補:
- chemical diffusion
- flow/advection
- 酸化速度の空間依存
- vent中心からのradial source profile

### chemical uptakeの個体処理順依存

現コードはchemical stockを個体リスト順で逐次吸収するため、資源不足時に処理順による競争biasがあり得る。

V1.3/Exp07では「chemical生態が長期成立する供給域」を主目的とし、この競争biasは変更しない。Exp07でlineage競争・sweepの強い結論は出さない。

chemicalと光を同居させて競争を評価する前に、必要ならcell内chemical需要を事前集計して需要比で配分する方式を別変更として検証する。

### 初期population / 初期ゲノム

Exp06でCまで絶滅したため、まずsourceモデルを正常化する。初期chemical_absorption、sensory_range、initial_populationはExp07では原則変更しない。

```text
   chem_regen / chem_min_stock / chem_capacity を削除

```

### 世界バージョン境界の扱い (9の補足)

V1.3は世界ルール変更なので、`tools/verify_vs_ref.py` を旧refに対して実行すると
**必ず不一致になる**。これは異常ではなくバージョン境界である。

- `tests/golden_state.json` のV1.2指紋は `tests/golden_state_v1.2.json` へ履歴保存する
- `.github/workflows/ci.yml` の結果不変性の基準refをV1.3実装コミットへ移す
- 以後は「V1.3内での結果不変」をCIが守る

V1.2以前の再現には `v1.2-final` を使う。`configs/exp05_*.json` /
`configs/exp06_*.json` はV1.3コードでは当時の結果を再現しない。

## 11. 必須テスト

- `sum(chem_source_flux) == n_vents * chem_vent_flux` を複数seedで確認
- ventがworld edgeでも1 ventの総fluxが一定
- vent重複時も各vent寄与が保存される
- **実効source == 公称source**: 全seed・全Exp07 fluxで、
  毎tickの実際のchemical流入が `n_vents * chem_vent_flux` と一致する
  (capacity clipping廃止の主目的。seed依存の損失が無いことの保証)
- 生物0でstockが理論平衡 `S/lambda` を保つ (初期値が不動点である)
- 生物がstockを消費した後、停止すれば `S/lambda` へ戻る
- stock=0でも次tick sourceが供給される
- 生物がstockを消費しても次tick source量は不変
- chemicalは0未満にならない
- source flux が0のセルはstockも常に0
- lossがEnergy outに、sourceがEnergy inに計上される
- Energy保存則がchemical条件でも成立する
- 乱数消費が旧実装と同じ (vent中心の抽選のみ) であること
- chemical source以外を変えていないConfigでは既存の光・nutrient等のテストがGreen

## 12. 科学的な位置づけ

V1.3は「chemicalを強くして多様性を作る」ための恣意的buffではない。

Exp06で判明した、**chemicalを地質由来一次Energy sourceとして定義しているのに、その供給式が自己増殖資源型になっていたモデル不整合を修正するもの**である。

恒久的なchemical供給量はExp07で成立範囲を測定した後に決める。光と同量に揃えること自体を目標にしない。局所ニッチとして小さなcarrying capacityでも、持続可能かつ進化可能であればよい。
