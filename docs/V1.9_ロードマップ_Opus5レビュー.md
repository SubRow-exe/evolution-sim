# 0. 結論を先に

方向性は正しい。「LUCA再現度を目的化せず、originとして十分妥当ならcloseする」という判断、Exp15 Attempt 1を失敗として保存した判断、Exp16でbaselineを最適化し直さなかった判断は、いずれもこのプロジェクトが以前に踏んだ罠を正しく避けている。

```text
F-2  実際の律速・carrying capacityはH2ではなくMatter -> 全実験の解釈に影響

```

一方で、**Exp16の55 runは、生物不在の定常場から計算できる1つの数値だけで完全に再現できる**ことも分かった (§1.5)。これは今後の環境追加すべてに使える事前スクリーニングになる。

# 1. 実測で分かったこと

すべて `experiments/opus5_roadmap_review_20260907/` で再現できる。

## 1.1 F-1 — light routeが物理スケール化されていない【Phase 1 HARD BLOCKER】

`evosim/simulation.py` の `_absorb_light()` には **`physical_mode` 分岐が無い。**
`_absorb_h2()` は冒頭で `if self.cfg.physical_mode: self._absorb_h2_physical(...)` へ分岐するが、light側には対応する処理が存在しない。

結果として、旧arbitrary単位の需要が、Joule建てになった `org.energy` へそのまま加算される。

実測 (`light_scale_check.py`、Exp15 Attempt 2 LUCA proxy config):

```text
E_max                        = 1.5639e-11 J
1 stepあたりmaintenance       = 4.3293e-15 J
light_max                    = 1.2      [旧 arbitrary E/tick 単位]
light field max              = 1.1895

light_absorption = 0.01 (= phototrophy_seed_absorption、最弱の新生phototroph)
  -> raw demand = 8.3748e-03
```

比:

```text
8.37e-3 / 1.56e-11 = 5.4e8 倍 (E_max = 全エネルギー容量) の需要を1 stepで出す
8.37e-3 / 4.33e-15 = 1.9e12 倍 (1 stepのmaintenance)
```

需要は `E_max - energy` でclampされるので発散はしない。しかしそれは**最弱のphototrophが、昼の毎stepで自分のエネルギータンクを満タンに戻せる**ことを意味する。H2側は同じ条件で1分裂に13時間かかる (§1.4)。

したがって現状で `phototrophy_innovation_prob > 0` にすると:

- 最初のinnovation個体が即座にエネルギー無制限になる
- `light_absorption` の値がほぼ無関係になる (0.01でも1.0でも同じくcap張り付き)
- 「phototrophyが爆発的に固定した」という、機構ではなく単位不整合が生んだ結果が出る

**これはPhase 1のHARD BLOCKERである。** どのcloseリストにもチェックリストにも載っていない。

必要な作業: `light_max` を W/m^2 (またはphoton flux) へ、`light_uptake_coef` を吸収断面積×量子収率相当へ置き換え、`_absorb_light()` に `physical_mode` 分岐を入れる。H2側で既にやったのと同じ作業を、light側でまだやっていないだけである。

## 1.2 F-2 — 実際のcarrying capacityはH2ではなくMatter

`nutrient` 場には**source が無い。** `evosim/world.py` は初期化で `np.full(..., nutrient_initial)` するだけで、以後は拡散と死骸分解による還流しかない。

```text
nutrient_initial = 2.0 / cell  ×  40×40 cells   = 3200 matter unit
initial_population 100 × initial_matter 0.50     =   50 matter unit
系の総Matter                                     = 3250 matter unit  (実測値と一致)
```

繁殖は `matter >= 1.0 × target_size`、子は `child_matter_frac=0.5` を受け取るので、集団の平均matterは概ね 0.65–0.75 になる。したがって:

```text
個体数の絶対上限 N_max ≈ 3250 / 0.70 ≈ 4600
```

Exp16の実測と並べる:

```text
baseline_10mM        final N = 2981   -> 総Matterの約64%が生物体内
h2_15mM              final N = 4876   -> 上限を超えている (平均matterが0.67未満へ圧縮)
exchange_slow_3600s  final N = 5000   -> max_population_halt に到達
diffusion_high       final N = 4937   -> 同上
```

`matter_ceiling_trace.py` でbaselineを4日追跡した実測:

```text
 day      N   nutrient    inOrg   meanM  meanE/Emax   medH2
 0.25    100     3194.8     55.2  0.5518       0.048  0.5664
 2.00    100     3144.5    105.5  1.0548       0.042  0.5664
 4.00    238     3024.4    225.6  0.9477       0.044  0.5664
```

したがって:

> **Exp16の「高成長」条件 (h2_15mM / diffusion_high / exchange_slow) は、H2由来の成長能力を測っていない。有限で再生しないMatter stockをバイオマスへ変換し切る速度を測っている。**

Exp16 §7.2 が「rich環境では別の律速が見え始める」と書いているのは、まさにこれである。文書は現象に気づいているが、正体を特定していない。

さらに重要な帰結が2つある。

1. **この世界には既にdensity dependenceがある。** ただしH2ではなくMatterの奪い合いとして。ロードマップは「資源競争・carrying capacityはPhase 6で扱う」としているが、実際には**もう起きていて、しかもその資源の物理的意味が定義されていない。** `V1.9_物理スケール再校正方針` の S3 が「nutrient field = 何を表すか」と問うたまま、答えないで先へ進んでいる。

2. **`max_population_halt = 5000` と Matter上限 ≈ 4600 がほぼ同じ値になっている。** つまり「haltで止まった」のか「生態学的上限に達した」のかを、現在の記録からは区別できない。Exp16 §7.3 の「10日runは平衡確認ではない」という留保は正しいが、留保では足りない。この2つは分離して記録する必要がある。

## 1.3 F-3 — H2 sourceは無限供給 (Dirichlet固定)

`_diffuse_h2_physical()` は毎substepで source cell を `h2_source_concentration_molm3` へ**復元**する。

```python
deficit = c_source - c[source_mask]
source_in_mol += float(deficit.sum()) * voxel_volume
c[source_mask] = c_source
```

生物がsource cellでいくら消費しても、次のsubstepで濃度が戻る。**source cellでのH2枯渇は原理的に起こらない。**

source外でも、Exp16実測の biological uptake / source influx = **5.6e-6** (最大条件でも1e-5オーダー) が示すとおり、生物はH2場をほぼ削っていない。上の4日トレースでも `medH2` は 0.5664 のまま**小数点以下4桁まで一定**である。

これは前回レビュー (`docs/V1.9_物理スケール_Opus5レビュー.md` M-2) で指摘した内容が、プロジェクト自身の実データで確認された形になる。原因は当時の分析どおり、**非生物的なexchange/loss sink (tau=900 s) が生物的sinkの約1e5倍強い**ことにある。vent濃度を下げても消費・供給の双方に濃度が入るため比は変わらない。

## 1.4 倍加時間 — 4–8 h anchorとの整合

LUCA proxyのパラメータから解析的に出る値 (`exp16_habitability_predictor.py`):

```text
H2無限大での理論最短倍加     =  8.01 h
10 mM source cell での倍加   = 13.31 h
baseline中央値セルでの倍加   = 170.3 h
Exp16 baseline 実測          =  55.9 h
```

読み取れること:

- **proxyパラメータ自体は自己整合している。** 飽和条件での 8.01 h は `V1.9_物理スケール再校正方針` の sanity anchor「4–8 h、reference ≈6 h」の上端にちょうど乗る。M-1で私が指摘した「アンカー間の2.99×矛盾」は、Attempt 2で `atp = 32.1 kJ/mol`、`qmax = 120 mmol/(gDW h)` へ改訂されたことで**実質的に解消している。** これは評価すべき点。
- ただし 8.01 h に到達するには H2 >> Km = 6.2 mM が必要で、それはsource cell近傍 (全1600セル中52セル = 3.2%) だけである。
- **実測 55.9 h は、中央値セルの予測 170.3 h より 3.0倍速い。** これは走化性が実際に効いている定量的証拠である (§1.5)。

`V1.9_LUCA_proxy設計` §3.7 は `mu ≈ 0.11–0.17 h^-1` を「上限として置く」と書いているが、**実際にはEnergy側の制約でこのcapには一度も到達しない** (4日トレースでは kinetic cap の 5.4%)。この事実を文書へ書いておかないと、将来 `nutrient_uptake_rate_matter_per_h` を触る人が効かないパラメータを触ることになる。

生物不在の定常場のうち、この濃度を超えるセルの割合を「生息可能率」と呼ぶ。

`exp16_habitability_predictor.py` の出力:

| h2_1mM | 0/5 | 0 | 24.8 | 56.6 | **5.2%** | ∞ | — |
| exchange_fast_300s | 0/5 | 0 | 16.5 | 106.8 | **28.4%** | ∞ | — |

**生息可能率は11条件を完全に分離する。** 絶滅は全て 45.9% 以下、生存は全て 75.2% 以上。閾値はこの間にある。

しかも:

- final N の順序は「生息可能率 (主) → 中央値セルでの倍加時間 (従)」でほぼ説明できる。
- 実測 gen interval / 予測 Td@med の比は 1.0, 0.68, 0.38, 0.33, 0.29, 0.21。**環境が悪いほど比が良くなる。** これは走化性が不均一な場ほど大きな利得を出していることの直接的証拠で、Exp15 Phase Aの問い「temporal chemical sensing / chemotaxisが実際に意味を持つか」への定量的な答えになっている。`exchange_slow` (ほぼ均一な場) では 32.6 h 予測に対し実測 32.0 h と一致し、走化性の利得がほぼ消える。

**この予測子はExp16の55 runを走らせずに得られる。** 今後どの環境軸を追加する場合でも、「生物不在の定常場 → 参照個体の収支 → 生息可能率」を先に計算すれば、全滅条件と飽和条件を事前に外せる。実験コストの削減として、これが本レビューで最も実用的な提案である。

なお、`Exp16_V1.9_結果考察` §3.1 の `L ~ sqrt(D*tau)` による整理は順序としては正しいが、**因果としては生息可能率のほうが直接的**である。L は「haloの広がり」の代理指標にすぎず、参照個体の代謝収支を含まないため、生理を変えたときには使えない。文書を差し替えることを推奨する。

## 1.6 F-4 — 深海ventと昼夜光は両立しない

`V1.9_LUCA_proxy設計` §3.1 は Lost City型 serpentinizing hydrothermal fluid を根拠に 10 mM を採っている。Lost Cityは**水深750–900 m、完全な無光層**である。

一方、V1.8 day/night機構は `light_cycle_period = 24 h`、`light_day_fraction = 0.5` で維持されており、Phase 1はその光を使ってphototrophyを創発させる計画になっている。

**同じ水塊が10 mMのvent H2を持ちつつ意味のある光量を受けることはない。** これは数値の問題ではなく設定の物理的整合性の問題で、Phase 1の結果を発表可能な形にするなら先に解消しておく必要がある。

最小の修正は**habitatの読み替え**である。浅海熱水系 (Vulcano、Milos、Kueishantao など、水深およそ5–200 m) は実在し、H2/H2Sの地質学的供給と光が同時に存在する。文書上1段落を書き換えるだけで、

- H2濃度は浅海熱水系のオーダーへ (Lost Cityより低いことが多い点は注記)
- 光は実在する水中光量へ
- 「chemical-first祖先の隣に光がある」というPhase 1の物語がそのまま成立する

となる。Lost Cityを引用したまま昼夜光を回すより、はるかに安全である。

# 3. 修正推奨点

## R-1 【最優先】light routeの物理スケール化をPhase 1の前提条件として明記する

§1.1。現状ではPhase 1は走らせても結果が読めない。V1.9 closeに含めるか、Phase 1の冒頭作業として明記するかは判断だが、**どこにも書かれていない現状は危険**である。

`長期ロードマップ` §3 と `次の実験計画` §5 に、Phase 1の前提として1行入れることを推奨する。

## R-2 【最優先】Matter/nutrientの意味と供給を定義する

§1.2。今のnutrientは「意味未定義・source無し・有限初期stock」でありながら、**個体数上限を決めている実質的な支配因子**である。

最小限やるべきこと (実装コストは小さい):

```text
1. nutrientが何を表すかを1段落で定義する (推奨: 炭素以外の生元素プール = N/P/S/微量金属)
2. 地質学的sourceまたはremineralization sourceを与え、carrying capacityを
   「初期条件のartifact」から「モデル化された性質」へ変える
3. max_population_halt と Matter由来上限を、記録上で必ず分離する
```

これはロードマップ Phase 3 (explicit carbon / Matter coupling) の**一部を前倒しする**提案である (§4 R-6も参照)。

## R-3 preregistered gateは「静かにSKIP」ではなく「大声でFAIL」にする

Exp15 Attempt 2 Phase Aは科学的にPASSしていたのに、workflowのartifact収集不具合でPhase Bが誤SKIPされた。

今後すべてのphaseがpreregistered gateで動く以上、これは繰り返される。**gate jobがsummary artifactを見つけられなかった場合は、FAIL扱いで先へ進むのではなく、非ゼロexitで停止する**べきである。「gateの入力が無い」と「gateの判定がFAIL」は別の状態であり、前者は必ず人間に見せる必要がある。

## R-4 実験成果物に「実際に走った設定」を残す

`run_luca_proxy.py` は `summary["luca_proxy"] = dict(LUCA_PROXY)` として**意図した値**を記録するが、`dataclasses.asdict(cfg)` も初期genomeの実現値も残していない。

Exp14では「計画文書に書かれた表現型が、generatorのoverride欠落で実際には適用されていなかった」ことで実験1本を失っている (`Exp14_表現型プロベナンス訂正`)。同じ穴がまだ塞がっていない。

推奨: 全formal runで `effective_config.json` (実現config全体) と `initial_genome.json` (実現初期表現型) をartifactへ出し、結果考察文書はそれを引用する。`AGENTS.md` のHARD RULEへ入れる価値がある。

## R-5 `Exp16` の解釈を「halo幅」から「生息可能率」へ差し替える

§1.5。`L ~ sqrt(D*tau)` は順序を再現するが生理を含まないため、iLUCA側を変えた瞬間に使えなくなる。生息可能率は生理と環境の両方を含むので、今後の全phaseで使い回せる。

## R-6 habitatを浅海熱水系へ読み替える

§1.6。文書上の1段落の変更で、Phase 1の物理的整合性が回復する。

## R-7 `nutrient_uptake_rate_matter_per_h` が効いていないことを明記する

§1.4。実測でkinetic capの5.4%しか使われていない。効かないパラメータをcalibration対象だと思わせないため、`V1.9_LUCA_proxy設計` §3.7へ「これはceilingであり、実際にはEnergy側が常に厳しい」を実測値つきで書く。

## R-8 mutation / innovation auditは実験ではなく計算で済ませる

`phototrophy_innovation_prob = 1e-4` / birth。Exp15 baselineの10日runでの総出生数はおよそ3000–4000。

```text
期待innovation回数 = 3500 × 1e-4 ≈ 0.35 回 / run
5 seed で 合計 約1.8回
```

**これではPhase 1は「innovationが起きたかどうか」の運試しになり、「起きた後に定着するか」を測れない。** また `phototrophy_loss_prob = 1e-3` は innovation probの10倍で、中立なら平衡頻度は 1e-4/1.1e-3 = 9%にしかならない。

この判断に**シミュレーションは不要**である。総出生数の見積もりだけで決まる。`次の実験計画` Step 3 を独立実験として立てるのではなく、Phase 1設計時の1時間の机上計算として畳むことを推奨する (§7 削ってよい実験)。

# 4. 優先順位変更

現在のロードマップ順:

```text
Phase 1 phototrophy -> 2 temperature -> 3 explicit carbon -> 4 pH/chemiosmosis
 -> 5 dynamic vent -> 6 ecology/HGT -> 7 oxygen -> 8 complexity -> 9 land -> 10 flight
```

推奨する変更は3つ。

## R-9 【昇格】「Matter/資源の閉じ方」をPhase 1より前へ

Phase 3 の一部 (§3 R-2の3項目) を**最優先へ前倒しする。** 理由は §1.2 のとおり、これが現在の個体数を決めている支配因子でありながら意味未定義だからである。

ただし Phase 3 全体 (CO2 field、炭素質量収支、WLPの炭素経路) を前倒しする必要はない。**Phase 3 を 3a / 3b に分割する**ことを推奨する。

```text
Phase 3a  Matterの意味定義 + source + carrying capacity の明示化   … 安い / 今すぐ
Phase 3b  explicit CO2 / inorganic carbon / 炭素質量収支            … 高い / 後で
```

3a は新しい環境因子の追加ではなく、既にある因子の意味を確定する作業なので、`環境因子追加・校正方針` の観点でもコストが低い。

**もし phototrophy をどうしても先にやりたい場合の最小回避策**: `nutrient_initial` を、runの到達個体数に対してMatter上限が十分上になるまで上げる。これでrun全体がEnergy律速の領域に留まり、Phase 1がMatter飽和のartifactに汚染されない。世界ルールを変えないのでversion境界も不要で、config変更1つで済む。ただし carrying capacity が未定義である問題自体は残る。

## R-10 【昇格】dynamic hydrothermal environment (Phase 5) を phototrophy より前へ

これが本レビューで最も強く推す順序変更である。

理由:

1. **Exp16の最大の成果を直接伸ばす軸である。** Exp16が示したのは「H2-rich領域へのアクセスが支配的」ということだった。次に問うべきは「そのpatchが動いたら何が起きるか」であり、これはExp16の結果から自然に導かれる唯一の問いである。
2. **V1.9で追加した3形質に、初めて本来の選択的意味が生じる。** `storage_capacity` / `starvation_horizon` / `reproduction_horizon` はいずれも「資源が時間的に途切れる」状況でこそ意味を持つ。現在のstatic ventでは、良いpatchを見つけたら永久に勝ちなので、貯蔵も飢餓応答も繁殖タイミングもほとんど効かない。Exp15 Phase B が弱い結果に終わる構造的な理由がこれである (§6 A-1)。
3. **phototrophyが「利益」になる前提条件を作る。** 現在の世界ではH2は空間的にも時間的にも常時利用可能で、維持break-evenは世界の99.9%で満たされる (baseline)。つまり **phototrophyは「あれば得だが無くても困らない」追加ボーナスにしかならない。** 選択によって定着するかを問うなら、H2が時間的に枯れる局面が必要である。dynamic ventはそれを作る。
4. **実装が安い。** vent寿命 / flux変動 / vent新生・消滅は、新しいstate variableをほとんど増やさずに書ける。深度・圧力・移流まで入れる必要はない。

## R-11 【降格】temperature (Phase 2) と pH/chemiosmosis (Phase 4)

### temperature: Phase 2 → carbon と ecology の後へ

降格理由:

- 新しい資源軸も新しい戦略も作らない。既存の全レートにArrhenius係数を掛ける操作である。
- 一方でcalibration面積が大きい (uptake / maintenance / damage / 膜安定性それぞれのQ10)。実装コスト・実験コストともに高い。
- 2 cm四方の世界に意味のある温度勾配を置くには、vent plumeのモデル化が要る。世界スケールの問題と絡む。
- LUCAの好熱性は学術的に未決着で、ここで契約すると後で戻りにくい。

捨てる必要はない。ただし「熱水噴出孔なんだから温度が要る」というのは美観の問題であって、現在のボトルネックではない。

### pH / ion gradient / chemiosmosis: mainstreamから外し、on-demand扱いへ

これはロードマップ中で**費用対効果が最も悪い項目**だと考える。

- 得られるのは既に持っている量 (`h2_usable_energy_j_per_mol`) の下位からの再導出であって、**個体にできることは何も増えない。**
- 実装は重い: 膜state、pH場、勾配収支、ATP合成の結合効率。
- 進化的な狙い (「エネルギー共役効率が進化する」) は、**遺伝子1本で買える。** `h2_usable_energy_j_per_mol` に掛かる無次元の共役効率geneを置き、膜維持コストとtrade-offさせれば、chemiosmosisレイヤー無しで同じ選択圧が作れる。

推奨: Phase 4 を「共役効率gene + 膜コストのtrade-off」に置き換え、完全なchemiosmosisは **abiogenesis trackの課題** として送る (原始的プロトン勾配を一次エネルギー源とする議論は、本来そちらの文脈である)。

## R-12 【昇格 / 新設】代謝副産物 (acetate) によるcross-feeding

Phase 6 の候補リストに埋もれているが、**HGTより優先度が高く、実装が安い。**

- モデルしている代謝はまさに `4 H2 + 2 CO2 -> acetate` である。産物が消えている今の状態のほうが不自然。
- 場を1つ増やすだけ (既存のH2場と同じ機構が使える)。
- **生物自身が作った初めての資源**になる。これは「生命が環境を変える」最初の一歩であり、このプロジェクトの長期目標の中核に直結する。
- acetate利用者が出れば、設計者が置いていない最初の生態的niche分化になる。

Phase 6 を分割することを推奨する。

```text
6a  competition / carrying capacity    -> R-9 (Phase 3a) へ統合
6b  metabolic byproducts / cross-feeding -> 昇格。安く、価値が高い
6c  HGT                                 -> 複数戦略成立後。現在の位置で正しい
6d  predation unlock                    -> 独立した大きな軸。単独phase
```

# 6. 追加すべき実験

## A-1 Exp15 Phase B — 期待される結果を事前登録する

Phase B自体は妥当なので実施すべき。ただし**結果の読み違いを防ぐため、事前に以下を登録しておく**ことを推奨する。

実測から分かる各遺伝子の可動域:

```text
E_max (storage_capacity=1.0) = 1.56e-11 J = full-activity 10.0 時間分
1分裂のEnergyコスト           = 4.49e-10 J = E_max の 28.7 倍
```

したがって:

- `storage_capacity` は**繁殖のためのエネルギー貯金には原理的に使えない** (最大遺伝子値5.0でも1分裂コストの17%)。使えるのはH2-poor領域の通過中の延命だけ。
- 一方、**夜を越えるには既定値で十分**である (10時間分 + 飢餓時代謝抑制)。将来phototrophyが出ても、H2が夜も利用可能である限り夜は圧にならない。
- したがって Phase B で `storage_capacity` に強い方向性選択が出ないのは**失敗ではなく予測される結果**である。

これを先に書いておかないと、弱い結果が出たときに「機構が働いていない」と誤診し、環境を触りたくなる。V1.8で一度通った道である。

## A-2 環境追加ごとの「生息可能率」事前スクリーニング【最も費用対効果が高い】

§1.5。生物不在の定常場と参照個体の収支だけで、全滅条件と飽和条件を事前に外せる。

新しい環境軸を入れるたびに、**シミュレーションを走らせる前に**これを計算することを標準手順にする (`環境因子追加・校正方針` §5 の手順へ挿入)。Exp16規模の探索を10分の1のrun数で設計できるようになる。

## A-3 carrying capacity / steady-state実験

Exp16 §7.3 が自ら認めているとおり、10日runは平衡ではない。R-2でMatter sourceを入れた後、**1条件・少seed・長期間**で:

- 個体数が平衡に達するか
- 平衡がMatter律速かEnergy律速か
- `max_population_halt` に触れずに平衡へ到達するか

を確認する。多条件は不要。1–2条件 × 3 seedで十分。

## A-4 Phase 1 は「供給」と「定着」を分けた2アームにする

§3 R-8のとおり、innovation供給が薄すぎて統計が取れない。

```text
Arm S (supply)       innovation ON、確率は据え置き
                     -> 「自然に出現しうるか」を問う
Arm E (establishment) t=0 に少数のphototrophを配置

```

Arm E は統計的検出力が桁違いに高く、**選択の話と変異供給の話を混同しない**。「設計者がphototrophを置いた」ことにはならない (置いたのは初期条件であって、適応度関数ではない)。`絶対設計原則` に抵触しない。

2はExp15 Phase Bと同じ設計をdynamic環境で回すだけなので、追加コストは小さい。

### Q2. Phase B → Origin Audit → mutation/innovation audit という順は妥当か

**順序を入れ替えることを推奨する。**

```text
現在: Phase B -> Origin Audit -> mutation audit
推奨: mutation audit (机上、1時間) -> workflow gate修正 -> Phase B -> Origin Audit
```

理由:

- mutation auditは計算だけで終わり、しかも **Phase 1が実行可能かどうかを決める** (§3 R-8)。最も安く、最も情報量が多いので先にやる。
- workflow gateの修正はPhase Bの前提。かつ R-3 の恒久修正を同時に入れる。
- Phase B の事前登録に A-1 を含める。

Origin Auditの内容自体 (5形質・粗い感度・最適値探索をしない) は妥当。**スコープを17形質へ広げないこと。**

### Q3. `長期ロードマップ` のPhase順序は妥当か

```text
推奨: 3a Matter閉じ -> 5 dynamic vent -> 1 phototrophy -> 6b cross-feeding
      -> 3b carbon -> 6c HGT -> 2 temperature -> 7 oxygen -> 8-10 (変更なし)
      (4 pH/chemiosmosis は mainstream から外し、遺伝子1本の共役効率へ縮約)
```

Phase 7以降 (oxygen → complexity → land → flight) は現状のままでよい。特に oxygen は「生命が地球環境を変える」最初のイベントで、このプロジェクトの長期目標の中で科学的価値が最も高い。そこへ至る依存鎖 (non-oxygenic phototrophy → oxygenic innovation → 酸化還元収支) を壊さないことが重要。
