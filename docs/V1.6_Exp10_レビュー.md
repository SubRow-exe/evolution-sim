## 0. 総評

設計思想（temporal sensing、未来予測なし、turn rateだけを偏らせる）は、
プロジェクト絶対原則12「行動に暗黙の知能・未来予測を勝手に導入しない」に対して
**現行V1.5より明確に強い適合**であり、方向性は支持する。
将来拡張（設計案 §7 の有限センサー + 測定ノイズ + 維持コスト）も原則8/10と整合する。

ただし実装前に潰すべき**前提のずれが2つ**ある。いずれも実測して初めて分かったもので、
案の記述と現在の世界の実挙動が食い違っている。

- A-1: V1.5は実世界では既に「ほぼ動いていない」
- A-2: 場が階段状なので `ΔQ` が原理的にほぼ常に厳密0

この2点を反映しないままExp10を走らせると、主仮説1/2/5/6のいずれも検証できない。

## 1. 用語

本書で使う語を先に定義する（`docs/実験結果保存方針.md` §5）。

- **`sensory_range`（感覚範囲遺伝子）**
  個体の感覚半径を決める進化可能な遺伝子。感覚半径 [wu] = `sense_coef × sensory_range`。
- **`cr`（走査セル半径）**
  `int(感覚半径 / cell_size)`。`cr = 0` なら走査対象は自分が乗っているセルだけになる。
- **`Q`（統合環境評価値）**
  設計案が導入する、各刺激の無次元応答と利用能力から作る現在環境の評価値。
- **`ΔQ`**
  `Q_now - Q_past`。正なら環境改善、負なら悪化。
- **piecewise constant（階段状）**
  値がセル内で一定で、セル境界でのみ不連続に変わる場のこと。
  現行の light / chemical はこれに該当する。
- **定位保持（station keeping）**
  好条件の地点に留まり続けること。現行V1.5は `stay` 分岐でこれを行う。

## A. 実測で判明した前提のずれ（要対応）

### A-1. V1.5は実世界では既に「ほぼ動いていない」

設計案 §1 は「V1.5の移動判断は依然として winner-take-all 型である」としているが、
Exp09本番runの実測は次のとおりである。

| 条件 | `mean_move_per_org_tick` 全期間max [wu/tick] | 非ゼロ区間 | `sel_walk` 計 |
|---|---:|---:|---:|
| a_light_only_lightspec | **0.000000** | 0/250 | 0 |
| b_chem_only_chemspec | 0.006168 | 17/250 | 124 |
| c_mixed_lightspec | **0.000000** | 0/250 | 0 |
| d_mixed_chemspec | 0.020049 | 99/250 | 0 |
| e_mixed_generalist | **0.000000** | 0/250 | 0 |

a / c / e は **5,000 tick全区間で移動量が厳密に0**である。

原因は感覚半径とセルサイズの関係にある。

```text
sensory_range default = 0.4
感覚半径 = sense_coef(25.0) × 0.4 = 10.0 wu
cell_size = 20.0 wu
cr = int(10.0 / 20.0) = 0   → 走査対象は自セルのみ
```

さらに最終snapshotを全条件で数えると、
**1,201個体すべてが `sensory_range ≤ 0.546`**（`cr ≥ 1` に必要な0.8に誰も届いていない）。

| 条件 | 個体数 | `sensory_range` min | max | `≥ 0.8` の個体 |
|---|---:|---:|---:|---:|
| a_light_only_lightspec | 310 | 0.299 | 0.546 | 0 (0.0%) |
| b_chem_only_chemspec | 99 | 0.338 | 0.456 | 0 (0.0%) |
| c_mixed_lightspec | 303 | 0.288 | 0.519 | 0 (0.0%) |
| d_mixed_chemspec | 187 | 0.334 | 0.461 | 0 (0.0%) |
| e_mixed_generalist | 302 | 0.305 | 0.518 | 0 (0.0%) |

`cr = 0` だと `_scan` の返す最良セルは必ず自セルであり、`_is_current` が真になって
`stay = True` → `decide_and_move` は 0.0 を返す。つまり**選択はしているが動かない**。

なお b / d に残るわずかな移動の発生源は特定できていない
（死骸・捕食由来のflowは全条件で0だった）。いずれにせよ
0.02 wu/tick = 0.001 cell/tick であり、走性としては無視できる水準である。

#### 帰結1: 設計案 §1 の位置づけが不正確

V1.6は「探索則の置き換え」ではなく、**実質固着から遊泳への転換**である。
変更の大きさは案が想定しているより一段大きい。§1をこの前提で書き直すべき。

#### 帰結2: Exp10 §4 の対照Bが対照Aと別物にならない

現状のV1.5は「動かない」ので、

```text
A. pure random walk
B. V1.5 winner-take-all   ← 実際には「ほぼ動かない」
C. V1.6 temporal integration
```

の3方式比較が実質2方式比較に潰れる。
対照Bを意味のある比較対象にするには、診断用に `sensory_range` を大きく固定する
（例: 1.6 → 感覚半径40 wu → `cr = 2`）必要がある。
これは事前登録に明記すべき条件であり、書かなければ
「V1.6はV1.5より良い」という結論が**対照の設定ミスに由来してしまう**。

#### 帰結3: Exp09が検証したのは比較の算術であって走化性ではない

Exp09の24,470,222回の「選択」はすべて自セルを指しており、行動としては現れていない。
これは `docs/Exp09_結果考察.md` の限界としても記載すべきなので、
本レビューと同時に同文書へ追記した（§5.8 / §6.2）。

### A-2. 場が階段状なので `ΔQ` が原理的にほぼ常に厳密0

これが本レビューで最も重い指摘である。

- light も chemical も**セル単位の定数**（`light` は `(40, 40)` 配列。セル内は完全に一定）
- wander速度 = `v_max × wander_speed_frac` ≈ **0.83 wu/tick**（Exp09中央個体で実測）
- `cell_size = 20.0 wu` → **1セル横断に 24.1 tick**

したがって同一セルに留まる約24 tickの間、`Q_now - Q_past` は**厳密に0**になる。

memory time候補 {1, 3, 10, 30} tick に対して、
**約96%のtickで `ΔQ = 0`、残り4%で階段状にジャンプ**する。

参考値（vertical light、`light_absorption = 2.0`）:

```text
隣接セルの light 差       0.0210 (勾配一定なので全域で同じ)
同 response 差            0.00672
セル1つ跨いだ時の ΔQ      0.01343   ← 24 tickに1回だけ発生
```

設計案 §5.1 の memory time スイープは、この状態では
「勾配をどう測るか」ではなく「セル境界をどれだけ拾うか」を測ることになり、
Exp10の主仮説1 / 2 / 5 / 6 のいずれも検証できない。

#### 対策候補

| 案 | 内容 | 評価 |
|---|---|---|
| **知覚だけ双線形補間** | 刺激は連続座標で補間し、**吸収はV1.4のままセル単位**に保つ | **推奨**。吸収物理を一切触らずに `Q` が空間連続になる |
| `cell_size` を下げる | 40×40より細かいグリッドにする | V1.4のdefault校正（`light_uptake_coef` / `chem_vent_flux`）がやり直しになる |
| 移動速度を上げる | `wander_speed_frac` / `speed_coef` を上げる | 移動コスト・損傷が増え、副作用が大きい |

#### 原則9（1軸ずつ）との関係

補間は「知覚モデルの変更」そのものなので、V1.6は

```text
(i)  知覚の連続化
(ii) 時間比較による turn rate 変調
```

の**2つを不可分に束ねる**ことになる。
winner-take-allのままでは補間に使い道がないため、実際には(i)だけを先行導入して
効果を測る、という分離ができない。

したがって「V1.6は2つの変更を含む」ことを後から発見するのではなく、
**設計案に最初から明記し、Phase 0で(i)と(ii)を個別に検査する**のが正しい扱いだと考える。

## B. 設計上の要判断（5件）

### B-1. 加算 `Q` では能力が「食べられる量」と「走性の強さ」を兼ねる

設計案 §4 の第一候補は単純加算である。

```text
Q  = Σ aᵢ Rᵢ
ΔQ = Σ aᵢ ΔRᵢ
```

能力 `aᵢ` が2倍になれば `ΔQ` も2倍になり、turn rate の変調も2倍になる。

- lightspec (2.0) は generalist (1.0) の**2倍強い走性を、機構ではなくスケールだけで**得る
- よって Exp10 §9 主判定2
  「E2/E3で対応刺激の利用能力が高い表現型ほど高Q領域へ偏る」は
  **構成上ほぼ自明に通る**。検証ではなく「構成の確認」と位置づけを変えるべき
- `response_gain` が表現型と交絡する。単一のgain値が3表現型で同じ意味を持たないため、
  Phase Aのgain掃引は表現型ごとに別の最適点を持つ

#### 対策候補

1. `ΔQ` を `Σ aᵢ` で正規化する（能力は「何を食べられるか」だけを決める）
2. 相対変化 `ΔQ / (Q_past + ε)` を使う
3. 表現型ごとに `response_gain` を事前登録し、交絡を明示したうえで比較しない

どれを取るかは設計判断であり、Claude側では決めない。
ただし**何も決めずにPhase Aを走らせると、gainの最適領域が表現型ごとにずれて
「広いパラメータ領域で成立する」という主仮説7の判定が濁る**。

### B-2. `Q` 水準はlight支配だが、`ΔQ` はvent縁でchemical支配

Exp09実測（選択時のlight応答 0.40〜0.44 / chemical応答 0.001〜0.11）から、
generalistの **`Q` 水準に占めるchemicalの寄与は約1.4%** にすぎない。

しかし `ΔQ` で見ると逆転する。

```text
light   : セル1つ分の段差        1.0 × 0.0067 = 0.0067
chemical: vent縁で stock 0→0.5   1.0 × 0.039  = 0.039    ← こちらが大きい
```

つまり複数刺激統合の効果は **vent縁の局所現象**として現れる。
vent は 13セル / 1,600セル = **世界面積の0.8%** しかない。

Exp10 §9 主判定5 / §11.3 を**世界全体の平均**で判定すると、
統合が正しく効いていても検出できずに落ちる。

→ **vent境界近傍に限定した層別観測**（vent中心からの距離帯ごとの
`ΔQ` 内訳・turn率・滞在率）を事前登録すべき。

### B-3. corpse / predation / nutrient の扱いが未定義

現行 `behavior.py` は死骸と捕食対象を**座標で直接ターゲティング**する。

```python
score = g[CORPSE_DIG] * c.matter
if score > best_score:
    target = (c.x, c.y)      # 死骸の実座標へ直行
```

一方、設計案の `Q` は light と chemical しか含まない。
このままだと

```text
一次Energy : 反射的な biased random walk
捕食・死骸 : 座標を知って最適追跡
```

という非対称が残る。**原則12の観点では、むしろ捕食側の方が問題が大きい**状態になる。

次の3択を設計案で選び、理由を書くべき。

- (a) 一次Energyのみ変更し、非対称を当面許容する（理由を明記）
- (b) 全刺激を `Q` へ統合する（スコープ拡大。Exp10の環境設計も変わる）
- (c) 段階導入とし、V1.6のスコープが一次Energyに限ることを明記する

### B-4. 「その場に留まる」ができなくなる

temporal walk は turn rate しか変えられないので**定位保持ができない**。
これは run-and-tumble として生物学的に正しい挙動だが、収支へ効く。

Exp09の中央個体（matter 1.186 / movement_power 0.502 / movement_efficiency 0.998）での実測:

```text
現在の維持費 (移動なし)   0.5536 E/tick
  bmr        0.3410
  organ      0.1811
  sense      0.0032
  membrane   0.0164
  resist     0.0119

毎tick wander した場合    +0.0410 E/tick  → +7%
移動損傷                  +0.00409 /tick  → 代謝損傷 0.02373 に対し +17%
```

+7%それ自体は致命的ではない。

ただし **chemical-only条件はExp09時点で既に最弱**である
（最終pop中央値101 / vent滞在率1.000への依存）。
定位保持を失えばvent滞在率が崩れ、条件が成立しなくなる可能性が高い。

→ 現行の満腹時停止（`satiety_energy_frac = 0.85` で移動0）を残すかを明記し、
**chemical-only条件の成立性の再確認をExp10の停止条件に入れる**ことを推奨する。

### B-5. `v1.5-final` の保存が計画に無い

V1.4 → V1.5 では `v1.4-final` を先に保存し、
単独source完全一致（`verify_vs_ref --single-source`）で退行を保証した
（`AGENTS.md`「V1.5実装前に必ず行うこと」）。

設計案 §8 は「V1.4/V1.5との bit 完全一致は要求しない」とだけ書き、
**V1.5再現手段の保存に触れていない**。

同じ手順を明記すべき。

```text
v1.5-final を保存
↓
CI結果不変性の基準refを移行
↓
V1.6着手
```

## C. Exp10計画の実務的問題（3件）

### C-1. E0 / E1 / E5 / E6 は現行worldでは作れない

| 環境 | 不足しているもの |
|---|---|
| E0 no stimulus | 光0・chemical0では個体がnutrient/死骸依存になる。**偽バイアス検定は進化・死亡を止めた固定個体群の短時間診断にすべき**（生態runでやると弱った集団で「ドリフトが無いこと」を見ることになる） |
| E1 uniform stimulus | chemical の一様源が無い（chemicalはventのみ） |
| E5 conflict | ventは `rng.integers` による乱数配置。暗部への決定的配置オプションが必要 |
| E6 orthogonal | `light_pattern` は `vertical` / `uniform` / `high_contrast_vertical` のみで、**すべてy方向にしか変化しない**。x方向勾配の新patternが必須 |

world側の実装追加が前提になるので、**Exp10のスコープに入れて事前登録**すべき。
「実験計画にあるが実装が無い環境」を後から足すと、条件の事後変更になる。

### C-2. 計算量が案のままだと budget を大きく超える

Exp09本番の実測コストは次のとおり。

```text
1 run ≈ 2.2 core-min   (5,000 tick / 最終pop ~300 / tick_ms ≈ 27)
Exp09全体 25 run = 0.94 core-hour
```

これを基準に案の規模を見積もる。

| 対象 | run数 | 実行量 | 20並列での実時間 |
|---|---:|---:|---:|
| Phase A「36組 × 4環境 × 3表現型 × 3 seed」 | 1,296 | 48.6 core-h | 2.4 h |
| Phase B 下限（10 seed / 20,000 tick） | 630 | 94.5 core-h | 4.7 h |
| Phase B 上限（30 seed / 50,000 tick） | 1,890 | **708.8 core-h** | **35.4 h** |
| Phase C（3強度 × 3対象）をPhase B下限へ | 5,670 | **850.5 core-h** | **42.5 h** |

いずれも **populationの増加を無視した下限**である。
Exp09のpopulationは5,000 tick時点でまだ増加中だったので、
20,000〜50,000 tickでは実際のコストは数倍になる。

§13 の「10時間程度」に収まるのは Phase B 下限だけである。
主因は **Phase A の「合計36組」に環境 × 表現型 × seed の掛け算が書かれていない**こと。

#### 縮約案

- Phase A: seed 1、環境は E2 / E3 の2つへ絞る（36 × 2 × 3表現型 × 1 seed = 216 run ≈ 8 core-h）
- Phase B: tick を 10,000 に、seed を 10 に固定
- Phase C: Phase Bを通過した**最終1候補のみ**

### C-3. Green条件4に効果量・統計規則が無い

§14-4「E2/E3でrandom walkより高Q領域滞在率が改善する」は、
閾値と判定規則を事前に決めないと事後判断になる。

Exp09は主判定が「1.0000か否か」という二値だったのでこの問題が出なかったが、
Exp10は連続量の比較である。

→ seed数と効果量を事前登録する。例:

```text
高Q領域滞在率の差 (V1.6 - random walk) が
  全seedで符号一致し、かつ中央値で X ポイント以上
```

X の値は人間が決める。Claude側では決めない。

## D. 良い点

- **原則12への適合が V1.5 より明確に強い。**
  周囲を走査して最大値セルへ直行する現行より、temporal sensing の方が思想に合う。
- Phase 0 の12項目は妥当。とくに
  「winner-take-all分岐が新方式では使われない」
  「吸収量計算がV1.5以前から変化していない」
  は良い停止条件である。
- §15「Exp10が答えないこと」の明示は Exp09 と同じ良い作法。
- **実装のヒント**: 現行のrandom walkは既に
  `org.heading += sim.rng.normal(0.0, cfg.wander_turn_sigma)` の形をしている。
  新しい二値のturn確率を導入せず、

  ```text
  sigma_eff = wander_turn_sigma × f(ΔQ)
  ```

  として既存機構を変調するだけで済む。
  この形なら設計案 §5.4 の最低条件
  「単調」「確率が0〜1に収まる」「ΔQ=0でbaselineへ戻る」「数値不安定にならない」
  が自動的に満たされ、新規パラメータは `f` のgain1つで済む。

## E. 推奨する順序

1. `v1.5-final` を保存し、CI基準refを移行する（B-5）
2. 設計案へ **A-1（V1.5は実質固着）と A-2（ΔQがほぼ常に0）** を反映し、
