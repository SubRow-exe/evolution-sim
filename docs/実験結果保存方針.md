# 実験結果の保存・可視化方針

更新: 2026-08-31

目的: GitHubだけを見ても主要な結果・空間挙動・考察を短時間で確認できる状態を保ちつつ、全生データをGit履歴へ入れてリポジトリを肥大化させない。

## 1. 保存先の役割分担

### GitHubへ必ず残す

各正式実験の結果確定後に以下を保存する。

1. `docs/ExpXX_結果考察.md`
   - 目的
   - 条件
   - 健全性チェック
   - 主結果
   - 解釈
   - 何を結論できるか / できないか
   - 次の判断
2. `experiments/<exp_id>/NOTES.md`
   - 実行run / commit / seed / tick / 環境
   - 主要な実測値
   - 外部生データの保存先
3. `experiments/<exp_id>/figures/`
   - 集計プロット
   - 代表的な空間GIFまたは最終PNG
   - `README.md`（各図が何を示すか、代表seedを選んだ理由）

### Google Drive / Actions artifactへ残す

- 全runの`stats.csv`
- 全snapshot / environment
- 全PNG / 全GIF
- events.csv等の容量が大きい詳細ログ
- 圧縮生データ

GitHubは「読める結果」、外部ストレージは「完全な生データ倉庫」とする。

## 2. 集計プロット

結果確定時に、実験の判定に使った主要指標を原則3〜8枚程度保存する。

例:
- パラメータ vs 生存率
- パラメータ vs 最終population
- populationの時間推移
- Energy / Matter収支
- resource利用率 / stock
- 重要形質の分布

プロットは`docs/ExpXX_結果考察.md`から相対パスで直接表示する。

## 3. 代表GIF / PNG

全runをGitへ入れない。

原則3〜6本程度を選ぶ。

選定は結果を都合よく見せるために行わず、以下の順で機械的・説明可能にする。

1. 主要条件のanchorとして固定seed（原則seed1）
2. 必要なら各条件の中央値に近いrun
3. 明確な外れ値・想定外戦略は「例外例」と明示して追加

`figures/README.md`へseed・条件・選定理由を書く。

目安:
- 1 GIFはできれば5 MB以下
- 1実験のGitHub可視化成果物は概ね25 MB以下を目標
- 超える場合はfps/解像度/フレーム数を下げるか、代表PNGへ置換

## 4. Claude Codeの必須手順

Claude Codeが正式実験の結果整理・結果確定を担当する場合、**テキストの結果だけ保存して終了しない**。

実験完了後は必ず:

1. health / condition / environment checkを確認
2. `docs/ExpXX_結果考察.md`を作成または更新
3. `experiments/<exp_id>/NOTES.md`を作成または更新
4. 集計プロットを生成して`figures/`へ保存
5. 代表GIF/PNGを厳選して`figures/`へ保存
6. 結果考察Markdownへ図を埋め込む
7. `figures/README.md`へ代表runの条件・seed・選定理由を記録
8. 全生データはGitへ追加せず、Google Drive / Actions artifactの保存を確認
9. `git status`とファイルサイズを確認してからcommit / PR

可視化が不要な実験の場合は省略してよいが、結果考察に「なぜ不要か」を明記する。

## 5. 用語の書き方

新しい略語・パラメータ・専門用語を結果文書へ初めて出すときは、その場で日本語の意味を説明する。

例:
- `light_uptake_coef`（光吸収速度係数）
- `chem_vent_flux`（1つのchemical噴出口が1 tickに供給するEnergy量）

パラメータ名だけで説明を済ませない。
