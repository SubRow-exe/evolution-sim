# 操作ガイド — GUIの見方と結果レポートの読み方

## 1. 起動

```
cd C:\Project\evolution_sim
python -m uv run python main.py --seed 42        # GUI起動
python -m uv run python main.py --headless --ticks 100000 --seed 1   # 描画なし高速実験
```

`--seed` を省略すると毎回ランダムなseedになる（seedは画面とmeta.jsonに表示・記録される）。

## 2. 画面の見方

```
┌────────────────────────────┬──────────┐
│                            │ tick     │ ← 経過時間
│      世界 (800×800)         │ pop      │ ← 現在の個体数
│                            │ births   │ ← 累積出生数
│   ● ● ●   ○               │ deaths   │ ← 累積死亡数(死因別内訳付き)
│      ●  ●                 │ corpses  │ ← 死骸の数
│                            │ lineages │ ← 現存する系統の数(初期100)
│                            │ max gen  │ ← 最大世代数
│                            │ seed     │ ← 再現用シード
└────────────────────────────┴──────────┘
```

### 背景色の意味(環境フィールド)

| 見た目 | 意味 |
|---|---|
| 上が明るく下が暗い | **光の強さ**。北(上)ほど光エネルギーが多い |
| 緑っぽいセル | **無機栄養**(身体の材料)が豊富。食べられると暗くなり、拡散でゆっくり回復 |
| 紫っぽいセル | **化学エネルギー噴出口**(熱水噴出口に相当)。4箇所ある |

### 個体(塗りつぶし円)

- **大きさ** = 実際の身体サイズ(身体物質量)
- **色 = 栄養戦略**(遺伝子から生成):
  - **緑が強い** = 光合成寄り(植物的)
  - **赤が強い** = 捕食寄り(動物的)
  - **青が強い** = 死骸分解寄り(分解者的)
  - 初期個体は全員ほぼ同じ灰緑色。**世代を重ねて色が分かれてきたら、それが栄養戦略の分化**
- **灰色の輪(塗りなし)** = 死骸。時間とともに分解されて栄養(緑)に還る

### 観察のコツ

- x100(キー3)で数千tick回して、色・分布・サイズの変化を見るのが基本
- 光の強い北側に緑系が集まる、栄養の濃いセルに個体が群がる、などが見えれば選択が働いている
- サイドバーの `lineages` が減っていく = 系統の自然絶滅。`deaths` の内訳で世界の死因構成が分かる

## 3. キー操作

**注意: キーはシミュレーションウィンドウをクリックしてフォーカスがある状態で効く。**
押したキーはサイドバーの `last key` に表示され、実行結果は画面上部の黒いバーに表示される。

| キー | 動作 |
|---|---|
| SPACE | 一時停止 / 再開 |
| 1 / 2 / 3 | 速度 x1 / x10 / x100 (テンキー可) |
| G | **グラフPNGを生成して保存**し、保存フォルダをエクスプローラーで開く |
| D | 災害発生(個体の90%をランダム死亡) → ボトルネック効果の観察 |
| R | 新しいseedでリセット(新しい実行として記録される) |
| ESC | 終了 |

Gキーは「グラフ画面を開く」のではなく「PNGファイルを書き出す」機能。生成中は1〜2秒画面が止まる。

## 4. 結果レポートの出力構造

実行するたびに `runs/<日時_seed>/` が作られ、以下が自動記録される:

```
runs/20260827_111523_seed42/
├─ config.json     全パラメータ(この実行の完全な条件)
├─ meta.json       seedとバージョン → config+seedで誰でも完全再現できる
├─ events.csv      全イベントの生ログ(1行=1イベント)
│                    birth: tick, 個体ID, 親ID, 系統ID, 世代
│                    death: tick, 個体ID, 死因, 年齢
│                    → 系統樹の再構築や寿命分析の元データ
├─ stats.csv       20tickごとの集計(時系列分析の主データ)
│                    個体数 / 死因別死亡数 / 総エネルギー / 総生体量 /
│                    栄養・化学・死骸残量 / 平均・最高年齢 / 系統数 /
│                    資源フロー累積(経路別の獲得量) / 最大系統のシェア /
│                    全14遺伝子の平均と分散
├─ lineages.csv    系統別統計(上位8系統)
│                    人口・シェア・累積出生数・代表遺伝子の平均
│                    → 特定系統が集団を席巻しているかの判定用
├─ performance.csv 計算性能ログ(tick時間・個体数・処理速度)
├─ snapshots/      2000tickごとの全個体の完全な状態
│                    (位置・エネルギー・損傷・全遺伝子) → 分布・ヒストグラム用
└─ plots/          Gキーまたは plot_run で生成されるグラフPNG
```

### グラフ(plots/)の見方

| ファイル | 内容 |
|---|---|
| population.png | 個体数・死因別累積死亡・年齢・系統数の時系列。災害は赤破線 |
| genes.png | **一番重要**。全14遺伝子の平均±標準偏差の時系列。右肩上がり/下がりの遺伝子=選択が働いている形質。帯が広がる=多様化 |
| budget.png | エネルギーと物質の収支。TOTAL(黒点線)が水平なら物質保存が正常 |
| histograms.png | 最新スナップショット時点の遺伝子分布。山が2つに割れたら戦略分化のサイン |
| resources.png | 経路別の資源獲得レート。**灰点線の未利用光**が大きい=まだ開拓余地があり個体数が増え得る |
| lineages.png | 上位系統の人口シェア。1本が上昇し続ける=特定系統による席巻 |
| spatial.png | 個体の空間分布(色=戦略)と緯度ごとの平均戦略値。空間的ニッチ分化の確認用 |
| performance.png | 計算コスト(ms/tick)と個体数の関係。最適化の判断材料 |

### 事後のグラフ生成・分析

```
python -m uv run python tools/plot_run.py runs/<run_id>
```

stats.csv / events.csv / snapshots はすべて普通のCSVなので、Excel・pandas等で自由に分析できる。

## 5. 個体数の安全停止

個体数が増えすぎると計算が事実上停止するため、`max_population_halt`(既定 20000)に達したら
**自動保存して停止**する(ヘッドレス)か**一時停止**する(GUI)。

これは個体を殺す処理ではない。「個体数を人為的に抑制しない」という設計原則を守るため、
世界のルールには一切干渉せず、実行を止めて記録を残すだけの安全装置である。
上限を変えたい場合は config.json の `max_population_halt` を編集する(0で無効)。

## 6. 実験結果をGitHubに残す

残す価値のある実行は `runs/` から `experiments/expNN_<名前>/` へコピーし、
`NOTES.md`(目的・結果・考察)を添えてコミットする。書式は `experiments/exp01_baseline_20k/` を参照。
`runs/` 自体は .gitignore で除外されている(seedがあれば再現できるため)。
