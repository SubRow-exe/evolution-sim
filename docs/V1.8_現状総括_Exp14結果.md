# 1. V1.8で何を変えたか

V1.8の目的は、lightとchemicalを単なる「同じEnergyの別field」ではなく、性質の異なる一次Energy源として扱うこと。

狙う構造:

```text
light
- 世界へ広く分布するrenewable flow
- 局所fluxは比較的薄い
- 表面積と局所強度に依存して取得
- 昼夜により周期的に0になる
- 未使用分はstockとして残らない

chemical
- vent近傍へ局在するstock
- 高密度なら高い局所取得速度を持ち得る
- 生物が使うと減る
- 個体間で奪い合う
- geological sourceから再供給される
```

V1.7からV1.8でlight/chemical Energy収支に直接効く主要変更は2つ。

## 1.1 昼夜cycle

```text
light_cycle_enabled
period
light_day_fraction
half-sine daylight factor
```

period=200 / day_fraction=.5なら:

```text
100 tick daylight
100 tick night
```

同じ`light_max`でもenergy中立正規化は行わず、一周期平均factorは約0.318。
したがってV1.7の静的light世界より平均供給量は低くなる。

## 1.2 一次Energyの局所密度依存吸収

light / chemical直接吸収へ:

```text
H(x,K)=x/(x+K)
```

を追加した。

lightでは:

```text
raw uptake
  ∝ light_absorption
  × effective_surface
  × H(local_light, light_uptake_half)
```

となる。

したがってV1.8では、**夜を消しただけでもV1.7へ戻るわけではない。**
`primary_energy_density_response=True`なら、薄い光ではV1.7より実効吸収速度が低くなり得る。

逆にV1.8で変更していない主要項目:

- BMR式 (`bmr_core=.15`)
- `E_max = energy_capacity × matter`
- reproduction式
- movement式
- damage / repair
- nutrient物理
- mutation式

# 2. Exp13総括

## 2.1 Light calibration

light sweep:

```text
light_max = 0.8 / 1.2 / 1.5 / 1.8 / 2.1 / 2.4 / 3.0 / 4.0
5 seeds each
```

全水準で10k前に絶滅。

`light_max=4.0`でも典型的に:


よってExp13は`LIGHT_CALIBRATION_FAIL / REVIEW`として科学STOPした。
これはtechnical crashではなく、選定可能なlight成立条件が事前sweep内に存在しなかったためのSTOP。

Chemical gridは完走。

現時点の暫定第一候補:

```text
chemical_uptake_half = 1.5
chem_uptake = 0.5
```

ただしこれはV1.8恒久defaultではない。
Light問題整理後に長期成立・探索・density挙動を再確認する。

# 3. Exp14の目的

Exp13 light絶滅について、単純な光量不足ではなく:

```text
1. 連続暗期が長すぎる
2. Energy storageが不足する
3. tick1一斉繁殖がreserveを削る
4. light総量不足
```

を切り分けるためExp14を実施。

さらに約10時間枠を使い:

- Phase A: mechanism診断
- Phase B: period × energy_capacity map
- Phase C: evolutionary rescue probe

の計116 formal runsを事前登録した。

116/116 runは技術的に正常回収された。
実行が想定より非常に短かった主因は、多くのrunが予定tick前に早期絶滅したため。

# 5. Exp14 Phase A結果

各armの平均絶滅tick概略:

| arm | 変更 | 平均絶滅tick | 解釈 |
|---|---|---:|---|
| A0 | baseline | ~150 | Exp13型collapse再現 |
| A1 | cycle OFF、平均供給相当light | ~384 | 暗期除去で大幅延命。ただし最終絶滅 |
| A2 | period 200→80 | ~128 | absolute tickは短いが最初の夜越し能力は大幅改善 |
| A3 | light_max 4→8 | ~160 | 光量2倍だけではほぼ救済しない |
| A4 | repro threshold .6→.8 | ~190 | tick1繁殖抑制＋reserve増で改善 |
| A5 | initial_energy 50→40 | ~171 | 初期Energyを減らしても延命＝tick1繁殖は増悪因子 |
| A6 | capacity100→200、initial E50→100 | ~302 | storage増加で最初の夜を越えやすくなる |

## 5.1 夜は明確に悪影響

A1はA0より大幅に寿命が延びた。
したがって「連続暗期が大きな負荷」という仮説は支持される。

A2/A6でも、R_refを下げる方向へ変更すると最初の夜明けへ到達する個体が増えた。

## 5.2 R_refの現在評価

```text
R_ref = night length / reference reserveで耐えられるnight ticks
```

Exp14ではおおむね`R_ref ≲ 0.45`付近から最初の夜越しが可能になった。

したがってR_refは:

> **「一晩を越せるか」の診断指標としては有用**

と考えられる。

ただしR_refが非常に小さい条件でも長期生存・継続繁殖には至らなかった。
したがって:

> **R_refは長期fitness / 生態系成立指標ではない。**

## 5.3 tick1一斉繁殖は増悪因子

baseline初期条件では:

```text
initial matter = .8
energy_capacity =100
Emax =80
repro threshold=.6×80=48
initial energy=50
```

なので開始直後から繁殖可能。

A5ではinitial energyを40へ下げ、tick1繁殖のみ抑制したところ、Energyが少ないにもかかわらず寿命が延びた。

よって:

```text
tick1一斉繁殖
→ Energy/Matterを親子へ分配
→ 個体数増加でcore maintenance等の総負担増
→ 夜前reserve悪化
```

は明確な増悪機構。

ただしA4/A5も最終的には絶滅するため、根本原因単独ではない。

## 5.4 Energy capacityも重要

A6ではstorage容量倍増で最初の夜を越える個体が明確に増加した。

しかし翌昼でも十分な再充填・再繁殖へ到達せず、最終的に絶滅した。

したがって:

```text
storage不足は存在する
しかしstorageだけ増やしても成立しない
```

# 7. Phase C結果

mutable条件:

```text
C1 body_size
C2 reproduction_investment
C3 movement_power
C4 上記3形質
```

全20 runで最終絶滅。
Generation 2は一度も成立しなかった。

C1/C4では平均寿命がやや延びたが、現時点で「進化的救済」とは解釈しない。

理由:

- body_sizeが固定されていない初期個体にはstanding variationがある
- body_sizeがわずかに1.0を超える個体は、initial matter=.8ではtick1のmatter繁殖条件を満たしにくい
- その結果tick1一斉繁殖を回避し、Energyを温存した個体が相対的に長生きした可能性が高い

したがってC1/C4の延命は:

> 「長期進化で大型化が選択され夜へ適応した」

ではなく:

> 「初期variationにより一斉繁殖を回避した個体が残った」

という初期条件効果を強く含む。

# 9. 最重要の未解決点 — A1はV1.7回帰ではない

Exp14 A1は:

```text
light_cycle_enabled=False
light_max=4/pi ≈1.273
primary_energy_density_response=True
```

である。

したがってA1は:

> 「夜を消したV1.8」

であって、

> 「V1.7へ戻した条件」

ではない。

V1.7では:

```text
cycle OFF
primary_energy_density_response OFF
static light
```

で生態系が成立していた。

V1.8ではdensity responseにより、薄い局所光では:

```text
H(I,K) < 1
```

となり、同じ光fieldでも個体の実効取得速度が下がる。

さらにA1は`light_max=1.273`まで下げている。

よって:

> **A1で夜を消しても絶滅したことだけから、「昼だけでもV1.7個体がEnergy赤字」と断定してはいけない。**

正しくは:

> **V1.8のdensity responseをONにした低強度continuous-light条件では、夜がなくても成立しなかった。**

である。

これはこのチャット終盤で新たに整理された重要な修正点。

# 10. 次チャットで最初に行うべき切り分け

次の実験を確定する前に、V1.8の2新機構を独立比較する。

最低限の概念比較:

```text
cycle OFF / density OFF  -> V1.7型control
cycle OFF / density ON   -> density response単独
cycle ON  / density OFF  -> day/night単独
cycle ON  / density ON   -> V1.8 combined
```

目的:

1. V1.7条件で現在コードでも長期成立することを再確認
2. density response単独でEnergy収支がどれだけ悪化するか定量化
3. day/night単独の寄与を定量化
4. combinedで相互作用があるか確認

比較時には`light_max`や時間平均供給を何に揃えるかを先に人間判断する。
A1のように別のlight_maxへ変更した条件を、そのままV1.7 controlと比較しない。

観測するべき中心量:

```text
realized light gain / organism-tick
maintenance + movement + repair / organism-tick
net Energy balance
Energy/capacity distribution
birth timing
population
extinction/survival
```

この切り分け結果を見てから:

- light_maxを校正するのか
- light_uptake_halfを校正するのか
- cycle period/storageを再検討するのか

を決める。

**現時点で特定parameterを恒久変更しない。**
