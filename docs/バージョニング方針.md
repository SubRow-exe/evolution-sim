# バージョニング方針

更新: 2026-09-01

## 基本ルール

本プロジェクトでは、進化・生態・環境結果を変えうる世界ルール変更と、結果不変の機能追加をバージョン番号で分離する。

### 小数点以下1桁: 世界ルール変更

対象例:
- 環境場・資源構造変更
- 光/化学/栄養の供給・吸収則変更
- 生理コスト・繁殖・移動等の力学変更
- 新しい遺伝子/形質
- 生殖方式変更

### 小数点以下2桁: 結果不変の機能・観測追加

対象例:
- PNG/GIF / GUI
- 観測指標 / CSV / 解析ツール
- CI/Actions
- 結果不変の性能改善
- ドキュメント

## 現在の適用

- `V1.1`: 高光利用・小型化・sweepを観測したbaseline。`v1.1-final`保存
- `V1.2`: 高コントラスト静的光場

- `V1.2.2`: 軽量preview
- `V1.3`: chemicalを一定地質source + 局所stock + 環境損失へ変更。`v1.2-final`保存
- `V1.4`: 一次Energy/資源直接吸収を有効表面積・個体吸収上限・公平配分へ変更。`v1.4-final`保存
- `V1.5`: light / chemical の異種一次Energy刺激を無次元responseで比較。`v1.5-final`保存
- `V1.6`: 知覚のみ双線形補間 + temporal biased random walk。Exp10 Green、人間判断で行動原理GO
- `V1.7` **仕様確定・未実装**: BMRをcore + size-scalable部分へ分解する基礎維持代謝 `bmr_core`。詳細は `docs/V1.7_基礎維持代謝仕様案.md`

## V1.6を閉じてV1.7へ進む前の処理

Exp10採用値:

```text
memory_tau = 10
response_gain = 64
```

2026-09-01時点の通常Config defaultは `response_gain=16` のまま。
V1.7変更軸へ混ぜず、V1.6確定処理として先に:

1. `response_gain` defaultを64へ反映
2. 全test / Energy / Matter / RNG確認
3. default結果変更に伴いCI基準refを更新
4. `v1.6-final` branchを保存
5. その確定commitからV1.7実装へ進む

とする。

## 世界バージョン境界の手順

1. 直前バージョン最終コードを `vX.Y-final` branchへ保存
2. 直前バージョンの重要な実験NOTES/結果docがmainに存在することを確認
3. `tests/golden_state.json` を必要に応じて `tests/golden_state_vX.Y.json` へ履歴保存
4. 新世界ルールを実装
5. 新バージョン最初の意図的結果変更コミットをCI結果不変性基準refへ設定
6. 以後、新バージョン内での結果不変変更をCIで監視

## V1.7特記事項

V1.7仕様:

```text
BMR = bmr_core + (bmr_coef - bmr_core) * M^0.75
0 <= bmr_core <= bmr_coef
```

は生理コストを変更する世界ルールなので、小数点以下1桁を上げる。

実装直後は `bmr_core=0` を暫定defaultとし、`v1.6-final` 完全回帰を保つ。

Exp11では15候補を評価し、事前登録条件を満たす恒久値候補を選定する。恒久値をdefaultへ反映したcommitで結果が意図的に変わるため、その確定状態をV1.7のCI基準refへ更新する。

候補が選定されなかった場合は `NO_SELECTION / REVIEW` とし、Exp11結果を見て同じ実験内で式・候補・閾値を変更しない。

純加算式ではなく再配分式を採ること、M>1で大型側に相対的BMRメリットが生じることは人間判断済み。詳細は `docs/V1.7_Exp11_レビュー判断.md`。

## 過去境界の補足

V1.4のdefault確定、V1.5異種刺激比較、V1.6行動変更はいずれも意図的結果変更としてCI基準refを更新した。旧世界再現には各 `vX.Y-final` を使う。

## 補足

バグ修正で結果が変わる場合も世界ルール変更に準じて扱う。
結果不変の内部修正のみ小数点以下2桁側で扱う。
