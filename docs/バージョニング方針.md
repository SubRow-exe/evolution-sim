# バージョニング方針

更新: 2026-08-30

## 基本ルール

本プロジェクトでは、**進化・生態・環境の結果そのものを変えうる世界ルール変更**と、**結果を変えない機能追加**をバージョン番号で分離する。

### 小数点以下1桁: 世界ルール変更

例: `V1.1 → V1.2 → V1.3`

以下のような、シミュレーションの進化力学・資源収支・生理・生活史を変える変更を含む。

- 新しい環境パラメータや環境場の追加
- 光・化学・栄養など資源構造の変更
- 生理コスト式・吸収式・繁殖式の変更
- 新しい遺伝子や形質の追加
- 成熟期間・繁殖クールダウン等の生活史ルール追加
- 生殖方式の変更
- 捕食・損傷・移動など世界内の相互作用ルール変更

これらは同一seedでも結果が変わり得るため、比較実験の境界として扱う。

### 小数点以下2桁: 機能・観測・解析の追加

例: `V1.2 → V1.2.1 → V1.2.2`

世界ルールを変えず、同一条件・同一seedでシミュレーション結果を不変に保つ変更を含む。

- PNG / GIF可視化
- GUI改善
- 空間分布・行動範囲などの観測指標追加
- CSV / レポート出力追加
- 解析ツール追加
- CI / Actions / 実行基盤改善
- 性能最適化（結果不変性を検証できるもの）
- ドキュメント改善

観測ON/OFFや機能追加前後で乱数系列・シミュレーション結果が変わらないことを原則とする。

## 世界バージョン境界での結果不変性の扱い

`tools/verify_vs_ref.py` と `tools/golden.py` は「同一世界バージョン内で
実装変更が結果を変えていないこと」を守るためのもので、世界バージョンを
またぐと**必ず不一致になる**。これは異常ではない。

境界をまたぐときは次を行う。

1. 直前バージョンの最終状態を `vX.Y-final` ブランチ (必要ならタグも) で保存する
2. `tests/golden_state.json` の指紋を `tests/golden_state_vX.Y.json` へ履歴保存し、
   本体は空にする
3. `.github/workflows/ci.yml` の結果不変性の基準refを、新バージョンの
   最初のコミットへ更新する。基準refはコードと同じ境界で動く科学的な
   アンカーなので、リポジトリ変数ではなくこのファイルで明示的に固定する
   (変数側が旧バージョンを指したままだとCIが落ちるため)
4. 以後は「新バージョン内での結果不変」をCIが守る

基準refの履歴:

| 世界バージョン | 基準ref |
|---|---|
| V1.1 - V1.2.2 | `18137b5` |
| V1.3 - | `ea78125` |

## 補足

バグ修正で結果が変わる場合は、単なる機能修正ではなく世界ルール変更に準じて扱う。
結果不変の内部実装修正は小数点以下2桁側で扱う。
