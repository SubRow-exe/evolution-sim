# バージョニング方針

更新: 2026-09-04

## 1. 基本ルール

本プロジェクトでは、進化・生態・環境結果を変えうる**世界ルール変更**と、結果不変の機能追加を分離する。

### 小数点以下1桁: 世界ルール変更

例:
- 環境場・資源の意味や構造を変える
- 供給・吸収・変換則を変える
- 生理コスト・Energy配分・繁殖・移動則を変える
- 新しい遺伝子・形質・state variableを追加する
- 生殖方式を変える
- Energy / Matter state modelを変える

### 小数点以下2桁: 結果不変機能

例:
- PNG/GIF/GUI
- 観測指標/CSV/解析
- CI/Actions
- 結果不変性能改善
- ドキュメント整理

## 2. 「実験条件変更」とversion境界

**同じ方程式・同じ変数意味・同じ生物モデルのまま、Config値や環境条件を変えて比較するだけならversionは上げない。**

したがって、V1.9 iLUCAを固定したまま H2 source concentration、diffusion、exchange timescale、source geometry などを振る環境ロバストネス試験はすべて **V1.9内の実験**として扱う。

同様に、V1.9で既に定義済みのiLUCA parameterについて感度試験を行うだけならV1.9のままでよい。ただし、parameterの意味・式・state構造を変える場合は新version境界となる。

**実験番号 (Exp15, Exp16...) とworld version番号は独立**である。

# 6. 世界version境界の手順

1. 直前version最終コード/refを固定
2. 直前versionの総括/主要実験結果を保存
3. 必要なgolden履歴を保存
4. 新世界ルールを仕様化
5. 新version最初の意図的結果変更commitを基準refへ設定
6. conservation / determinism / regressionを確認
7. 以後、同version内の条件探索と新world-rule変更を混同しない

# 7. Abiogenesis -> LUCA track

**諦めていない。現在はDEFERREDであり、ABANDONEDではない。**

ただし、abiogenesisを扱うには現行 `Organism` より前段に、少なくとも前生物的化学種・反応・区画化・触媒/複製・遺伝の成立を表すモデルが必要になる。これは「既存iLUCAのparameter sweep」ではなく世界のstate/ルールを大きく追加するため、V1.9とは分離して扱う。

再開時のversion番号はV1.9終了時点の状況で決める。番号を先に予約しない。

詳細: `docs/Abiogenesis_to_LUCA_保留方針.md`
