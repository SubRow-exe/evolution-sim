# バージョニング方針

更新: 2026-09-07

## 1. 基本ルール

本プロジェクトでは、進化・生態・環境結果を変えうる**世界ルール変更**と、結果不変の機能追加を分離する。

### 小数点以下1桁: 世界ルール変更

例:
- 環境場・資源の意味や構造を変える
- 供給・吸収・変換則を変える
- 生理コスト・Energy配分・繁殖・移動則を変える
- 新しい遺伝子・形質・state variableを追加する
- 生殖方式を変える
- Energy / Matter state modelを変える

### 小数点以下2桁: 結果不変機能

例:
- PNG/GIF/GUI
- 観測指標/CSV/解析
- CI/Actions
- 結果不変性能改善
- ドキュメント整理

---

## 2. 「実験条件変更」とversion境界

**同じ方程式・同じ変数意味・同じ生物モデルのまま、Config値や環境条件を変えて比較するだけならversionは上げない。**

したがってV1.9内で:

- H2 source concentration
- diffusion
- exchange/loss timescale
- source geometry
- 既存iLUCA parameter感度

を振るだけならV1.9のまま。

parameterの意味・式・state構造を変える場合は新version境界。

**実験番号 (Exp15, Exp16...) とworld version番号は独立**である。

# 6. ロードマップとversionの関係

`docs/長期ロードマップ.md` は**phase順序の仮説**であり、version番号予約表ではない。

原則:

```text
Phaseで次の主要world-rule軸を選ぶ
  ↓
直前versionをclose
  ↓
次version番号をその時点で付ける
```

遠未来まで `V1.10 = X`, `V1.11 = Y` のように固定しない。

ただし通常は1つの大きなworld-rule軸ごとにversion境界を切る。

例:

```text
generic phototrophy emergence
Temperature field / thermal kinetics
explicit carbon
pH / ion gradient / chemiosmosis
```

を全部一versionへ同時投入するのではなく、可能な限り分ける。

同version内の標準experimentは:

```text
mechanism sanity
fixed baseline
 evolution ON
minimal interaction
```

程度に留め、細かな最適化でversionを長期化させない。

# 7. LUCA fidelityとversion境界

**LUCA再現度を上げること自体を理由にversionを増やし続けない。**

新しいLUCA-like機構を入れるのは:

- 現在結果を支配する欠落
- 次phaseのselection pressureへ必要
- 明らかな非生物学的挙動の修正

である場合を優先する。

分子詳細だけを追加するためのversionは、mainstream上の価値が明確な場合に限る。

---

# 8. 世界version境界の手順

1. 直前version最終コード/refを固定
2. 直前versionの総括/主要実験結果を保存
3. 必要なgolden履歴を保存
4. 新world ruleを仕様化
5. 新version最初の意図的結果変更commitを基準refへ設定
6. conservation / determinism / regressionを確認
7. 同version内のparameter sweepと新world-rule変更を混同しない
