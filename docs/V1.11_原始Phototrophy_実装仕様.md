# V1.11 — 原始Phototrophy（H2依存・無酸素型）実装仕様

更新: 2026-09-10  
状態: **DESIGN FREEZE / Claude実装用正本**

## 0. このversionでやること

V1.11では、現在のH2依存iLUCAから、**光を補助Energy源として利用する能力がstructural innovationによって獲得可能になる**ようにする。

ただし、最初から完成した光合成生物を置かない。また「色素だけできたが生態的効果が0」という中間段階も独立agent stateとして実装しない。

V1.11で表現する最初のphototrophyは、実際の初期無酸素型phototrophyを粗視化して、

```text
H2依存chemolithotroph
  -> pigment + primitive reaction center + membrane coupling のmacro-innovation
  -> H2を電子供与体として維持したまま、光でEnergy conservationを補助
```

とする。

**H2が完全に無い場所ではV1.11 phototrophyだけでEnergyを得られない。**

水を電子供与体にするoxygenic photosynthesis、O2生成、H2S/Fe2+等の代替電子供与体、Type I/II reaction center分化、chlorosome等の高性能antennaはV1.11では実装しない。

---

# 1. 生物学的な位置づけ

V1.11の設計は以下を背景とする。

1. LUCAはH2依存・CO2固定型・嫌気的で、Wood-Ljungdahl pathwayを持つ熱水環境生物だったという再構成が有力候補の1つである。
2. photochemical reaction-center型phototrophyはLUCAそのものの確定形質ではなく、LUCA後のBacteria系統で成立したと考えるのが安全である。
3. 初期のreaction-center phototrophyはoxygenicではなくanoxygenicだったと考えられている。
4. anoxygenic phototrophyでは、光はEnergy conservation / reducing power生成を助けるが、H2・H2S・Fe2+等の電子供与体が必要である。
5. 色素、reaction center、electron transport、antenna、carbon fixationは実進化では別々のsubsystemとして発達した可能性が高い。

したがってV1.11では、分子進化の全中間体をagent stateとして逐一置くのではなく、**最初に生態的な効果が現れるところまでを1回のmacro-innovationに粗視化する**。

### 参考

- Weiss et al. 2016, *The physiology and habitat of the last universal common ancestor*, Nature Microbiology. DOI: 10.1038/nmicrobiol.2016.116
- Blankenship 2010, *Early Evolution of Photosynthesis*, Plant Physiology / PMC2949000
- Fischer et al. 2016 / Ward et al. review, *A physiological perspective on the origin and evolution of photosynthesis*, PMC5972617
- Cardona 2016, reaction-center evolution review, PMC4773611
- Overmann et al. 2005, extremely low-light green sulfur bacteria, PMC1317439

これらは「唯一の確定進化経路」を意味しない。特にreaction centerの最初期進化順序には未解決点が多い。

# 2. V1.11進化ロードマップ

## Stage 0 — 現在のiLUCA

```text
phototrophy capability = OFF
light_absorption = 0
H2 -> usable Energy
DIC + N + P -> biomass
```

光は環境に存在しても利用不能。

## Stage 1 — V1.11で実装するprimitive phototrophy

structural innovationにより、以下を1つのcoarse-grained capabilityとして獲得する。

```text
pigment
+ primitive photochemical reaction center
+ membrane electron/proton coupling
```

効果:

```text
H2 1 molから保存できるusable Energyに、光依存bonusが加わる
```

つまり初期phototrophは依然としてH2依存。

```text
H2 = 0 -> photo bonus = 0
light = 0 -> photo bonus = 0
H2 > 0 AND light > 0 -> photo bonus > 0
```

## Stage 2 — 将来

V1.11後、必要に応じて同じ `light_absorption` の進化または別antenna形質により、弱光利用性能を上げる。

## Stage 3 — 将来

H2S / Fe2+など代替電子供与体をworldへ追加し、vent H2への絶対依存を緩める。

## Stage 4 — 将来

reaction center Type I / Type IIの分化を明示する必要が生じた場合に追加。

## Stage 5 — V1.17候補

```text
2 reaction systems / water oxidation machinery
-> H2O electron donor
-> O2 generation
```

oxygenic photosynthesisはここまで導入しない。

### Rhodopsin系について

retinal/rhodopsin proton pumpはchlorophyll/reaction-center型とは別の光利用routeとして扱う。V1.11の必須前駆段階にはしない。将来、独立macro-innovationとして追加可能。

# 4. structural innovation

出生時の既存 `structural_mutate()` を使用する。

初期iLUCA:

```text
phototrophy = False
light_absorption = 0
```

OFF -> ON event:

```text
phototrophy = True
light_absorption = max(current, phototrophy_seed_absorption)
```

### probability

V1.11 first implementationでは既存値を維持する。

```text
phototrophy_innovation_prob = 1e-4 / birth
phototrophy_loss_prob       = 1e-3 / birth
```

これは分子mutation rateの推定値ではない。

**複数の分子的変化が最終的に機能的phototrophyへ到達するmacro-innovationの粗視化確率**である。

結果を見て「出やすくするため」に変更してはいけない。変更する場合は独立したsensitivity experimentとして行う。

### seed absorption

物理lightへ接続するため、V1.9 arbitrary値0.01はそのまま使わない。

V1.11 working value:

```text
phototrophy_seed_absorption = 0.001
```

後述の吸収率mappingでは約0.1%の初期吸収能力となる。

最初のinnovationは完成した高性能phototrophではなく、**弱いが選択可能な機能**として開始する。

# 5. 光fieldの物理化

## 5.1 基本量

physical_mode=Trueでは、従来の arbitrary `E/tick` lightをphototrophy計算に使わない。

新しい基本量は photon flux とする。

```text
light photon flux: umol photons / m2 / s
```

Config追加候補:

```text
physical_light_enabled: bool = False
light_photon_flux_max_umol_m2_s: float = 1.0
light_effective_wavelength_nm: float = 800.0
light_physical_pattern: str = "uniform"  # uniform | legacy_shape
phototrophy_radiant_to_usable_eff: float = 0.10
phototrophy_h2_bonus_cap_j_per_mol: float = 30000.0
```

`physical_light_enabled=False`ではV1.10.1完全回帰。

### 1.0 umol photons/m2/sについて

これは「初期地球の真値」として採用する値ではない。

現生の極低光anoxygenic phototrophでは0.01 umol photons/m2/s級でもactivityが観測され、1 umol photons/m2/s程度でsaturationに近づく例がある。一方、primitive RCは現生のchlorosome系より低性能だった可能性が高い。

したがって1.0は**物理単位を持つdiagnostic / working reference**として置き、最終environmentはExp20で感度を見る。

## 5.2 photon -> radiant power

```text
photon_energy_J = h * c / lambda
photon_rate     = flux_umol * 1e-6 * N_A * projected_area
P_incident      = photon_rate * photon_energy_J
```

波長はV1.11ではeffective single wavelengthで粗視化する。

```text
lambda = 800 nm
```

これはbacteriochlorophyll系の近赤外利用を代表させるためのeffective wavelengthであり、spectrum全体を再現するものではない。

# 6. 個体の光捕捉

## 6.1 projected area

physical cell radiusを既存 `physical_radius_m()` から得る。

```text
A_projected = pi * r^2
```

V1.11ではshading / self-shading / cell-cell optical competitionは無視する。

光はH2/CNPのようなdepletable stockではない。

## 6.2 light_absorption -> absorptance

遺伝子値をそのまま%として使わず、飽和mappingを使う。

```text
absorptance = 1 - exp(-light_absorption)
```

性質:

```text
0      -> 0%
0.001  -> 約0.10%
0.01   -> 約1.0%
1.0    -> 約63%
5.0    -> 約99.3%
```

これによりgeneが大きくなっても100%を超えない。

## 6.3 raw usable photo power

```text
P_absorbed = P_incident * absorptance
P_photo_raw = P_absorbed * phototrophy_radiant_to_usable_eff
```

working value:

```text
phototrophy_radiant_to_usable_eff = 0.10
```

この10%は祖先RCの実測値ではなく、**吸収したradiant energyからATP等のusable cellular Energyへ至る粗視化効率**である。

seed absorptance自体が約0.1%なので、incident light全体から見た初期総効率は約0.01%となる。

# 7. 最重要ルール — V1.11 phototrophyはH2依存

独立の

```text
light -> Energy
```

経路をphysical modeへそのまま入れてはいけない。

それをすると、innovation直後から

```text
light + DIC + N + P
```

だけで増殖でき、電子供与体なしのphotoautotrophyが成立してしまう。

V1.11では以下とする。

```text
H2 -> baseline usable Energy
H2 + light + phototrophy -> baseline + photo bonus
light alone -> 0 usable Energy
```

## 7.1 H2 1 molあたりのphoto bonus cap

H2は2 electronsを供給する。

800 nm photonを粗視化し、electron transferに必要な光量とcellular conversion lossを考慮した上限として、working value:

```text
phototrophy_h2_bonus_cap_j_per_mol = 30000 J/mol H2
```

を使用する。

既存:

```text
h2_usable_energy_j_per_mol = 3750 J/mol H2
```

なので十分な光があれば、原始phototrophyはH2利用効率を最大約9倍（3750+30000）まで押し上げ得るが、H2そのものを不要にはできない。

このcapは水分解やoxygenic photosynthesisを意味しない。

# 8. physical H2 uptakeとの結合式

V1.11 physical modeでは、`_absorb_light()` を独立Energy経路として使わない。

phototrophy bonusは `_absorb_h2_physical()` 内でH2 uptakeとcoupleする。

個体iについて:

```text
q_max_i = existing physical H2 uptake kinetic limit [mol/s]
B       = h2_usable_energy_j_per_mol           [J/mol]
C       = phototrophy_h2_bonus_cap_j_per_mol   [J/mol]
L       = P_photo_raw                           [W]
H       = energy_headroom / dt                  [W]
```

H2 uptake rate qに対するusable power:

```text
P_total(q) = q * B + min(L, q * C)
```

### 性質

```text
q=0 -> P_total=0
L=0 -> existing H2 equationへ完全回帰
phototrophy OFF -> L=0 -> existing H2 equationへ完全回帰
light増加 -> 同じEnergy headroomを満たすために必要なH2量が減る
十分な光 -> ただしq=0にはならない
```

## 8.1 headroomからH2 demandを求める

`q <= L/C` の領域:

```text
P_total = q * (B + C)
q_required = H / (B + C)
```

`q >= L/C` の領域:

```text
P_total = q * B + L
q_required = (H - L) / B
```

これをpiecewise analyticに実装し、

```text
q_demand = min(q_max_i, q_required)
```

とする。

binary searchは不要。

既存のcell内H2 fair-shareをそのまま使用する。

fair-share後のactual H2 uptake `n_H2` から:

```text
E_h2_base = n_H2 * B
E_photo   = min(P_photo_raw * dt, n_H2 * C)
E_total   = E_h2_base + E_photo
```

を再計算する。

供給不足でH2 demandがscaleされた場合にもphoto bonusをactual H2 uptakeから再計算すること。

Energy headroomを超えないことをassert / clampする。

# 9. Energy ledger

H2由来baseline energyと光由来bonusを区別する。

```text
flows["h2"]    += E_h2_base
flows["light"] += E_photo
```

`E_photo`は外部radiationからsystemへ入ったEnergyなので:

```text
energy_in_cum += E_photo
```

H2 stock側のsystem energy equivalentは既存どおり:

```text
H2_mol * h2_usable_energy_j_per_mol
```

photo bonus potentialをH2 stockへ事前加算してはいけない。

未吸収光はsystem stockとして保存せず、そのまま通過・散逸した外部fluxとして扱う。

# 10. phototrophyのコスト

新しい人工penaltyは追加しない。

既存physical basal modelはorgan componentに:

```text

chemical_absorption
nutrient_absorption
...
```

を含むため、`light_absorption > 0` になればbasal organ upkeepが自然に増える。

したがって:

```text
dark environment -> phototrophyはcostのみ
light + H2 -> benefitとcostのtrade-off
```

が既存式から生じる。

このcostが機能していることをpositive/negative controlで確認する。

# 19. V1.11の終了条件

V1.11で確認したいのは「phototrophyを必ず進化させる」ことではない。

以下が成立すれば実装成功:

1. H2依存iLUCAからstructural innovationでprimitive phototrophyが発生可能。
2. innovation直後から弱いが非0の生態的効果を持つ。
3. lightだけでは生きられず、H2依存性を維持する。
4. 光があるとH2利用効率が上昇する。
5. light_absorptionのbenefitとbasal upkeep costからselectionが自然に生じる。
6. innovationが有利か不利かはenvironmentの帰結として決まり、fitness関数を置かない。
7. H2/C/N/P/Energy ledgerを壊さない。

この条件を満たした後、phototrophyがどの環境で維持・拡大するかをExp20で調べる。
